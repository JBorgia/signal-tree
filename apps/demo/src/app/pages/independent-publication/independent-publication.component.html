Publish a note while a route is still under review.

A route proposal can stay pending while an independently authored note reaches its own endpoint. This tutorial uses the v16 development API; it is not stable v15 guidance.

Try one local review

  1. Propose west. The visible route changes, but the proposal stays pending.
  2. Publish the literal note. Its endpoint can receive it before route review ends.
  3. Reject the route to restore its previous value (north on the first proposal), or confirm it to keep west. The note remains.

Declare what the note actually consumes

independent is correct here because 'dispatch-ready' is a literal authored without reading the proposal. A value saved earlier, hidden input, or cached computation can still depend on pending work. Moving that read outside the callback does not make it independent. Declare all contributing owners for dependent work; use unknown when you cannot establish a complete declaration.

The Link owns publication from the note leaf. Local confirmation and rejection affect tree state; this in-memory endpoint has no server, durable storage, or remote acknowledgment. Admission and settled() do not prove backend durability or distributed agreement.

Leaving this page disposes the Link and destroys the component-owned tree.
