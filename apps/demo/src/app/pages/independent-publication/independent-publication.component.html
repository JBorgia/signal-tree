Keep working while a proposed route is under review.

An agent proposes west. A dispatcher receives a shipment update and sends an unrelated note. Review the proposal, then try a conflicting edit and recover without pretending rejection succeeded. This tutorial uses the v16 development API; it is not stable v15 guidance.

Try one local review

  1. Propose west. The visible route changes, but the proposal stays pending.
  2. Publish the literal note. Its endpoint can receive it before route review ends.
  3. Reject the route to restore north, or confirm it to keep west. The note remains. After confirming, reset the local scenario before trying another west proposal.

Reset clears this demonstration's state and delivery log only after every pending proposal has settled. It does not undo an external business effect.

One workflow, three useful views

For the person using the app

Your shipment update survives. An unresolved proposal stays visible, and a refused rejection gives you a next step.

For the developer

Keep each pending handle until it settles. Inspect current changes, classify external updates, and declare genuinely independent work. Destroy the owned tree when the editor closes.

For the business

This is a foundation for reviewable automation while ordinary work continues. Reduced rework and faster reviews are benefits to measure with users, not savings proved by this demonstration.

Declare what the note actually consumes

independent is correct here because 'dispatch-ready' is a literal authored without reading the proposal. A value saved earlier, hidden input, or cached computation can still depend on pending work. Moving that read outside the callback does not make it independent. Declare all contributing owners for dependent work; use unknown when you cannot establish a complete declaration.

The Link owns publication from the note leaf. Local confirmation and rejection affect tree state; this in-memory endpoint has no server, durable storage, or remote acknowledgment. Admission and settled() do not prove backend durability or distributed agreement.

Leaving this page disposes the Link and destroys the component-owned tree.
