Core concept / batching()

Multiple writes. One coherent publication.

Batching groups publication, not business jobs. Multiple synchronous state writes can be grouped into one framework publication so observers re-read one coherent final state.

Batching does not own HTTP retries, queues, delays, background work, or failure recovery. Values still update immediately inside batch(); transaction semantics are separate.

Keep the boundaries separate

Three different responsibilities

Batching

Coherent publication

Transactions

Pending operation semantics
