🚀 What's New

🧩 v15.0.0-rc.1 — the package and API reset (August 2026)

The first public candidate for the v15 package and API reset. The packages are now @signal-tree/kernel, @signal-tree/angular, and @signal-tree/react.

💥 Breaking

  • Framework realization is construction-bound. There is no runtime package installation and no .with() builder. signalTree(state, config) declares state, enhancers, and one derived factory in a single construction call, and each framework package binds its native carriers when it creates a tree. Neutral and Angular trees can coexist in one process.
  • timeTravel({ shouldSkip }) removed. undo() and redo() move one turn. undoable(fn) asks the admission question before a turn exists: a cursor move is not designated, so there is nothing to skip past and no per-transition predicate runs on every recorded write.
  • entityMap({ recordHistory: false }) removed. It excluded a collection by location, so a turn touching both it and ordinary state was only partially reversed. Designate the operations that should be undoable with undoable(); everything else costs no restoration at all.
  • Lazy signal creation removed. Large trees are cheap to read because of incremental materialization on the default path — measured 149µs for one changed leaf among 10k against 1808µs for a full rebuild — and need no configuration.
  • The async markers, form(), status(), stored(), and the persistence/edit-session packages are not part of the v15 public surface. Orchestration, forms, and storage live in application code and framework primitives; the tree stores the results.

✨ New

  • @signal-tree/react ships. useSignalTree(owner, selector) subscribes to owner invalidation and rereads the selected canonical value without mirroring state. Whole-root observation is the same hook with ($) => $().
  • transactions() adds explicit tree-local optimistic transaction grouping; rollback failures surface as SignalTreeRollbackError so callers can reconcile or refetch instead of silently corrupting state.
  • Restoration refuses rather than destroying later truth (ST1034). An undo()/redo() either reverses the authored operation atomically or does not happen.
  • Tree lifetime is a documented contract. A tree owns runtime resources until destroy(); bounded-lifetime trees (tests, SSR requests, route-owned stores) must be destroyed at their ownership boundary.

Earlier releases (v14.0.0 and before) are release history. They describe @signaltree/* APIs as they were at the time — many were later removed. They live on their own page now: Release history — v14.0.0 and earlier. The current surface is the package READMEs, CHANGELOG.md, and the v15 migration guide.
