Async state in SignalTree is a marker family, not a free-standing service method. Two markers cover the two main shapes:

  • asyncSource<T>(config) — load-and-expose. Auto-loads on materialization. Exposes data, loading, error, plus refresh / set / update / reset. Accepts Observable or Promise loaders.
  • Input-driven debounced search — no SignalTree marker. The pipeline is ordinary RxJS in your service: debounceTime → filter → distinctUntilChanged → switchMap. switchMap already gives cancellation and latest-wins, and distinctUntilChanged already gives dedup — SignalTree adds no causal authority over any of them, so it owns none of them. Results land in plain tree state through external().

Both markers attach at any tree depth alongside entityMap and app-owned loading/freshness services. Auto-clean on the surrounding DestroyRef. No manual tap() / setLoading() wiring.

👉 Full interactive demo: /async — exercise both markers end-to-end with simulated network latency, debounced search, and live counters showing how cancellation and dedup work in practice.
