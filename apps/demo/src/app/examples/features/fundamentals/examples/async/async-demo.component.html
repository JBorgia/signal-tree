Application policy

Loading, retries, cancellation, cache, and migration stay outside.

Fetching is application-owned. Once the endpoint resolves, wrap the synchronous state write in external() to state that another authority decided the value.

Request bookkeeping is different: loading indicators, retry counts, error presentation, and cancellation are authored application policy, not external truth.

The Link handle is deliberately small: retrieve(), settled(), and dispose(). Retry, backoff, and status APIs are not part of it.

Application-owned orchestration

HTTP policy does not move into the tree.

Debounce, deduplication, cancellation, latest-wins behavior, retries, loading state, and error presentation remain application concerns. Angular services, resources, or RxJS can own them; SignalTree receives the resulting state transition.
