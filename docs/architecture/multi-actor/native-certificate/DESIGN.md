## Representation

A private recipient certificate carries exact native occurrence identity, selected
payload, native requirement references, explicit readiness, subtractable proof
contributions and the acquiring connection token where applicable. It is a view
of source-owned facts, not a second value or settlement authority.

1. Native lifecycle finalizes requirements. Composite requirements explicitly retain
   readiness dependencies; a computed `proof` getter is not a finality certificate.
2. Recipients subscribe by requirement identity, including enrollment with no local
   operation. The subscription checks the same requirement still occupies its slot;
   replacement and disposal release it.
3. Finalize all native requirements, update indexed recipient contributions, compose
   selected projections, then refresh/wake delivery. Unfinished selected evidence
   cannot normalize to a clean baseline.
4. Membership completion selects the occurrence and installs payload/support together.
   An omitted ancestor removes its collection from the outgoing support domain but
   does not erase recovery facts. Hidden edits cannot recreate an outgoing path.
   Reappearance selects a retained occurrence or a new lifetime explicitly; typed
   address equality is insufficient to reuse old authority.
5. Ingress carries the exact connection token in both scalar and collection paths.
   Nested scopes restore the outer token and consumed-occurrence set. No acquiring
   relationship changes a peer's native input certificate.

## Required discriminators

- Parent declaration writes x, a new recipient enrolls, parent throws, recipient
  independently writes y: retain unfinished validation/owner window then useful
  delivery after relevant settlement, without a new value event.
- Repeat enrollment for scalar and membership sources and a computed composite;
  no parent recipient operation is required to preserve support.
- Omit nested collection while q holds it: outgoing omitted payload progresses.
  Edit retained hidden storage, then restore ancestor: exact payload and support
  agree. Replace lifetime at the same address: old listeners cannot retarget.
- Full/equal incoming update with peers enrolled in both orders; nested incoming
  callbacks: permission belongs only to the acquiring token.
- Replacement/disposal before finalization: stale callbacks do not update live
  certificates; no obligation-free listener retention.

## Independent design review

Read-only review identified that merely retaining requirement references, filtering
visible collections and changing a collection acquisition check would be insufficient.
The explicit readiness, scalar/membership enrollment, occurrence replacement and
both acquisition-path rules above incorporate those corrections. Source inspection
supports a bounded implementation; no native runtime tests or acceptance are claimed.
The reviewer disclosed incidental exposure to archived review excerpts, so complete
blinding is not claimed. Final implementation requires a separate adversarial pass.

Do not turn these into caller-specific guards. If a covered path requires a
contradictory mechanism or repeats the claimed boundary failure, preserve it and
apply the recurrence rule. Sibling selected-inverse/framework and retirement gates
remain necessary before broad qualification and production integration.

Source inspection shows the design was not fully represented: clean ancestors
were not obligatorily enrolled; scalar readiness subscriptions lacked exact-slot
replacement lifecycle; readiness checked all selected contributors. These are
mechanism gaps, not an approval to change semantics. The successor must use a
mandatory verified occurrence enrollment and shared slot lifecycle, distinguish
transition reduction from delivery readiness, and preserve consumed dependencies
when their source subtree leaves the outgoing payload. The original candidate,
fixtures and first failures stay frozen.
