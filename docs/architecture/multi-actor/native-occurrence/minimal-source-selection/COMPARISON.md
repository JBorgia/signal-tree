## Recommendation

Review **source-issued once-per-request ordinary output materialization** first. O(N) work is legitimate when N-row output is requested. It need not imply an immutable persistent source data structure, a global cache, or an extra walk for every point mutation. The necessary immutable artifact is the output certificate retained by a completing publication unit, not necessarily every version of native state.

A separate minimal extension to existing native responsibility preparation should expose its actual admitted/retained step disposition. Do not introduce a new authority index unless a concrete obligation query cannot be answered from the already-prepared effects and existing per-slot native evidence. A proves that field scope alone is insufficient, not that a new global authority representation is required.

| Option | Work and lifetime | Main risk / disposition |
| --- | --- | --- |
| Present recipient overlay + absence-aware membership snapshot | Retained recipient rows override source []; current failure retains old support | Rejected as the source-selection solution; neither original footprint nor source capture coherence is fixed |
| Source-issued output certificate on actual request | O(N + emitted support) for one requested ordinary output; O(output size) retained only by live requests/units | Smallest plausible mechanism; must prove exact native frontier, demand placement and no extra point walk |
| Persistent source ordinary root | O(log N) point versioning, retained historical nodes, new source propagation/version lifecycle | Substantial cross-cutting architecture, NOT approved or shown necessary; do not implement |
| Shared EntityEgressProjection/'cache' | Existing complete rendering/copy costs and relationship-local permission | Not a source authority. Renaming it a cache does not make sharing its permission legal |

## A. Materialize at the native source boundary, once for output demand

**Demand:** introduce a private request tied to an actual observer's output need and the impending membership completion. The native source request must be per exact occurrence/selection frontier, not unconditional because a publication factory is registered globally. No observer / no requested output -> no complete snapshot. A parent root output request may require a nested collection output even without a direct collection subscriber. Multiple recipients may share native source evidence for the same frontier, but each keeps its own permission/ingress projection.

**Producer location:** the collection has ordinary topology and ordinary row access inside entity-signal.ts. At membership preparation, after the structural writer's child installations/user callbacks that precede this activation, obtain a source-issued ordinary output for the exact child source revision. For a still-prepared child unit, use its prepared ordinary topology/row overlay; for an already-installed child unit, use the source's current ordinary topology/rows validated at that revision. These are native ordinary authority reads, not rows.all(), getProjectedEntities(), node snapshots or recipient projection reads. The public ancestor's absence must not hide the collection's own ordinary selected domain.

The builder walks **ordinary adjacency once** and resolves each selected ordinary row and requirement references together. It can use the existing placement overlay while it is synchronously valid; it must not retain that live overlay as a historical snapshot. Copy the ordered output array and exact support references into the completion-owned certificate before returning. Native source ordinary selection includes required negative/member/key/order evidence; enumerate that only as necessary to certify the actual requested domain. Explicitly count support-only entries as well as displayed rows. Reuse a complete prepared selection already materialized for this exact request/frontier instead of rendering it again for membership.

**Certificate contents:** exact source/occurrence, native unit and validated revision; selected ordinary payload; member/key/order/field requirement references (including unfinished identities); source exclusion/domain evidence; completion status. A complete array is immutable as a selection/version artifact, but do not claim deep immutability of arbitrary user objects merely because its wrapper is frozen. Preserve existing row preparation/capture guarantees; any application getters must be staged at the existing allowed preparation point and revision-checked. No user getter may run between final validation and terminal installation.

**Installation:** prepare the membership requirement and selection reference together, validate parent descriptor/exact child/source revision and the native admission validity needed by the certificate, then install both in its terminal record. Membership completion owns the certificate. Delivery renders/uses that retained payload and corresponding support, never current native state. Native requirement finality remains separate; a pending parent horizon preserves exact references and blocks readiness normally. Discard on aborted uninstalled preparation; release at supersession/disposal or when the output unit no longer retains it. No all-history chain or global version cache.

**No new double scan:** current entity-egress-projection.prepare already performs order.map for complete subscribed output (:217); structural draft creation also scans (:222). A candidate must demonstrate how the requested source materialization replaces or shares the required output-building work, not add another N-row proof/snapshot pass while calling it 'output'. For point publication that already has its exact delta and no membership/full-source-output request, keep the point path; do not eagerly manufacture a source-wide certificate. A whole root restoration does request a complete root value and may pay the unavoidable output cost. Actual work accounting—not a handle type—decides whether this alternative meets the bound.

This alternative does not assert that native ordinary output equals every recipient's eligible output. Source certifies native facts; relationship ingress grants and retained per-slot permission remain relationship-local. A recipient must not wholesale reseed clean from the source array. The completed source selection should drive exact domain/payload selection while existing recipient role/permission reduction applies only to its own enrolled occurrences. Review must reject any implementation that quietly replaces that reduction with a shared egress authority.

## B. Reentry without a persistent source root

Avoid eagerly capturing an earlier child merely because it was written first. Parent output preparation occurs after the later child's interceptor has finished. If B's interceptor rewrote A, materialize A from its latest completed native ordinary frontier at the parent's final preparation, not A's older completion and not the original supplied literal. Preserve A's actual requirement provenance; parent independence cannot re-author it.

A parent producing multiple child outputs validates a vector of exact child revisions plus the parent occurrence/descriptor revision. During preparation, source materialization must not execute user code after final validation. If a permitted callback/getter while preparing B rewrites already-materialized A, A's certificate fails the final revision check. Do not publish the stale A artifact, replay application callbacks, or reread physical snapshots. Apply the repository's existing reentry/stale-preparation semantics. A proposed implementation should either stage callback-bearing work before any output freezes or use the existing refusal boundary; it must not invent an unlimited recomposition loop. A change entirely before parent preparation is ordinary current-frontier selection and must not be refused unnecessarily.

This uses O(number of child outputs actually requested) revision validation, which belongs to that output's construction; no requirement to maintain a persistent global ancestor selection tree. Unrelated branches aren't enumerated for a leaf output. If a native write inside the final terminal installation could occur without a callback-free window or observable revision, this alternative fails; do not mask it with opaque tokens.

Required discriminator: outer writes A=1; B interceptor writes A=2 under a different native requirement; parent output must select A2 with its requirement. Repeat inspector-only A rewrite (ordinary selection unchanged), new A lifetime, omitted sibling, and a getter that rewrites A during B output preparation. Retain earlier valid writes on failure as existing code requires.

## C. Minimal native responsibility result before any authority index

The exact producer is transactions.ts:2373 prepareEntityResponsibility, which already computes `effects`, source revisions/segments and terminal admission writes. Extend its private result to identify **the actual prepared effects and their exact per-step native domains**, and explicit no-field-admission/retention, alongside the terminal plan and installation validity. It must say why no result occurred (no authority, inspection, inverse handled elsewhere, or no newly admitted field effect), rather than having publication interpret undefined as clean.

The first bounded consumer rule is dictated by A: when native admission leaves a selected field's existing settlement obligations intact, replacing its publication footprint must retain those native obligations. Publication may replace a foreign possible window or consumed-input component only under the approved declaration/native input rules. Do not keep the whole old proof indiscriminately (that would retain the original foreign-window failure), and do not discard every old role (that would violate A). Exact current source requirement roles are already stored per field; investigate whether a producer-issued retain/supersede disposition can select those existing references without reconstructing owners globally.

This is a feasibility question, not permission to declare native requirement.destination automatically complete settlement truth. Require equivalence with actual native recording/rollback/confirmed-history controls. The producer must derive supersession from its existing authority rules, not simply from an effect's presence or a changed number. Structural dependencies and later-confirmed conflicts may retain obligations despite another local effect. If the narrow existing evidence cannot prove disposition for a path, leave that path unqualified and identify the exact missing authority query. Do not build a new global index merely to make a total API convenient.

**Validation/install:** distinguish a reservation counter from an installed revision. Current ++sourceRevision occurs during preparation; it is not itself proof the plan installed. Pair the returned admission result with its installed source identity and the relevant authority mutation version. The native responsibility record and publication selection bind one unit; validate both before installation; complete publication only after installation. If authority changes during preparation without changing physical values, either retain immutable obligation references whose outcomes are deliberately live, or invalidate any captured disposition that assumed a different obligation set. Specify which in the reviewed implementation; don't add a global epoch that needlessly rejects unrelated settlements.

Current frame publication precedes responsibility preparation. A bounded two-phase bind can reserve a publication unit, obtain the native admission result, bind it before finalizing/installing the plan, and prohibit completion while unbound. Alternatively reorder internal pure preparation if no user callback timing changes. No new transaction contribution may be created just to make the publication declaration independent.

## Review questions / explicit limits

1. Can exact requested ordinary payload + support be materialized from native source authority during one validated precompletion window, reusing the already-required output work? Identify concrete hook/demand integration before coding.
2. Are field obligations fully represented by existing native per-slot evidence plus the authority's prepared disposition, including structural/confirmed-history overlap? A alone establishes retention, not total equivalence.
3. Can callback-bearing child preparations finish before final freezing, or does existing reentry refusal apply consistently? No old immutable artifact may silently become current after a later child rewrites it.
4. Demonstrate noobserver zero snapshots, no extra point collection walk, once-per-request output work, peer permission isolation and bounded unit retention.

Persistent roots and a new authority index remain deferred alternatives, not approved next steps. Original foreign-window restoration expectation remains valid; wider-updater expectation conflict is separate. No runtime repair is part of this comparison.
