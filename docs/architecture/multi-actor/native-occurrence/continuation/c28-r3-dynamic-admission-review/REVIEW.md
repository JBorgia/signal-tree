## Concrete cleanup and provisional requirements

ConstructionAllocation installs/discards only its own resources and clears cancellation callbacks after installation. finalizeLeafSignal registers returned release only after wrapOwnedWritableSignal returns. Therefore a new second registration throwing after the first succeeds must unwind the first locally before rethrowing; otherwise construction cancellation cannot release that partially attached wrapper. Registering both is not automatically atomic. The combined release must be idempotent, identity-local and used by both attachment paths. Provider installation must reject an occupied foreign provider; teardown must compare exact installed function/token before deletion, rather than blindly delete a potentially replaced provider. Do not copy the unconditional member-provider deletion as proof of safety.

Honor allocation.isActive for preparation, not merely notification. A detached source must not acquire transaction effects or operation links before membership installation; canceled construction releases its own hooks, independently installed reentrant members survive. Do not remove a held absent member's source hook merely because membership is absent; existing lifetime/reactivation controls govern that distinction. Destroy/provider cleanup must sever the transaction closure even if leaf handles survive. A provider/delegate cycle is not by itself a leak, but clearing the provider is required to avoid retained enhancer authority through live handles. No new global leaf registry is needed.

Cheapest falsifiers: duplicate registration after observer attachment leaves no residual observer; canceled sibling construction releases only its own delegate; inner member installed during outer failure still prepares and rolls back; held absent/reactivated leaf retains correct identity and one preparation; provider cleanup cannot erase a replacement. These obligations are not verified by source inspection alone.
