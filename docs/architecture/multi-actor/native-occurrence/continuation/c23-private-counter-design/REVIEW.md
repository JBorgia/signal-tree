## Why this cell, and what is preserved

entity-signal.ts:390 selects the runtime; :401–419 creates one version carrier per EntitySignal closure, not one per row. It survives while that collection and its retained projection closures survive. Reads are :454 createVersionedProjection and :1736 the fresh tap reader. Writes are :3504 updateSignals and :5400 membership wake. Neither caller nor returned API receives the version location itself; public readers depend on it, but their payloads are collection projections, not the carrier. Numeric increments are useful cache revision keys and must remain numeric/ordered; this is not an epoch conversion.

The version is not bound to the collection's EntityPublicationSource or an entity field/membership source. That source is separately constructed at :1866 and disposed via onDispose at :1867. Native ownership/permission/source facts for row writes continue through that existing source. The version's generic registration instead allocates a separate intrinsic source, invokes the native scalar factory, and seeds private nativeValues/nativeViews with an initial requirement (intrinsic-mutation.ts:230–241; experimental-publication/private.ts:139–141). No public collection snapshot contains this private counter, so recursively supplied public views do not gain this scalar source as a payload child.

In neutral derive, capturePublicationInput happens before reading/updating (:509 onward). The createCell writer (:555–573) accepts only next, compares/stores it, and ignores both preparation callbacks. Thus the private version derives create a capture object that cannot be consumed by this writer's prepare/complete path. Changing just this source selection removes that unused factory/capture; it does not suppress the entity source, application callback input capture, row permission or prepared terminal records. Generic createCell still supports actual-data interception/late observation and MUST stay registered.

The private counter still calls the exact same derive implementation on the same binding. No extra version() read, no replacement with native mirror data, no extra tracking, no callback reorder, and no custom realization interpretation. runInvalidationGroup still advances subject epochs, then version, then owner invalidation; first-error delivery/completion behavior and installed read revision remain untouched. Membership wakes, omitted/reactivated collections, current-reader refresh and retained tree teardown semantics therefore still require their existing controls; they are not proved merely by no cell escape.

Do not expand this first seam to neutralEpoch fallback (:2255), weak activation carriers (:2287), membership revision, restoration index/history/frontier, destroyed, metrics, fallback actual leaves, or native implementations. Native private-cell nonregistration is precedent, not authority to alter other roles. No new strong references or explicit cleanup obligation should be introduced. Retained public projections may legitimately keep the existing collection closure alive; do not equate tree.destroy with proven GC collection.

A private injected factory that retains every source could observe the old version registration. That is not proof of public reachability; document it as an internal diagnostic change, never use it to excuse a supported custom-runtime observer regression. Custom constructors remain on their original path.
