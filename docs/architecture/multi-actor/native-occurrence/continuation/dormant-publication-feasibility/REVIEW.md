# Dormant preparation feasibility — bounded source review

**Conditionally feasible for a source-certified clean prefix; not feasible as a check of current listener/pending counts, and not implementation-ready from the existing lazy factory alone.** No current contract found requires materializing every publication certificate during a genuinely obligation-free prefix. Existing physical storage and ordinary fallback can represent that prefix. However, current source has no complete activation barrier or late source-seeding operation proving the proposed omission safe. Main should review those concrete gaps before any patch.

This is one feasibility question, not an alternative architecture proposal. No runtime change, omission experiment, savings estimate or cost-gate claim was made. A source activation state must describe how the existing source's truth is represented; it must not become a second value, topology or responsibility authority.

## Premises and exact source

Owner scope: “no consumer, no own/foreign pending owners, no inspection divergence/recovery/diagnostic obligation” and “initialize at first real obligation BEFORE its write.” Contributor contract: “Framework packages may realize SignalTree truth for their runtime. “Clean prefix” must be historical, not merely a current observation: no relevant obligation has been installed, consumed, exposed or escaped during the omitted prefix. ## Concrete positive basis and hard counterexample

For ordinary entity values, `physical/entity-value-store.ts:57–84` already defaults ordinary-before to physical-before when no inspection baseline exists. `physical/entity-ordinary-topology.ts:27–39` already defaults ordinary placement to the physical stage when no divergence/overrides exist. Clean ordinary changes can therefore remain represented by the existing physical source, provided the source has never crossed a disqualifying boundary. This is a representation argument, not proof that all current ordinary preparation can simply be skipped: continuity, subject lifetime, absence, held handles and capture contracts still matter when activated.

Publication provenance has a stricter condition. `experimental-publication/lifecycle.ts:181–207` prepares requirements and finalizes a possible-owner window from the **global** pending-owner registry after callback-capable preparation. It is not limited to owners of the destination tree. `nativeProof` at 155–174 retains inherited uncertainty and exact possible-owner history; settlement does not retroactively make that history declared-independent.

Executed paired discriminator: two bare sources can end with the same value 7, neither having a source Link during its writes, while one wrote during another tree's pending owner. After that foreign owner confirms, both can again have no pending owner from that history. Nevertheless, subsequent native consumption must distinguish them. Replacing both histories with a fresh clean seed is therefore concretely unsound. Losing a still-pending window can start an outbound effect prematurely; losing a settled historical window changes conservative/surviving evidence into declared proof.

This refutes “activate when a Link finally appears” and “no pending owners now implies source history is clean.” It does **not** refute activation before the first write/consumption that would create the historical obligation.

## Missing rules before implementation review

1. **Source-certified eligibility:** retain enough source-owned state to know the entire omitted prefix was clean. No consumer now, no own pending owner now, physical equality, or a disposed Link alone proves this. Do not erase an activated history because its owners subsequently settle.
2. **Complete bootstrap:** seed current values, subject identity, presence/absence, order/key support and ordinary equality from existing authorities only. Preserve already escaped handles/snapshots. Current entity native factory supplies no such operation. Missing support must not be replaced by either unjustified clean proof or an unnecessarily unavailable input that blocks the genuinely clean case.
3. **No window rebasing:** when clean state is first consumed while a newly opened unrelated owner is pending, do not run ordinary authorship preparation at activation and attach that new owner to an older clean value. Activation is representation of prior truth, not a new write. Conversely, never drop an owner that was possible when the actual write occurred.
4. **Admission reentry:** specify activation/seed publication and source revision ordering across supported callbacks. Recheck at the actual pre-install boundary; preserve source admission's captured input timing. The current seams expose the problem but do not already implement a universal dormant-to-active protocol. Simple fallthrough after an invalidated entry check is not justified.
5. **Exact scope:** normal state/identity, equality/interceptors, native notifications, ordinary/physical divergence, responsibility and callbacks remain intact. This review does not authorize omitting them. No savings are inferred by subtracting whole modules from earlier attribution.

## Executable discriminator and observed results

Two new specs are supplied in tests.patch, runnable on any proposed successor through Nx. They each cover scalar and EntityMap sources across clean, foreign-pending and foreign-confirmed histories. The first creates a late passive source Link; the second leaves the source entirely unlinked until native input capture. Both open an additional unrelated pending owner **after the original source writes**, assert one callback invocation, real source/target values and unchanged unrelated owner state, and inspect actual endpoint sends and receipt basis.

All **12 cases pass on the unchanged frozen baseline**:

| Source history | Initial receipt | Outbound before original owner settles | Final basis |
| --- | --- | --- | --- |
| Clean prefix | eligible / declared | `[7]`, despite the newer unrelated pending owner | declared |
| Foreign owner pending at source write | conservative / unknown | `[]` | surviving after confirmation |
| Same foreign history, already confirmed before enrollment/consumption | conservative / unknown | `[7]` | surviving |

The clean row catches false obligation introduced by late bootstrap; the pending row catches an actual early-send leak; the confirmed row catches historical proof laundering that endpoint-value assertions alone miss. These are executable **semantic** discriminators. They do not prove dormancy, activation count, or cost: no dormant implementation exists in this task. A future patch must pair them with its own source-state assertion showing the clean prefix was actually dormant and activation occurred before evidence exposure/obligation, without adding a public test API.

Focused existing boundary replay: BASE-1 and BASE-2 inspection creation rules and supported recipient preparation reentry pass (three tests). Two existing `publication-enrollment-adjudicated.spec.ts` enroll-in-updater cases fail at **line 42**, because the **newly enrolled secondary Link** receives zero sends instead of one. Earlier assertions for the primary Link pass. Raw first failure is preserved in `runs/activation-boundaries/first.log`; 34 unrelated cases were filtered. No fixture or runtime repair was attempted. This is a current-baseline qualification gap for dynamic enrollment, not evidence caused by a dormant optimization.

Spec-type checks pass, including the final pair of diagnostic files. No broad suite, CPU, allocation-saving or framework-wide equivalence claim. Source inspection covers native adapter binding; executable discriminators here use the neutral kernel. Actual Angular/Vue/Solid callback and native-publication timing remain successor falsifiers, not assumed passes.

## Disposition for Main

There is **no demonstrated semantic impossibility for a never-obligated clean prefix** represented by existing source truth. There **is** an executable impossibility for reconstructing arbitrary previously unobserved history from current values/current owner counts. Therefore this is a conditional feasibility result, **not implementation go-ahead**: Main must review a concrete source bootstrap plus complete activation/reentry boundaries. The existing secondary-Link enrollment failure must remain visible when qualifying that seam; do not silently normalize it as a new guarantee or expand this task into its repair.
