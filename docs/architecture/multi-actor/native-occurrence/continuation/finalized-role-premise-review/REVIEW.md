# Independent finalized-role premise review

**Conditionally sound representation premise; not yet a complete implementation design.** A finalized composite can replace ancestry with an equivalent data proof while retaining identity and live OwnerCells. No semantic counterexample to that narrow transformation was found. The concrete missing design fact is installation-gated enrollment/cleanup for every unresolved composite that can remain source-owned. “Ready” alone supplies neither that hook nor cleanup authority. No runtime authorization or acceptance follows.

## Concrete hook requirements

1. Already-ready composite: at construction, calculate the exact union once and return a data-backed requirement with the same provenance defaults. No subscriptions, notification, or install authority is needed for this pure detached representation. Do not invoke arbitrary accessors; only the source-owned proof graph is in scope.
2. Unfinished composite destined for nativeValues/effect support: carry it in the prepared native completion/installed record, not a global registry and not a listener registered by combineNativeRequirements during preparation. intrinsic-mutation.ts:54–59,347 already gates native completion with installedPublications. private.ts:180–182 currently carries selected requirement and activation separately, but completes only activation. This is a concrete place to enroll the installed selected composite, including the no-Link case. It needs an explicit lifecycle-owned cancel/release path.
3. Readiness transition: after both unfinished and unactivated flags are gone for every component, materialize the role union before dropping ancestry. finish's final deliveries (:371–373) and deliverNativeRequirementReady (:211–214) are the existing transition sites. Local registration may use their readiness notification machinery AFTER installation; cancellation and normalization must be idempotent. Computation itself must not invoke recipients or alter the established notification/error order. Owner settlement is neither necessary nor sufficient.
4. Coverage: private.ready creates recipient composites; observationRequirement wraps selected support; entity.ts:228 constructs support composites, while its complete(:234) only activates the prepared requirement. A scalar-only hook cannot establish a shared combine helper's complete lifetime coverage. Specify how each durable unresolved composite is enrolled, or explicitly leave that call site unchanged. An idle installed source with no recipient must still close; reader-triggered compaction is insufficient.

Do not add listeners in generic construction: an old unfinished child can hold the listener closure strongly, retaining an uninstalled parent after a later preparer throws. Weak maps do not prevent this edge. Conversely, source-owned normalization cannot be cancelled merely because one Link is disposed if the source remains live. Separate source lifetime, recipient subscription lifetime, and detached failed-attempt lifetime. The existing onNativeRequirementReady release-before-callback and notifyRequirement first-error aggregation must remain effective.
