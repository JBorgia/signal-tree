# C21 portable-source audit

## Result

**Do not treat the current native-occurrence archive as a self-contained reconstruction of C21.** There are concrete omitted source bytes and an unavailable named git baseline. This is a preservation finding, not a runtime acceptance verdict. No root/archive writes, test execution or build occurred in this audit.

Target is `/private/tmp/st-native-combined-c21/SNAPSHOT-C21.json`, SHA-256 `73e4ecfde64ee05a1eed1eb1362e8ca6f18755b1192a3583454440ef4ad68c27`, 3066 paths. TARGET.json preserves the path/hash map. Root HEAD is `628d302dadb082a48c58528651c9088234d0a777`; root has existing documentation/tooling changes, not applied by this audit. C21 runtime is not root HEAD. The retained production commit `87f6831fa60cafe87508f0ace84b7638698ca3b0` resolves in root git.

## Concrete gaps

1. **Named early baseline is absent.** `native-occurrence/evidence/IDENTITY.json` names baselineGit `87ddcfdedcb5d91e700d812bd6cbee2f77038510`. `git cat-file -t` fails in root's git database. That identity alone cannot seed replay. This does not assert absence from every machine or external repository.
2. **Archive helper omits source payloads.** `/private/tmp/archive-st-reviewed-evidence.py` excludes `candidate`, `baseline`, `successor`, `raw`, `three-way`, and any directory containing `packages`; it also skips existing `.gz`, `.zip`, `.tar`. `/private/tmp/archive-native-continuation.py` has comparable exclusions. Generated `.json.gz` manifests are lists of hashes, not file-content bundles. The scanned native-occurrence archive has no tar/tgz/zip/git-bundle payload. Some explicit source files and full-file additions are present and were credited.
3. **Useful source bundles remain only in temporary storage.** Read-only tar member hashing shows `/private/tmp/st-dynamic-member-enrollment-successor/candidate-source.tar.gz` has 2975 file members and **69 exact C21 matches** among files unresolved by the retained archive/git/patch check. Examples: Angular current-read-capability spec and typing spec, and Solid declared-publication-composition spec. `st-native-explicit-handoff-successor/continuation-recurrence-archive/frozen-source.tar.gz` and `st-native-prepared-unit-successor/inspection-boundary-freeze/source.tar.gz` each contain **53** exact matches in that unresolved set (overlapping, not additive). They include restoration/order-boundary-evidence.ts and framework composition tests. None of these tar payloads was found inside the native-occurrence archive. OMITTED-BUNDLE-EVIDENCE.json records bundle hashes, counts and exact matched paths. Removing `/private/tmp` would remove these known recovery inputs.
4. **Latest composition identity/harness is not all retained in the archive.** No `continuation/combined-c21` directory existed during inspection. C20 and the clear-guard successor are archived, so this absence alone does not prove the final test delta is lost; the patch audit credits recoverable test bytes. C21's manifest/composition, diagnostic redirect and full-run harness should nevertheless be preserved together. Manifests do not record file modes or a deletion/whitelist recipe.
5. **Replay commands still depend on temporary paths.** C21 run-isolated.py reads `/private/tmp/st-current-read-integration/SOURCE-SHA256.json`; diagnostic-redirect.cjs rewrites the R4 hardcoded trace sink to another absolute C21 temporary path. Node binary and dependency paths are host-local. Those commands are evidence, but copying them without a portable wrapper is not a reconstruction recipe. The exact source tests should remain unchanged; supply an external output redirect and derive input identity from the archived target manifest.

## What was actually recovered

The audit read 7506 files under native-occurrence, decompressed 782 gzip files, and inspected 251 patch/diff payloads. It loaded exact blobs from HEAD and retained 87f6831f, then 4851 distinct matching-path blobs reachable from root git refs (32,406 path/object entries enumerated). It did not assume the working root's current files were C21.

Direct byte hashes plus forward unified-diff replay recovered exact target bytes for much of the tree. The patch check recognized 923 file sections and retained 248 newly derived blobs only when their SHA-256 occurred in preserved manifests. It used exact old-line positions/content, no fuzzy application; new-file `-0,0` sections were included. Every credited final result matches the target hash. PATCH-CLOSURE-COVERAGE.json and PATCH-DERIVATIONS.json give provenance.

**101 files remain unresolved in the scoped set: 26 runtime files, 72 specs, and 3 config/build assets** (`tsconfig.typecheck-specs.json`, root `vitest.config.ts`, `llms.txt`). SCOPED-UNRESOLVED.json lists exact paths/hashes. Runtime examples include entity-signal.ts, transactions.ts, private.ts, entity.ts, lifecycle.ts, physical/entity-mutation-frame.ts and several scalar/membership internals. All scoped tools were recovered by this bounded method.

This is an unresolved reconstruction inventory, **not proof that all 101 files are irrecoverable**: archived Python assembly transforms were inspected but not executed, and fuzzy/context relocation, reverse patch derivation, unreachable git objects and archives outside the stated native-occurrence boundary were not exhausted. Exact current-reader fixture bytes are a concrete gap in the inspected retained inputs: no direct matching payload or source patch was found, whereas the skipped temporary bundle contains those exact bytes. The 69 bundle matches establish a useful missing preservation component without claiming all residual patch chains are impossible.

Historical docs/PDF recovery was deliberately not expanded. The full target has 383 paths unresolved by this method, most outside the requested source/build scope; that is not a claim of 383 code gaps. There was one interrupted exploratory patch enumeration before restricting derived blobs to manifest identities; it produced no coverage conclusion. No full clean-room reconstruction/build was run, so no successful reproducibility claim is made.

## Minimal portable preservation plan for Main

Use **one retained git baseline plus a verified overlay**, rather than retaining every temporary candidate or duplicating the repository:

1. Pin full baseline commit `87f6831fa60cafe87508f0ace84b7638698ca3b0` with a durable ref and record its tree identity. Ensure that exact git object closure is preserved/transferred or fetchable; a SHA alone is not a portable baseline. Do not rely on the absent 87ddcfd baseline. Existing retained git objects can supply historical documents/PDFs. If baseline availability cannot be guaranteed elsewhere, export only the baseline blobs required by the scoped manifest, not repository history/PDFs/node_modules.
2. Preserve the **335 added/changed scoped files** in PORTABLE-OVERLAY-REQUIRED.json, **3,118,737 uncompressed bytes** (actual C21 file sizes). This conservative overlay is relative to 87f6831f and bypasses fragile multi-stage patch replay. It includes source/tests/tools/config, package/tool README assets and llms.txt; no historical docs/PDF tree. A small compressed content-addressed payload or path-preserving overlay is sufficient. This is a preservation plan only: these payloads have not been written to root by this reviewer.
3. Retain TARGET.json and SCOPED-MANIFEST.json. The latter has 1738 paths, including build assets, manifests, lockfile, Node pin and configs. Reconstruct from a whitelist: obtain matching baseline files, overlay changed/new bytes, materialize only scoped paths (or explicitly delete baseline extras). Verify every output hash and record modes/symlinks separately. Do not let stray baseline specs enter discovery. Archive package documentation used as build assets even though historical docs are outside scope.
4. Preserve C21 COMPOSITION.json, original patches/inputs, original raw commands/first failures, run-isolated.py, run-full-watchdog.py, progress-reporter.mjs and diagnostic-redirect.cjs. Supply a separate portable wrapper using relative manifest/output paths; preserve original command bytes as evidence. Pin Node24.15.0/pnpm10.17.0 and use the preserved lockfile for dependencies. Root's node_modules symlink is not portable; an offline dependency guarantee would require a separate pnpm-store export and is not established here.
5. Before claiming closure, reconstruct into an empty scratch **without reading any `/private/tmp` candidate or source tar**, verify all scoped hashes/modes, then have Main run the intended focused discovery/types/build checks when the full qualification is no longer competing. Full release/doc gates are not implied by this source preservation subset.

The overlay is intentionally larger than the current unresolved set: it is a small, simple reconstruction primitive that avoids relying on patch ordering, assembly-script environments, or incidental git reflogs. No need to archive another full-repository tar.
