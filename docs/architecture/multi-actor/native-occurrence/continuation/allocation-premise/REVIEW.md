Verdict: the per-member construction record plus detached storage handoff is viable. Do not implement append/truncate, numeric slot reuse, or merely clear publication listeners. The following concrete seams must be included before claiming full cleanup; none requires a public API or different publication authority.

1. **One explicit construction owner, created before buildAddition invokes recursive construction.** signal-tree.ts:1044, :1565–1582 currently allocate then prepare responsibility. Ownership must cover failure inside createSignalStore and prepareMemberResponsibility, not only installPreparedMember. Pass it explicitly through recursive ordinary branch creation. Each independently invoked public mutation receives a distinct record. Never sweep “all allocations since start”; do not enlist already-existing children. Close each member once using installed/canceled state, not outer function success.

2. **Redirect the complete leaf binding, not only its reader.** Neutral tree-scalar-leaf-runtime.ts:125–170 closures capture kernel, slotIndex, publication and shared liveness; createLeaf:199–209 also populates binding and leaf maps. Native native-tree-scalar-leaf-runtime.ts:142–173 captures the same plus realized carrier; replace:197–273 and derive:275–345 use kernel/readRecordSlot, capture hooks, publicationInput, reAdd and publish helpers directly. Native .set/.update already point at these writers. All read, peek, replace, derive, notify and authority-admission operations must resolve the same per-cell state. Otherwise a canceled writer still reaches the live tree or an installed writer keeps detached storage. Preserve the same native cell/token identity: no second carrier construction at commit.

3. **Prepare native machinery before commit.** observation.createWritableCell may execute its getter; createToken, commitNative, token.invalidate, runInvalidationGroup, equality, capture/observer hooks are callback-capable. None belongs in the handoff. Native publication.bind currently receives realized.token at construction (:162); neutral publication.bind similarly owns the writable binding. Retain these in the attempt until install. Callback-free transfer may append prepared value/equality records, attach existing binding/token and position mappings, and switch the private forwarding cell. Do not use a normal value write, factory call or equality check to transfer storage. Publication/completion stays after the installation boundary.

4. **Enumerate strong registrations.** Slot kernel owns values[], equalities[], slotByPositionId (tree-scalar-slot-runtime.ts:createSlot); neutral publication owns bindings[]; native publication owns tokens[]; both leaf runtimes own leafByPositionId. These presently have no per-attempt detach/attach contract. Deferring just slotByPositionId while appending values still fails the original slotCount oracle and retains data. Resolve installed slot identity at handoff, after nested writers, without reserving/reusing an array suffix.

5. **Position and capture seams are also eager.** position-registry.ts:99–127 owns parents/address Maps; allocate inserts immediately, registerPositionAddress inserts immediately. signal-tree.ts:1482 and finalizeLeafSignal:222 register addresses during construction; finalizeLeafSignal:232 calls wrapOwnedWritableSignal when capture is enabled. Inventory and stage/own these exact registrations/hooks, plus prepared responsibility and native occurrence enrollment. Existing registry has no exact cancel API. A private per-attempt reservation/attach or exact owned-entry cancellation seam is required; monotonic unused numeric IDs are not permission to retain Map entries or rewind counters. Do not substitute a different registry identity: prepared native occurrences validate the actual parent/child registry/address relationship. Validation must see the attempt's own provisional facts without treating them as installed ordinary authority.

6. **Detached branches retain root routes too.** materializeOrdinaryBranch:1455 attaches the live scalar runtime to both accessor and backing store; ordinaryMemberBuilders:1562 closure captures materializationContext, captureRuntime and scalarSlotRuntime. An escaped failed child branch can therefore retain/re-enter the root even if leaf value arrays are detached. The record must clear/redirect these construction and runtime forwarding edges on cancel, and release prepared responsibility/inventories. A live shared liveness object must not remain usable by canceled leaf writes to reAdd the parent. Leaf-local weak metadata alone is not the root-retention issue; strong root-owned entries and escaped-child→root forwarding paths are.

7. **Explicit installed handoff inside member installation.** materialize-markers.ts:800 prepares fresh presence/ordinary image/occurrences and invokes membership preparer, then validates. Transfer only after all callback-capable preparation and same-key/parent validation. At the existing physical membership + terminal-record boundary, attach the exact prepared resources and record installed state before linkAddedMember/inheritObservation/completion can throw. Do not cancel successfully installed resources because later observation delivery throws. Existing prepareCommit wrappers can publish by default; they are not a callback-free allocation-attach seam. Keep allocation attach a private primitive data handoff, not a published frame commit.

8. **Preparation-time child mutation requires an explicit check.** A preparer can retain and write the detached child or perform a nested live write. The planned ordinary image must match the value actually attached. Track/validate the attempt's own staged revision (or prove an equivalent existing validation covers it) before installation; do not silently install changed data under an older prepared payload. This is a validation obligation, not permission to invent a new public refusal policy. Same-key nested installation must invalidate the outer stale plan while preserving the nested exact handle.

Minimal discriminator set before freeze: unchanged repeated-refusal slotCount0; responsibility-preparation throw; membership-preparer throw; stale validation; retained failed child plus retry with no alias/root publication; independently installed nested child survives outer refusal and future writes; same-key nested identity survives; installed completion throw preserves allocations; detached child write during preparation cannot mismatch payload; neutral and actual native carriers cover set/update/peek/notification and cleanup. Measure actual root-owned registrations, not only slotCount. Keep existing ordinary/inspection and partial-installed callback/error controls.

No general allocator, graph registry, new SDK, weakened native type, global checkpoint, or weak reference to needed live authority is required. The missing pieces are private per-construction allocation/registration ownership and a callback-free attach operation across the named owners. Main/Carver should include those seams in the bounded implementation; a slot-only patch is insufficient.
