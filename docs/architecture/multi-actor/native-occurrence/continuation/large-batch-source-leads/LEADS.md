It does not traverse rows or flush pending delivery. Unsorted ids() may walk the active linked list to populate keysCache (`physical/structural-store.ts:220–227`), then stores a second copied array in idsValue and retains the source array through idsSource. Structural mutation invalidates keysCache; it does not itself clear idsSource/idsValue. Therefore interstage ids reads can add/retain old key arrays and move allocations between phases. The next setAll uses snapshotActiveOrder (:231), a separate linked-list walk that does not consume keysCache; warming ids does not remove that walk.

No source-backed claim that the extra reads clear pending work or prevent a stall. They change cache state, allocations and retention, potentially affecting engine behavior; that remains unmeasured. No sortComparer or row materialization is requested by this fixture's count/ids path.
