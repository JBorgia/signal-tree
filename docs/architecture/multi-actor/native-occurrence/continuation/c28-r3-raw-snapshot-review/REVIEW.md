## Required boundaries; why this is not a blind substitution

1. **Physical versus exposed presence.** Raw handle resolution ignores collection presence. Existing byId/row reads enforce rowAbsent (:514–523), which permits hidden physical rows only for the matching tree registry and matching tap depth. `internals/physical-rows.ts` explicitly documents nested tap and other-tree exclusion. Restoration.applyReversal (:715–734) opens/closes that window in finally. A raw read in an ordinary hidden collection or nested consumer tap would return data the old path rejects. Merely proving that typical undo runs in applyReversal does not prove every adapter invocation does. Preserve this collection-owned visibility gate for the optimization's supported callers; do not expose raw physical truth via callbacks or add an ordinary fallback that bypasses it. Existing raw handle hooks alone cannot express the gate.

2. **Address, lifetime and staged occupancy.** Snapshot input is a key: removal obtains it from resolveEffectiveRemoveKey/prepared or live subject state (:2270–2294); rekey uses effect.before. Acquire the key's lifetime at the original read point and resolve that handle. Do not read arbitrary retained backing by effect.subjectId or select the ordinary-view value. Reject/absence behavior and planned future key occupancy must continue to come from existing validation. Handle identity must not cross collections/incarnations. A fabricated/old handle does not become a general source authority.

3. **Cloning/identity.** Do not add a clone inside a generic raw helper. Keep the placement rekey deepClone at its current callsite, keep removal's live-reference behavior and existing prepared-value preference. `deep-clone.ts:13+` tries structuredClone, then falls back to recursive cloning; getters/proxies/unsupported values can trigger user code or throw. Moving or doubling the clone changes reentry/error timing. New raw read should not inspect payload keys/getters merely to obtain the value.

4. **Validation and reentry.** buildPreparedRealizationContext (:2480–2511) runs canApplyEffect before each context update. Later physical frame validation/install checks remain necessary. The raw seam's maps/value access is callback-free in its implementation, but it removes callback-capable facade/custom-location construction and reactive dependency reads from the old path. A proxy ownKeys/custom createDerived side effect formerly reached through facade creation need not be reproduced for an optimization, yet public final state, refusal/no partial installation, errors from actual retained clone work and unrelated reentry authorship must remain. This review has not proved those controls. Never weaken existing stale-frame validation or silently waive an original reentry fixture.

5. **Supported shape/fallback.** Adapter recognizes collections structurally by byIdOrFail/changeId/removeOne (:3405); private test doubles or other admissible nodes may lack raw hooks. A mandatory unchecked call would narrow support. Optional internal use plus the original fallback preserves that shape, but fallback/visibility selection must itself be reviewed. No new public capability is required.

6. **Materialization elsewhere remains.** hasCollectionKey (:3414) still calls byIdOrFail; occupancy checks use it. The sampled call tree also contains direct byId paths. Replacing this one helper does not remove every row projection, native scalar initialization or validation allocation. No predicted bytes/130k closure follows.

## Finite discriminators for a future prototype (NOT RUN)

Keep original controls and first failures, then add only these focused distinctions:

- **Raw identity/lifetime:** acquire row A; same-lifetime rekey returns exact backing reference at new key; fresh same-key B cannot satisfy A; reset with reused subject ID leaves old handle missing. Active missing backing must not turn into a successful undefined snapshot. Existing physical/entity-handle-resolution.spec.ts tests rekey and same-key ABA; structural-store.spec.ts:172,194,212 covers incarnation/key distinction. Extend only identity/missing-value gap if needed.
- **Real undo/redo endpoint:** small mixed remove/restore and placement rekey with differing address versus row.id. Exact final rows/order/held row+field behavior, and no field projection constructed solely by the targeted snapshot when no prior facade exists. Existing tree-realization-adapter.spec.ts:2812,2922,3069,3353,3492 are preserved predecessors. Materialization count is private diagnostic; useful values/lifetimes are the public oracle. Do not demand zero total projections while hasCollectionKey remains.
- **Visibility boundary:** hidden collection reversal in its own tree can read retained physical row; an observer nested at another tap depth and another tree still observes absent. Same adapter read outside a valid physical window must retain old absence/refusal. Use existing physical-rows rules, not a new permission. This is the decisive falsifier for directly using raw hooks without the guard.
- **Clone/reentry boundary:** accessor/proxy in placement-rekey snapshot runs only at the existing deepClone boundary, with original call count/throw precedence and no partial installation. Removal retains reference identity and existing prepared value; no newly eager getter reads. Reentry that replaces/rekeys the addressed subject during a callback must fail through existing validation or preserve the exact prior later-truth result, not install stale payload. Preserve original stale heterogeneous/full-effect validation tests (adapter.spec.ts:4075,4333). Do not invent a new exception oracle without baseline characterization.
- **Reactive/custom-facade compatibility:** held row/field after undo remains live for a later real write; observer reentry and custom location factory behavior preserve useful result/error cleanup. Ordinary operation/read dependencies must not accidentally disappear because a general reader was replaced globally. Scope optimization only to internal realization snapshots; do not rewrite byId or public/custom createCell.
