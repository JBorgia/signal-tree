## Source-owned gaps

- `experimental-publication/private.ts:166–190`: prepareMembership identifies ancestor recipients, then skips a fresh address with no slotNode. Creating that node alone would make ready() throw because `occurrences.get(slot.child)` is absent (line208).
- `internals/materialize-markers.ts:791–847`: installPreparedMember passes no ordinary before/after payload. It prepares before defining the child on accessor/backing storage, installs records, links membership, and completes in finally. Completion is gated by installedPublications through the composed intrinsic publication record; do not replace it with an unconditional late projection.
- `private.ts:327–379`: bindSource cold-enrolls occurrences, fields and preparers by traversing the existing subtree. Future fields have no preparer, relative-field index or occurrence. RecipientOccurrences.enrollCaptured mutates groups, installs proof entries and subscribes immediately; it is not a detached preparation operation.
- `native-occurrence.ts:25–48`: captureNativeOccurrence authenticates the actual root-to-child descriptors. A new child cannot pass that check before its parent edge is installed. Weakening this check to accept matching addresses would admit a different lifetime.
- `private.ts:211–225`: completed membership already accepts source-supplied ordinary after.value and preserves direct collection natural arrays versus containing-branch representation. Supply that prepared value; do not replace this arm with a physical read.
- `link.ts:580–616`: collection recipients have their own prepared projection, explicit acquisition/seed disposition and source registration. The scalar traversal stops at entity bindings. Dynamic scalar enrollment alone cannot claim dynamic collection correctness.

## Recommended private mechanism

1. **Materializer-owned prepared child description.** Extend the private prepared-member result to carry normalized ordinary payload, exact child identity and a detached subtree enrollment description, alongside responsibility. Before is explicit absence for a genuinely fresh member; after is the supplied ordinary value. Use the already validated/materialized value, not the original getter-bearing input and not a later branch snapshot. Inspection installation must retain inspection disposition and must not admit the payload.
2. **Authenticate the pending edge without faking installed ancestry.** Add a private source-issued prepared-occurrence capability at the construction/install boundary. It binds verified parent occurrence/root/registry, key, exact child and internal descendant identities. Validate the existing parent and vacant expected edge before installation; validate detached descendant descriptors while preparation may still fail. Keep ordinary cold capture unchanged. A path string or caller-provided NativeOccurrence is not a substitute. Issue/consume only through the source-owned installation path; this grants identity, never eligibility.
3. **Prepare recipient enrollment without registering it.** For each live matching recipient, allocate missing slot/field trie entries and occurrence groups off to the side, with payload facts and native requirements captured now. Stage scalar preparer registrations, input capture functions and release ownership. Reuse existing enrolled ancestors and exact child identities; avoid separate groups per alias or key string. Sibling recipients get independent state. No insertion into live maps/sets, readiness subscriptions or source preparer maps during a preparation that another participant can still reject. Current enrollCaptured/preparePublicationMutations are imperative; a private staged/reservation seam is needed rather than invoking them directly here.
4. **Install structural and recipient identities together.** The source installer commits the physical parent edge, membership linkage and prepared recipient metadata/registration records before any later updater, equality, tap, observer or completion can run. Recheck the parent/member expectation and recipient generation before the first store mutation; do not discover mismatches by calling ordinary captureNativeOccurrence after the first store write. Registration commit must use prepared intrinsic maps/records, with no user getter/equality or callbacks. Full collection traversal and payload preparation do not belong here.
5. **Activate delivery after installation, before readiness publication.** Once the whole member's enrollment records are installed, activate prepared proof subscriptions and then complete its membership unit. Suppress readiness wakes while activating the set, since ordinary enroll/replace can synchronously invoke proof callbacks. One wake may then process the fully enrolled member. Subsequent synchronous child writes must already find their preparers—even when a later sibling operation throws. Never wait for the legacy membership notifier or a later microtask to enroll descendants. The finally completion preserves already-installed successful membership when later work fails; it must not publish an uninstalled child.
6. **Preserve captured requirements.** Fresh payload and descendant slots must derive support from the source's membership/value construction and captured native inputs/possible-owner horizon. Do not use an unconditional initialRequirement to make an adopted subtree appear clean. A foreign pending owner must still hold it; rejection/confirmation must resolve the actual recorded proof. Admission is not created by successful identity enrollment.
7. **Separate collection enrollment.** For any supported materializer path producing an entity collection, stage the actual EntityPublicationSource recipient registration and its prepared ordinary seed/disposition, with the same representation distinction as current collection delivery. Ordinary whole-value creation currently rejects marker definitions (`signal-tree.ts:910`), so ordinary new-key tests alone cannot exercise or authorize creating a new EntityMap. Keep the existing materialize-markers call path in the caller inventory and establish what it can actually supply. Do not silently skip a supported collection or interpret scalar success as acquisition permission.
8. **Own lifetime and cleanup.** Uninstalled plans own only detached allocations and are discardable on prepare/finalize failure or reentry. Installed registrations belong to the recipient and exact source lifetime; their releases join disposal. Repeated omit/readd of the retained child reuses its occurrence without duplicate subscriptions; genuinely replaced children cannot borrow its slot. Omission masks exposure, not automatically permanent deletion of a live retained child. Terminal completion drops transient enrollment plans/payload references; permanent retirement follows existing authority, not a new unconditional unsubscribe policy. A completion captured before dispose cannot re-enroll or wake a disposed recipient.

This can remain entirely inside materialization/intrinsic publication/native occurrence/recipient internals; no public SDK method or type change is indicated. It is more than a one-line guard change. The needed private staged-registration interface does not exist today; implementation must make its failure and activation boundaries explicit.

## Falsifiers to predeclare before runtime changes

- Replay unchanged whole-value-new-keys.spec.ts: both current timeouts, first added child then n(3), and completed fresh member followed by a later throwing value. Preserve original assertions, timeouts and raw logs.
- Pre-existing root and nested branch Link; independent siblings; nested branch below an omitted ancestor; initially inspection-only child later authored adoption; prove no inspected sibling leaks.
- Exact child omit/readd and subsequent descendant write; address reused by a different child where supported; direct leaf/branch recipients acquired after installation must keep independent identity and natural payload.
- Failure at child construction, responsibility preparation, recipient preparation, finalization and reentry before installation: no new live slots/subscriptions/pending units. Test callback access to the new child followed by another write, and verify that later writes are observed exactly once.
- Successful earlier member followed by later getter/equality failure: the earlier member remains installed and delivered with correct support, while failed later members leave no registration. This is not whole-operation rollback.
- Dispose between prepare/installed completion, dispose while foreign proof is pending, repeated terminal cycles with retained handles: no resurrection and no accumulating subscriptions/strong transient payload retention.
- Actual foreign pending owner holds the new subtree, confirm releases current payload, rejection follows existing semantics without unknown-to-clean conversion. Include thrown/aborted preparation so a failed plan cannot retain a foreign owner subscription.
- Exercise supported collection materialization separately with explicit acquisition versus authored disposition and direct array versus branch `{all: ...}` representation. If no dynamic collection producer is supported, document that source fact rather than manufacturing a public example.
