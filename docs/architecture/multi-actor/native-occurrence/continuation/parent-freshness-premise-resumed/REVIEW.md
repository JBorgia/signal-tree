## Necessary source boundaries

Paths below are relative to `packages/kernel/src/lib/` unless otherwise specified. “Necessary” means the semantic boundary must be covered, not that each listed file must be edited.

1. **Installed snapshot validity distinct from delivery.** `internals/snapshot-authority.ts:31–102`, `internals/materialize-markers.ts:798–871`, and `internals/location-runtime.ts:401–432,568–680`. A warmed branch and every affected warmed ancestor need a synchronous means to reject stale materialization after successful installation and before the first callback. It must work during grouping and after a callback throws or reenters. Refused preparation must not publish fictional installed state. Membership, value changes, absence/reactivation and installed restoration all affect validity; moving only the construction notification does not cover them. Preserve lazy output construction, repeated-read identity and unrelated sibling identity. A neutral source revision, dirty marking, or validation design can satisfy this; evidence does not uniquely require one.

2. **Authoritative scalar input, separate from native mirror.** `utils.ts:449–460,527–540` reads reactive leaves by calling them. Angular's `packages/angular/src/lib/observation-adapter.ts:72–85` returns a native `signal(read())`, whose value changes only through commit/invalidate; its `peek` is the supplied source reader. `internals/native-tree-scalar-leaf-runtime.ts:139–155` supplies the installed slot/liveness reader, while frame commit can explicitly suppress publication (109–132). `internals/tree-scalar-slot-runtime.ts:209–220` installs slots first. A newly rebuilt snapshot that still calls an unpublished native mirror can therefore remain stale. Concrete composition window: `internals/causal-runtime/tree-realization-adapter.ts:808–814` installs scalar slots, then during publish calls entity-plan invalidation before scalar publication; `entity-signal.ts:609` can deliver entity completion there. Snapshot materialization needs installed scalar input while retaining native dependency observation and absence semantics. Do not substitute ordinary recorded values (`readRecordSlot`) for physical installed values during inspection. Advancing native mirrors early is not entailed and risks changing the explicitly preserved app-computed timing. **Source inference; callback scalar-window reproduction not run.** Cheapest falsifier: warmed branch containing a scalar changed in the same selected operation as an EntityMap edit; read branch and native computed in entity completion before scalar publication.

3. **Complete ancestry, including symbols and accessor/store identity.** `utils.ts:449` binds string-key branch ancestry, but symbol-key branch handling at 527–535 does not. Marker handling binds through `snapshotMarkerNode(value,node)` for both key kinds. `snapshot-authority.ts:31–43` only walks registered parents; `node-shape.ts:46–47` canonicalizes accessors to backing stores. Any proposed parent-directed validity mechanism must cover symbol-key branches, newly installed children and accessor/store aliases; the existing parent map alone is not proof of complete coverage. A missing bind is directly visible in source, but **no symbol callback failure was executed here**. Cheapest falsifier: warm root and a symbol-key child, change that child's membership and then scalar value during completion, assert direct root/child freshness and unchanged sibling identity. A mechanism not using parent traversal can satisfy this obligation another way.

4. **EntityMap wrapper and underlying projection must both be current.** `markers/entity-map.ts:370` snapshots as `{all: node.all()}`. `internals/materialize-markers.ts:257–274` separately caches the marker wrapper with `materializeSnapshotNode`. `entity-signal.ts:432–447,1527,1534–1551,3810–3812` uses a version-cached `allSignal` and chooses a fresh reader at getter acquisition only when `taps.depth` is nonzero. The wrapper can hide a current inner reader; a rebuilt wrapper can still read a stale inner projection. The requested acquisition-independent property rules out relying solely on acquiring `.all` inside a tap. Carry installed collection/value/membership freshness through both layers and ancestors; preserve lazy collection materialization. `entity-signal.ts:598–614` installs values before completion and updates projection signals afterward, so delivery-order assumptions need checking. **The supplied controls do not test EntityMap wrapper or pre-acquired `.all`; no executable result claimed.** Cheapest falsifier: warm root wrapper and hold `.all` before an edit; compare held/fresh `.all`, marker snapshot and root inside completion, with a second read checking stable identity. Include point edits and membership/order changes, plus omission/reactivation.

## Unsupported premises and bounded conclusion

- “Membership publication occurs before completion, therefore snapshots are current” is refuted by the raw ordinary controls.
- “Freshly rebuilding a branch necessarily reads installed native scalar values” is unsupported by the Angular mirror source and the mixed-install window above.
- “The existing parent map covers symbols” is false for the branch path inspected; this matters if a design depends on that map.
- “Fixing branch cache validity alone fixes EntityMap snapshots or held readers” is unsupported: wrapper and projection are separate layers.
- Angular controls do not establish Vue/Solid/React callback behavior. Their own native realization boundaries require focused falsifiers; no cross-framework pass claim is made.
- Neither eager whole-tree rebuilding nor earlier framework notification is required by the owner premise. No new public API or framework-specific kernel authority is derived here.

The ordinary warmed-snapshot failure is demonstrated. The other boundaries are required coverage/inferences with explicit unrun falsifiers, not independently executed defect reports. Main can choose the mechanism and run those focused tests against C8. No runtime/source edits, release verification, performance claims or broad-suite duplication were performed.
