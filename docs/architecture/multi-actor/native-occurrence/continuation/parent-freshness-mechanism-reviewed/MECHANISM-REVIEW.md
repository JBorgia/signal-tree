## Required semantics versus optimization

**Zero second-output allocation is an optimization target, not a frozen semantic requirement identified in the owner premise or contributor contract.** Stable returned identity, fresh installed values, preserved callback/error behavior and native delivery timing are separate obligations. The proposal's no-second-allocation control is self-imposed; allocating a temporary output and discarding it can preserve the required returned identity.

Consequently, retaining the existing tracked builder on actual observe recomputation, then returning an already-current cache object instead of the newly built equivalent output, is a legitimate narrower proof. Measure duplicate build/allocation work honestly. Do not infer permission to duplicate user code from permission to allocate twice.

## Concrete missing rules in the touch proposal

1. **One invocation must not accidentally perform two build attempts.** DESIGN step 4 calls observe then checks freshness; the supplement allows observe's build to return with its starting generation invalidated, without caching. A naïve caller then sees DIRTY and builds again, replaying a marker/comparer. Define an invocation-local receipt identifying whether observe actually attempted a build and its result/error. If it did, do not automatically perform a second attempt merely because no clean cache was installed. Preserve the characterized current-call outcome; do not introduce retries, new cycle exceptions or old-value fallback. Source basis: location-runtime.ts:623–669 and native-location-realization.ts:217–222. Cheapest falsifier: finite mutate-then-return callback with invocation counter/tripwire. **Not run on proposed mechanism.** Worker baseline cases establish that mutation/straddling output is reachable, not hypothetical universal behavior requiring repair.

2. **“Touch” needs a closed set of safe operations, not calls to arbitrary readers.** utils.ts:389–393 calls dormant functions; child branches normally pass through signal-tree.ts:464–475's absence check before materialization. Calling a retained child observe directly can evaluate its recipe and bypass that accessor check. Generic snapshotMarkerNode at materialize-markers.ts:257–274 may execute a custom snapshot. Explicitly preserve dormant membership dependencies and symbol ancestry, without replacing a missing recipe with a snapshot/comparer invocation. A child observe call is safe only if its possible recomputation is accounted for; its name is not a callback-free guarantee. **Source-level gap, no mechanism runtime failure asserted.** Cheapest falsifier: direct V1 read followed by delivery, with dormant branch/reactivation, symbol child, and calibrated custom/sort callback counters. Then change each newly included dependency independently.

3. **R4 projection currentness is not a callback-free dependency-touch API.** C8 entity-signal.ts:447 recomputes when either notification version or installed revision differs. Calling `.all()` merely to touch after direct materialization can therefore invoke `computeAll` again on normal notification; the comparator is user code. The getter at 3935 also still selects a fresh reader inside taps. Reuse R4 for actual current projection values; if touch is retained later, it needs a private observation-only collection operation, not another epoch/cache or an `.all()` call assumed cheap. A branch-wrapper clean touch must not bypass R4 or replace its existing errors. Cheapest falsifier: warmed sorted collection, completion snapshot read, normal delivery, callback counts/error identities and subsequent isolated collection change. **Not run on proposed mechanism.** This is an integration obligation, not a claim that R4 lacks freshness.

The supplement correctly acknowledges that returning successfully after an unstable touch can let the runtime mark itself clean. A private trackedG flag cannot prevent that (neutral location-runtime.ts:635–657). Do not resolve it by early native publication. The narrower proof avoids inventing touch recipes while this is unresolved.

## Bounded implementation path approved

- Keep the install-only generation/ancestor bookkeeping, same retained observe identity, canonical accessor/store identity, symbol edges and affected dormant descendants. Bind dependencies/ancestry before invoking reads that could reenter; register the record before its first build. Mark only after the relevant installed unit/evidence is complete and before callbacks. No output construction or publication in the install hook.
- Retain the ordinary tracked builder on actual observe evaluation. With stable start/end generation, prefer an existing cache winner at that same generation; otherwise install the successful result. This preserves runtime dependency collection and returned object identity while allowing a measured temporary output. Preserve the runtime's old delivered value until it evaluates normally.
- First exercise this path with plain branches and source-owned scalar terminals, where the inspected build path need not execute user marker/sort callbacks. Keep volatile custom-marker behavior on its existing route. Do not silently generalize duplicate builds across callback-bearing paths. Extend only against the existing finite callback controls, preserving their limitations; universal custom-callback correctness is not a prerequisite for this bounded proof.
- Integrate the EntityMap parent wrapper with R4's existing source-current projection machinery. Do not duplicate it. Sorted collections require the bounded count/exception comparison above before claiming unchanged callbacks. An extra allocation is acceptable; an unreported extra callback invocation is not.
- Discriminate native terminal input separately: compare rebuilt branch output, installed scalar source and native mirror inside a real post-install/pre-publication callback. Current native leaves use published mirrors (Angular observation-adapter.ts:72–85; native-tree-scalar-leaf-runtime.ts:139–155). If a private installed reader is needed, preserve absence/attachment semantics and native dependency observation without publishing the mirror early. **This window remains untested by the parent controls; no native-terminal pass claim.**

C7a characterization now bounds the exceptional cases: volatile-marker immediate recovery differs from cached-sort recovery; Angular cold writes may stop at NG0600; warmed marker mutation/nesting is reachable; neutral sort self-reentry can end in stack overflow. Preserve these as baseline limitations rather than expanding the task to repair them. For callback-bearing paths changed by R4, use the corresponding C8 behavior for comparison instead of importing C7a's cache policy.
