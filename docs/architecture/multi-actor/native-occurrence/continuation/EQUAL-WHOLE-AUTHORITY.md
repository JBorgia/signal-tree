# Equal whole-row publication — owner decision

Owner selected November2,2026: “Allow fresh publication evidence for explicitly replaced unowned fields (recommended).”

The approved question was: “One equal-value case needs a semantic decision: a whole-row replacement explicitly supplies the same ordinary values already stored, but their old synchronization evidence is held only by a possible dependency on an unrelated pending transaction. May v16 treat those explicitly supplied, unowned fields as freshly authored for publication—matching explicit field writes—while preserving actual pending transaction ownership, rollback behavior and value-notification suppression?”

## Selected contract

An explicit whole replacement may offer its supplied unowned fields to native authorship admission even when ordinary values compare equal. A new admitted endpoint refreshes publication evidence. Actual pending destination ownership is preserved; declaration permission never erases a transaction's claim. Rollback/inverse and net-zero behavior and value-notification suppression remain unchanged. Mere observation, reordering or replay is not new whole-value authorship.

This extends the equal-value boundary; it does not reopen the earlier inspection-adoption approval. It authorizes the scoped implementation and regression work under the governing plan. It does not authorize activation, new unspecified public exports, release, changed budgets, or a Link-only relabeling of historical support.

Implementation must preserve lifetime and own-property presence, distinguish explicit/partial/derived/realization inputs, and consume the endpoints selected by native admission. Required discriminators and original first failure are in c12-publication-admission-review/REVIEW.md. No implementation acceptance is recorded here.
