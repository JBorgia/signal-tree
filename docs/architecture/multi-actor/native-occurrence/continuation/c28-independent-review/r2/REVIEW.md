## Wake concern: bounded invariant

private.ready:304 adds a wait for unit.native ONLY when unit.relevance is nonempty. completeScalar:446 still subscribes only to unit.invocation. For a unit constructed by the ordinary scalar factory, the closure check establishes all old contributors ready at admission. With a nonempty mask, its native requirement is exactly a composite of C alone (admitted) or ready S plus C (retained). C is the same prepared requirement placed in unit.invocation. Readiness for these already-finalized/activated old contributors is not re-opened by owner outcome changes. Consequently native readiness cannot lag invocation readiness through an independent old contributor on this path. Normalization itself is not an extra readiness condition: a still-composite native requirement already reports ready once its components do.

C26 completion ordering reinforces this invariant. intrinsic-mutation.ts:333 places native completion first; completePublication:58–67 continues all parts despite errors and rethrows the first failure. Native completion registers normalization before delivering activation. Recipient completion either sees C already ready and immediately wakes, or registers on C and wakes when its horizon closes. onNativeRequirementReady releases subscriptions before invoking callbacks; notifyRequirement continues later callbacks after a thrown listener. No second native listener is needed under this construction invariant. Exact bypasses and empty-mask units do not take the new native wait.

This is a source proof restricted to the actual factory, not a generic guarantee for arbitrary manually assembled Unit/native pairs. If a future producer supplies nonempty relevance with native containing another unfinished component, this listener arrangement can strand. Cheapest falsifier: a real factory-produced nonempty-mask unit where invocation becomes ready while native remains unready, and no later wake occurs. Current source construction rules exclude that witness. A diagnostic assertion of this implication plus useful delivery in both completion orders is preferable to an arbitrary private mismatched-unit injection.
