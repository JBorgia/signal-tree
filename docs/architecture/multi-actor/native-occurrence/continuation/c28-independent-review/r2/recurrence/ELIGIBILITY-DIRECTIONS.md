## Direction A: capture prospective recipient comparison evidence

An exact capture can provide admission-time eligibility for a later proof IF every proof/cell that can become a comparison operand is covered and its relevant readiness/role facts are captured without invoking user code. A single current binding or current field proof is insufficient. R2 already demonstrates the concrete problem: n1 current support is p-only while the old receipt prior retains confirmed a. Sibling preparation links tentative facts through publicationPredecessors; reduction may first install/normalize a sibling and collapse a tentative receipt back to effectivePredecessor. The eventual aggregate prior need not equal either leaf P or the operation selected when the next unit was prepared.

Required obligations: capture both current aggregate contributors and legitimate fallback/prior alternatives; handle already-prepared sibling facts whose final aggregate proof is not yet known; validate that reentry has not changed that domain before installation; preserve unknown/invalid/negative-membership evidence and exact pending-at-capture lower bounds. An open candidate cannot be treated as closed merely because it later becomes ready. If closure is required, either prove the late-selected operand was within the closed domain at admission or conservatively decline comparison cleanup.

This need not retain a union of historical owners forever: existing finite installed facts/requirements might provide a transient comparison domain, released after completion. But a permanent fallback-owner union or cumulative lineage retained on current state would recreate the retention problem. Merely retaining a proof pointer instead of an owner list does not avoid retention. The design must state the lifetime and bound, including nested/reentrant pending sibling units.

Cheapest falsifier: the preserved n2 recurrence plus one grouped two-sibling equal admission where the first sibling collapses and the second resolves to an older prior. Record the actual reduction operands against the admission-captured domain. A missing old a or a newly selected unenumerated proof falsifies completeness. No broad historical replay required.

## Direction B: local immutable confirmation cutoff

A hypothetical predicate can answer a different question without enumerating every historical cell at admission:

eligible(cell, admission) = exact cell confirmed by admission cutoff AND not in the captured/protected lower bound; removal additionally requires I/V-only eligibility, role/flag preservation and closed eligible certificate context.

The current OwnerCell has identity and outcome, but no immutable confirmation time/order. owner/id are transaction identities, not confirmation order. Example: an early-created q can confirm inside the updater after input capture, while a later-created r confirmed before it. Comparing transaction IDs or checking outcome at reduction misclassifies q. Source disappearance must not create confirmation either.

A local monotone confirmation ordinal recorded exactly once on the existing cell at pending→confirmed, plus an admission ordinal, can represent the stated temporal predicate even for a cell first encountered on the late prior. The source has a concrete hook: ownerTransition changes outcome before notifying dependents/observers and forbids reversal. Repeated same-terminal events are currently permitted, so they must NOT restamp an already-confirmed cell. Replaced registry cells must not inherit another cell's stamp; rolled-back/abandoned/missing cells remain ineligible. Metadata is cell-local and scalar; no global strong registry/list of historical owners is necessary. This would be publication eligibility metadata only, never ordering of writes, causal priority or server authority. Overflow/epoch and same-runtime identity handling would need an explicit bounded representation decision.

Crucially, this stamp does NOT replace protection. q captured pending then confirmed before scalar preparation has a stamp before that preparation cutoff but must remain protected by input.owners/frame entry protection. Snapshot those lower bounds before admitting cleanup; later frame changes must not retroactively weaken them. Nor does a stamp prove the prior certificate's horizon was closed at admission. If that requirement remains, the late operand must have an independently valid closure witness; testing ready only at reduction would enlarge cleanup to history deliberately excluded by R2. A completeness mechanism for cells is not automatically completeness for proof provenance.

Cheapest falsifiers: n2 old a remains eligible despite no current-source reference; q captured pending and confirmed before preparation remains protected; a confirmation after admission remains ineligible despite being confirmed at reduction; duplicate confirmation does not change classification; source removal/registry replacement never fabricates confirmation; an unresolved historical prior becoming ready later is not silently treated as admission-closed. Pair with existing fresh confirmed-validator contradiction and opaque dual-obligation controls.

## Common acceptance boundary

Either direction must preserve raw validation and earlier issued evidence, gate projection on completion/activation, preserve D/W/unclassified roles and all flags, and compare the actual reduced aggregate without forcing receipt status. Comparison eligibility need not authorize source normalization or dependency deletion on an old operation. Keeping these permissions separate is required whichever data representation is used. The present evidence supports investigating these bounded mechanisms; it does not establish either implementation or justify accepting R2.
