## Mechanism proposed

1. Extend each existing MATERIALIZED record with a private installed generation, cached generation, initialized flag and current output. Retain the SAME `observe` object. A private `markSnapshotInstalled(node)` canonicalizes with snapshotNodeKey, increments only existing records along SNAPSHOT_PARENT, and never creates a memo, builds output, notifies, or advances a runtime token. Walk past nodes without memos; do not stop merely because a record is already dirty (a nested read may have cleaned an ancestor). Keep weak ancestry; do not add reverse consumer lists, a neutral DependencyNode graph, a root scan or a root revision.
2. Keep existing branch-to-parent binding. Add its symbol equivalent. Extend that SAME parent map to terminal-to-owning-store bindings only when a snapshot walks the terminal. Add these in both key loops. A cached parent necessarily walked the included source; an unobserved parent has no stale output. A fresh child absent from an old parent image is covered by marking the installer-known parent, independently of a child edge. Held-child membership/liveness needs marking the affected child/retained descendant branches too, using the existing membership traversal, not only its parent.
3. Mark after successful physical installation and settlement evidence, before the first callback, capture, observer or completion that may read. Separate this from publishMembershipChange. That existing function remains the notification path, not the sole freshness boundary. Cancellation/preparation/no-op must not mark. A physical value change counts even when ordinary-authority participation differs; an authority-only change without changed read output does not.
4. ST materialization always touches the retained `observe` dependency, but returns the MATERIALIZED current output. If installed generation differs, build from installed source values and cache once. Read freshness applies to already-held functions; it is not selected by acquisition time or tap depth. Unchanged reads reuse identity; unrelated sibling records remain untouched. Freeze newly produced outputs as today.
5. Installed terminal reads need a private source-owned reader registration, keyed by the actual leaf object, with no new public/adapter export. The canonical builder first performs the normal reactive read for dependency tracking, then takes the installed read for the payload. Native scalar registration reads its current attached slot plus absence, not the Angular signal mirror. Reuse existing source read closures where possible; do not parse paths or use PositionRegistry parent ids as a node lookup. Only marked tree terminals use this route; opaque callable values/custom markers keep their contract.
6. Notification and current output must remain distinct. The retained observe computation must still establish dependencies on the new shape at delivery. A simple `if clean return cached` inside it is UNSOUND: it can drop dependencies when Angular/neutral recomputes. Proposed bounded solution: canonical builder has an internal dependency-touch mode that walks current own members, touches membership, child observe and terminal dependencies, but allocates no snapshot output and returns the cached current output. Use this only when observe runs after a direct read already built that installed generation. When dirty, normal tracked build produces the one output. No stored dependency list or second graph. This does cost a dependency walk at delivery; it is not zero traversal and needs measurement. Child tracking must use its retained observe explicitly, not rely on an out-of-computed prior build. Preserve observe's previous delivered value until recomputation so neutral settle can compare old versus new and notify ordinarily.
7. EntityMap needs its own collection identity and installed projection cache, not the native shared epoch identity. `snapshot(node)=>({all:node.all()})` can otherwise rebuild a fresh wrapper around a stale array. Supply a private built-in snapshot recipe that depends on the existing collection version but reads a collection-local installed-generation-cached `computeAll`. Share that current cache with the stable held ST `all` reader if the approved contract includes it; no tap-selected function swap. Advance only after installed collection value/order/membership changes, before completion. Marker dirtying follows existing marker→parent edges. Keep native app computed delivery unchanged. Custom marker policy remains unchanged.

Example: warmed root/rows; install `a`; mark rows and root before completion. Held rows reader touches old observe but builds `{a}` from installed state; root reuses this rows output and its unchanged sibling. Nested assignment based on `{a}` installs `b`, marks again, and yields `{a,b}`. Later notification makes retained observe revisit dependencies and return that same current object. A warmed external Angular computed remains old until the normal token delivery.

## Review limits and decisions needed

This is a proposed mechanism, not a claim all hooks are already present. HOOKS.md distinguishes existing code from additions. In particular native stored leaves are actual Angular signals; a dirty bit alone cannot make their pre-delivery values current. Likewise existing EntityMap projection caching is notification-version based. Neither is solved by ancestry alone.

Main should review the dependency-touch mode and the proposed private installed reader/collection seams before authorizing code. The mode avoids a second output allocation, but still revisits demanded members at delivery; do not advertise one traversal per write. Arbitrary custom marker/sort callbacks can reenter during building: a generation changing during a build must never be recorded as clean at the new generation. Exact retry/error behavior is not established here and cannot silently change existing semantics.

EntityMap direct held projection coverage is a scope question within the approved ST-reader contract: do not claim broad acquisition-independent freshness while fixing only branch wrappers. Inventory the collection's common physical install paths before implementation; public query/projection behavior beyond the approved contract is not authorized by this packet.

Ask whether the required observable distinction and source boundaries are supported, including native leaf and EntityMap counterexamples. Independent interpretation review subsequently checks whether bounded results justify the claims. No runtime work starts on reviewer agreement alone without the requested authorization.
