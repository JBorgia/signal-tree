## Necessary corrections

1. **Name a native currentness mechanism; the assumed graph is absent.** `adapter.ts:88–105` routes the native factory trio to createNativeLocationRuntime. In `native-location-realization.ts`, createDerived directly calls observation.createReadonlyCell; createCell returns a native carrier; native epochs use native handles/token publication. These do not construct the DependencyNode/DependencyEdge graph in location-runtime.ts. Native scalar leaves also bypass that graph and may use realized.commit directly. Consequently adding a snapshot constructor and installed-change stage only to the neutral implementation cannot make the actual Angular discriminator pass or dirty its cached native child snapshots. The native file was absent from the design's SOURCE-READS inventory.

   Required design addition: enumerate native snapshot dependencies/currentness sources and the exact private bridge that makes their installed revisions visible without publishing framework tokens early. Cover membership cell, scalar leaf/direct-commit and prepared-frame routes, native epoch/entity queries, and adopted live-slot binding. Explain how the same memo retains identity and receives current child values. Merely forwarding createSnapshot to native createReadonlyCell is insufficient; always rebuilding or replacing the native memo is excluded. This does NOT establish impossibility or require a new SDK by itself; the mechanism is currently unspecified.

2. **Specify delivery propagation THROUGH an already-read snapshot.** Concrete neutral graph: writable S → snapshot P → ordinary createDerived D, with D warmed/subscribed. Installed-change marking dirties only P (per design), early P() recomputes and clears dirty, then source delivery excludes P from repeated invalidation. Existing P.publisher.notify only calls notifyObservers; it does not notifyDependents(P.node). D therefore has no described invalidation route. Its readCurrent begins with the clean-cache fast return. Token/listener delivery on P alone is not notification of D's internal dependency edge.

   Required rule: at the established delivery boundary, changed snapshot publication must reach nonsnapshot downstream consumers even if an early read already refreshed P. Preserve the distinct saved observable baseline, and specify version accounting without duplicate source advancement or rebuilding merely to recover a lost dirty flag. Test direct snapshot subscription AND ordinary derived chained through snapshot(s), including early read, A→B→A, two writes, reentry and throwing subscriber. These are different from Angular computed token timing.

3. **Make pending-baseline lifetime and demand scheduling explicit.** Existing neutral invalidate queues only a listener/native-token demand, while flushConsumers removes a consumer before settle and catches its exception. A new baseline retained on a warmed but unobserved snapshot cannot simply wait forever for a settle that was never queued. Conversely queueing every marked snapshot to settle/readCurrent violates discriminator7's no readless output build. On builder throw, existing settle has no finally releasing your new baseline; “release on error cleanup” needs an exact ownership path, preserving dirty/error recovery and any reentrant interval's baseline.

   Required rule: identify who drains/discards an unobserved pending baseline without materialization, who owns it if the consumer is not queued, and how a failed settle/reentrant write retires the old interval without clearing the new one. Use existing per-source/per-consumer ownership where possible; do not introduce a permanent global pending graph. Add a warmed-unsubscribed/no-read control, subscribed→unsubscribe during group, builder throw then successful retry, and nested write during recovery. Account for demanded downstream D, even if P itself has no listeners/token.

## Obligations already correctly stated

- Keep one memo and lazy construction; unchanged/repeated reads preserve reference/build counts. No global ancestry walk or reliance on marker-only SNAPSHOT_PARENT.
- Snapshot marking must be callback-free and happen after complete installation and before callback-capable completion; never in preparation or between sibling stores. Refused outer preparation must not advance its currentness; successful nested work still must.
- Capture the first observable baseline once per interval, consume the old interval before notification, and preserve reentrant later work. A fresh direct read must not cancel pending delivery.
- R3 still owns participation/seal/validate/complete ordering. This repair cannot resample proofs, replace ordinary payload authority with physical snapshots, or compensate for a missing participant.
- Existing current-read approval covers direct ST reads, not early invalidation of warmed native application computed. Verify real Angular and the neutral derived-chain separately; retain Vue error/native-cache controls when the implementation touches shared current-read realization.

The discriminator list is otherwise a useful bounded start. Keep the original typed diagnostic unchanged as evidence generation, with separate assertions for the fixed behavior. Add the three missing mechanism obligations above before proceeding; no additional broad inventory or full-suite run is needed to resolve this premise review.
