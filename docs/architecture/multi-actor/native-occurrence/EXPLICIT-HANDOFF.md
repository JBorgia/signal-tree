# Explicit private handoff successor

On October 29, 2026, the owner instructed “do it” after the recommendation to
replace ambient rollback evidence with an explicit private write handoff, then
complete prepared semantic operations and publication records with obligation-based
cleanup. This authorizes implementation within the existing product plan. It does
not authorize public API changes, activation, release, budget changes or reopening B.

The preserved [getter-reentry failure](invocation-successor/reentry-review/RESULT.md)
is the first discriminator. The intended mechanism passes the selected endpoint
directly into the exact kernel operation; it must not make that endpoint available
to another write via shared invocation context. Existing framework observation,
interceptors, callback ordering, ordinary/inspection distinctions and lifetime
rules remain binding. Missing evidence is not clean evidence.

Source/seam review precedes the new native experiment. The rejected invocation
candidate stays frozen. Passing this correction alone would not close structural
normalization, recipient selection, retention or full release qualification.

The [first explicit continuation](explicit-handoff/RESULTS.md) passes the unchanged
getter-reentry fixture, but [independent review](explicit-handoff/independent-review/REVIEW.md)
finds three retained/repeated-continuation failures. Main reproduced all three.
The source remains frozen. This is not a rejected product direction; the new
continuation still lacks operation-scoped consumption, closure and installation
evidence.

[Lifecycle review](continuation-lifecycle-review/REVIEW.md) distinguishes consumed,
installed and closed. The [installation review](continuation-lifecycle-review/INSTALLATION-REVIEW.md)
accepts single-effect mark locations but requires a real two-unit partial-failure
discriminator before changing whole-transaction terminality. No partial-settlement
policy or whole-operation atomicity is inferred from one field's receipt.

The [two-unit diagnostic](partial-install-diagnostic/RESULTS.md) reproduces
partial installation followed by terminal rejection on the unchanged experimental
predecessor. This is a correctness failure, not a selected partial-settlement
policy. The [public comparison](public-partial-install/RESULTS.md) reproduces the same
safety defect on exact retained v16 `87f6831f`: after one inverse installs and
a public interceptor blocks the next, retry does nothing and confirmation reports
a rolled-back transaction. Effect order differs, so both forward-order permutations
were tested. Each source has two passing and two failing cases. No claim about a
published v15 artifact follows.

The next [prepared-unit boundary](public-partial-install/PREPARED-UNIT-BOUNDARY.md)
moves user-capable preparation ahead of selected installation, preserving public
interceptors and real batching. The public comparison records followup results;
the candidate acceptance tests must also assert useful retry and confirmation.
[Independent design review](public-partial-install/DESIGN-REVIEW.md) supports the
direction and requires ordered transformed-sibling support, same-row composition
and callback-free mixed installation. Runtime implementation is in progress. Neither
whole-operation atomicity nor production acceptance is established.

A separate [installation-purity review](public-partial-install/INSTALL-PURITY-REVIEW.md)
finds late preparation and completion in membership/structural wrappers. The
point value-store and prepared scalar primitives are narrower. These are source
findings, not new executed public failures, and prevent extending a point-only
result to all mixed membership routes.

The separate [paired-preparation successor](paired-preparation/STATUS.md) passes
bounded independent review, Main's139-check replay and eight real facade checks.
Complete-suite differential now rejects integration: four hidden-collection rollback assertions regress. Closed-continuation cleanup passes its separate bounded review. See the [final disposition](FINAL-DISPOSITION.md). Production remains unchanged; P3 is incomplete.

The owner subsequently directed continued correction. The [continuation record](continuation/README.md) preserves that rejected baseline and records bounded retained-source, enrollment and approved SDK results. Its remaining gates are not waived by those corrections.
