# Callable location performance

> **Historical checkpoint:** this comparison isolates commits `84837fb3` and
> `81780c4e`; it does not compare against the earlier declarative-construction
> branch and it does not establish the final framework carrier. Angular and Vue
> now expose native leaves. See
> [Framework-native leaf performance](framework-native-leaves.md) for the
> architecture-selection benchmark.

The v15 callable-location migration replaces canonical leaf methods:

```typescript
location.set(value);
location.update((current) => next);
```

with one location grammar:

```typescript
location();
location(value);
location((current) => next);
```

The comparison is generated by `tools/bench-callable-locations.mjs`. It runs
independently installed production tarballs built from commits `84837fb3` and
`81780c4e`. Their kernel tarball SHA-256 values are
`a5c6505e0c82f58cff091fb74e589d34bf3965d885d2fd378537a03eed3db287` and
`f5ade269f1a661083506b663e655c27d7deb58bd99de5a4df9b6c439dbf60c95`;
the raw JSON records both commits and full digests. Call order alternates per
operation and round, and artifact-to-worker assignment is mirrored: each
artifact occupies each worker slot for half the samples. Each paired point is
the median of five trials. The recorded run used 30 measured pairs after five
warmups per worker assignment, with two million reads, one million replacement
or derivation writes, and 500 representative tree constructions per trial. GC
runs before construction trials and outside the timer.

An identical-current A/A run uses the same protocol. Its purpose is to expose
measurement noise before interpreting a before/after difference. Every arm checks
that its work landed and destroys its trees.

## Result

<!-- measured: node --expose-gc tools/bench-callable-locations.mjs; raw samples in apps/demo/public/benchmarks/callable-locations.json and callable-locations-aa.json -->

Node v24.3.0 on macOS arm64:

| Operation          | `84837fb3` methods | Callable locations | Paired median delta | Paired p10-p90 | Reading                       |
| ------------------ | -----------------: | -----------------: | ------------------: | -------------: | ----------------------------- |
| Scalar read        |           10.75 ns |           10.72 ns |               -0.7% | -1.7% to +1.8% | No clear difference           |
| Scalar replacement |           58.62 ns |           62.77 ns |               +6.6% | +3.4% to +9.9% | Measured overhead in this run |
| Scalar derivation  |           67.78 ns |           67.04 ns |               -1.0% | -5.4% to +1.9% | No clear difference           |
| Tree construction  |           11.58 us |           11.47 us |               -1.2% | -7.7% to +5.1% | No clear difference           |

The one supported comparison claim is scalar replacement: the `81780c4e` build
measured about 4.1 ns slower in this run. The experiment did not isolate the
dispatcher from every change between the two commits, so that delta must not be
attributed to the dispatcher alone. Its two mirrored worker-assignment medians
agree at +8.3% and +5.5%. Read, derivation, and construction intervals cross
zero, so their median signs are not treated as improvements or regressions.

The A/A control's paired medians were -0.1%, -1.8%, -2.3%, and -2.0% for read,
replacement, derivation, and construction. In particular, replacement's control
interval was -4.3% to +0.1%, while the comparison interval was +3.4% to +9.9%.
The identical-code derivation control itself leaned negative, which is why the
comparison's small negative median is not presented as an improvement. Treat all
exact percentages as machine-local rather than a universal tax. Raw paired
samples and worker assignments ship with the demo:

- `apps/demo/public/benchmarks/callable-locations.json`
- `apps/demo/public/benchmarks/callable-locations-aa.json`

## Complexity

The timing delta does not represent more state work. The production scalar
complexity guard remains unchanged: a replacement performs one slot read, one
equality check, one slot write, one revision increment, and one publication,
independent of total tree size. The extra cost is constant public-call dispatch,
not a new traversal or dependency operation.

Run that deterministic control with:

```bash
pnpm nx test kernel --skip-nx-cache --output-style=static \
  --testFile=src/lib/production-scalar-substrate.benchmark.spec.ts \
  --testNamePattern='proves compiled scalar reads and writes stay constant in logical work'
```
