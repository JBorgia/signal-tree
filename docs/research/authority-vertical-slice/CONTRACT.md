# Comparative authority vertical slice, v0

No production changes. Exact incumbent8d220643; rejected persistent implementation9b9b0b35 is evidence, not an arm. Neutral native reactive store for A/B; real incumbent kernel as control. A/B are not claimed framework integrations. Same literal expected traces/assertions, no expectation derived from a candidate. Local authored order only; no network authority policy invented.

Locations: named scalar/branch-member cells with explicit `{present:boolean,value:unknown}`. Absence is distinct from present undefined. Entity key/lifetime presence and finite record values; stable non-reused ref objects. Same key replacement cannot retarget a held reference. Simple flat payloads only. No nested collections, ordering/rekey, async transaction callbacks or production adoption claim in this slice.

Interface exported factory `createStore()`:
- `write(key,value)`, `remove(key)`, `read(key)` => `{present,value}` (absent omits value); keys may be `branch.member` but presence is explicit at that semantic leaf (no implicit parent creation). `snapshot()` => `{cells: Record<string,unknown>, entities:Array<{key:string,id:number,value:Record<string,unknown>}>}`; absent cells omitted, present undefined own property retained. Snapshot output enumeration is allowed and counted separately.
- `begin(fn)` invokes synchronous fn immediately, returns handle `{accept(),reject(),state()}`. Writes within fn attributed to owner, immediate reads valid. Empty handle still settles. Nested begin uses separate owner, outer attribution restored afterward. If fn throws, attempt rejection; preserve original error identity. If rejection fails, attach usable `recovery` handle on extensible Error using explicit prototype-only reporting (control reports its existing mechanism). Do not replace original thrown value. No public API proposal.
- `undoable(fn)` commits ordinary local writes and saves a one-step undo command; `undo()` realizes prior facts as NEW authoritative local truth through the same installation path. Undo with a pending dependency may explicitly refuse per existing control policy; unchanged original restoration sequence (no owner during undo) must succeed. No redo required.
- `add(key,record)` returns reference `{id,read(),write(record)}`. `removeEntity(key)`, `get(key)` => ref|undefined. Duplicate live key errors. Retired ref reads undefined; write throws. Rollback removal may restore same lifetime; replacing key creates fresh lifetime. Live dependent truth may require refusal, but defined overlap cases must settle successfully.
- `observe(fn)` returns unsubscribe; observer sees coherent snapshot of installed state, state() terminality complete before delivery. Native delivery may be scheduled; `flush()` drains. Reentrant writes must survive, and observer throw must not undo installed/terminal state. Define and report error delivery via `takeErrors()`; A/B synchronous vs control framework scheduling not equated silently.
- `failNextPreparation(error)` one-shot supported failure before next non-noop write OR settlement installation; must throw identical value, change no visible state/authority and permit retry. Control reports unsupported if exact corresponding fault boundary cannot be injected without modifying behavior; unsupported is not a pass and prevents equivalent-cost claim for whole contract.
- `stats()` / `resetStats()` expose truthful operation and allocation counts (named model objects/index nodes, not V8 heap bytes). Must count prepared cell/record copies, visited locations, native writes and publications; keep full snapshot enumeration separate. A must count current-state duplication; B counts live-obligation base facts. `destroy()` invalidates handles/refs and releases maps/observers/history; stats debug may report sizes but no snapshots in measured point operations.

All installation units stage fallible work and validate base revision after reentrant preparation, commit native/ownership/terminality with no callbacks, then queue publication. Reentry occurs during delivery, never midway through a unit. Rejected settlement leaves all contributions disposed or remains pending unchanged. Do not use value-equality as write identity.

Arm A: authoritative sparse canonical/pending state; native values are a projection with no public independently writable route. All writes, undo and settlement route through authoritative preparation. No required AVL implementation; disclose concrete representation/allocation work.
Arm B: native semantic state authoritative; only live pending obligations retain hidden canonical facts/contributions. Base facts may live while hidden by obligations, but no full-store committed mirror or unconditional before-value restoration. Ordinary writes with zero live obligations must not create retained ownership cells. Last-owner retirement resolves correct native truth before releasing records. Use indexed dependency lookups.

Both must support repeated overlapping scalar writes, newer ordinary committed writes, out-of-order acceptance, member absence/undefined, entity lifetime preservation, observer writes/ABA/nested settlement, failure retry, useful controls. Measure common passing scenarios first with operation counts; only compare CPU/heap on explicit equal-capability subsets and disclose failed/unsupported obligations. Preserve first reds before corrections.

## Clarifications established during the comparison

- Branch payloads are finite flat records at one atomic location; `{}`, `{member:undefined}`, and absent branch remain distinct. Nested terminal-level ownership is outside this slice. Exploratory nested-alias probes are preserved but not used to define the common flat-record scope.
- Exact incumbent evidence establishes scalar removal of already-visible absence as a no-op, and missing entity removal as an error. Neither repeated call silently authors a new absence contribution. Both arms align with these policies after preserving their first divergence.
- Prototype defensive output copying and rejection of entity-update getter reentry are stronger than two observed incumbent behaviors. They are fixture requirements shared by A/B, not accepted public compatibility changes or incumbent bug findings. Current public control can admit the update after preserving its getter's independent write.
- `failNextPreparation(error,{afterPrepared:1})` is a fixture-only staged fault after one location is prepared and before installation; it is not an adapter SDK proposal. Exact incumbent unified fault injection is unsupported by this adapter, never counted as a pass.
- Common counters `installedUnits`, `nativeWrites`, `observerDeliveries` have matched units. Other counters retain each arm's definitions. Logical clones/index-entry copies are not V8 allocation totals.
- The reporting shortcut `.recovery` on callback Errors fails for a nonconfigurable occupied property in both arms. The original-error identity falsifier is permanent case41. This boundary is NOT accepted or excluded from the final verdict; neither arm is a fully accepted slice implementation. No additional application recovery API is invented to erase that result.
