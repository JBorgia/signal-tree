# Arm A: authoritative mutable sparse location index

This is the bounded model, not a production kernel or framework integration. Exports `createStore` from `arm-a.mjs`. Direct checks: `node arm-a-selfcheck.mjs`; first log `arm-a-first.log` passed. Common unchanged tests owned by root are authoritative evidence.

## Authority and surviving values

`truth` owns every installed location. Each contains an authored canonical fact and an owner-indexed map of pending facts. A monotonic operation ordinal selects the newest surviving fact; acceptance promotes its authored fact only if newer than canonical, rejection deletes its contribution. Thus accepting an older writer while a newer writer remains pending preserves the correct hidden value for later rejection. Newer ordinary writes mask older pending contributions without losing authored order. No equality guard decides ownership.

`native` is a private reactive projection. No capability writes it independently. Reads use this projection; scalar writes, explicit leaf/branch writes, entity membership/value writes, undo realization, acceptance and rejection all prepare through authority before installing the projection. `native` duplicates current visible state and is reported explicitly. This deliberately does not claim elimination of duplicate current-state storage.

Locations are semantic atomic cells. A branch cell may hold `{}`, `{member:undefined}`, or be absent. A dot in a key has no hierarchical meaning. Nested production branch-terminal granularity, structural parent dependencies, collection order/rekey, and Links are outside this contract. Entity record payloads are atomic as well.

## Installation / publication / reentry

Affected location records are staged by cloning only their pending maps. Record and projection clones precede revision validation. Commit installs all staged authority and projections, then owner terminality, then queues delivery; no observer runs within this installation loop. Preparation detects changed revision (including reentry through a payload getter during cloning). Controlled preparation fault is one-shot, identity preserving, before stage/installation. A failed settlement retains pending authority and permits identical retry.

Observers are delivered in a coalesced microtask after synchronous units complete. Observer callback writes produce a later queued delivery, including ABA writes. `flush()` drains delivery to quiescence (1000 rounds is a runaway-observer guard). Observers read current coherent installed state; this does not promise every intermediate state has a separate notification. Exceptions are queued to `takeErrors()`, never roll back already installed/terminal work. Unsubscription during delivery prevents later callbacks. Callback `begin` failure attempts full rejection, preserving thrown identity; extensible Error gets `recovery` and `recoveryError` only if cleanup itself fails.

## Lifetime / reclamation

Entity values carry non-reused numeric IDs. References carry only key/ID and lookup current projection; they cannot retarget a later ID. Rollback removal restores the same ID if its fact wins. A canonical replacement/newer ordinary write takes precedence over older removals. No retired-reference registry or tombstone map exists. Absence-only locations with no pending obligations are deleted. Terminal owners clear their touched sets and leave the owner index; retained handles hold no state facts. Undo command intentionally retains prior facts until undo, replacement by another undoable command, or destroy. Destroy clears both maps, owners, history and observers and invalidates handles/references.

## Costs / counter interpretation

No AVL or persistent whole-store root. Mutable top-level Maps are indexed by location; each write or settlement stages the affected location's pending Map, so work is O(touched locations + pending contributions at those locations), not O(all locations). This is not constant time with unbounded overlapping owners. Snapshot enumeration and `stats()` debug inventory are not point-operation work; the measurement harness must keep them outside the measured loop when claiming indexed work.

Counters are logical named model allocations/work, not V8 allocator or byte counts. `visitedLocations` counts affected-location preparation visits. `indexNodes` counts newly populated pending-Map entries (cloned entries plus newly added owners), not internal engine hash buckets. `preparedCellCopies` counts staged fact/projection state objects; `preparedRecordCopies` counts objects in structured-cloned payloads. `namedModelObjects` includes those copies, location records/Maps, contribution records, initial canonical facts, owner/set/handle records and returned references; it deliberately excludes transient JS iteration/array scaffolding and engine-internal allocations. `readReturnedCopies` separately counts copied return-state/payload objects, so read cloning is not labeled preparation. `currentStateCopies` counts prepared projections. `resolutionVisits` counts visited pending facts. `nativeWrites` counts projected location installations even if values compare equal. `publications` counts observer invocations, not queued batches. `snapshotEnumerations` counts exported locations. Retention sizes report canonical/native locations, pending owners/contributions and undo facts. A field-only entity operation clones its atomic entity payload; no production per-field granularity claim.

Ordinary and same-value writes still create authored intent and can consume the preparation fault; this is necessary to retain ABA write identity. An empty pending handle settles and retires its owner. Undo while any owner is pending explicitly refuses, matching the permitted slice constraint; no cost claim covers a supported pending-undo feature.

## Independent-review correction, same experiment

First source is preserved as `arm-a-first.mjs`. Review found entity add/reference.write cloned user payload before capturing preparation revision, so a payload getter could install an inner write while the outer entity operation incorrectly succeeded. Exact incumbent control rejected the outer operation and preserved the inner write. Correction passes the raw payload into `writeState` and performs its first reflection in staged `copy`, after revision capture; the existing revision validation rejects outer installation without undoing newer inner work. Four focused checks in `arm-a-review-correction.log` verify getter reentry through add and held-reference write, absent scalar removal policy and absent entity removal policy. No equality-based guard was added.

Exact incumbent probes also established repeated scalar removal of a visibly absent location is a semantic no-op (including within another pending callback); it authors no hidden absence contribution and does not consume a preparation fault. Repeated entity removal throws. Arm A now preserves these policies; initial differing behavior was not treated as a new product contract. Same-value writes remain authored operations. Six original direct controls still pass after these corrections. Root owns expanded unchanged assertions and independent review evidence.

## Staged fault boundary and normalized publication counters

The pre-staged-fault implementation is preserved as `arm-a-pre-staged.mjs`. The fixture-only overload `failNextPreparation(error, {afterPrepared:1})` now throws the identical error after preparing the first affected location but before installing any location. The default still throws at entry. This hook applies to ordinary write, settlement and undo staging. The mixed scalar/entity rejection probe records unchanged visible state, pending authority, zero native writes/installed units after the injected failure, followed by a successful retry restoring both locations (`arm-a-staged-fault.log`). The probe establishes a fault between location preparations; it does not inject failures into JavaScript Map mutations during the callback-free installation loop.

`installedUnits` increments once per successfully committed installation unit, even without observers. `observerDeliveries` increments per actual observer callback invocation. Existing raw counters remain unchanged for historical comparison; `publications` remains the older callback-invocation counter and equals `observerDeliveries`.
