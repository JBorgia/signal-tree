# Arm B — native current truth with live-obligation records

Native `cells` and `entities` Maps are the only committed/current store. Ordinary writes without pending obligations allocate no retained ownership location. A pending first touch allocates an obligation containing the currently visible base fact and per-owner latest authored fact. Hidden base facts remain only while pending contributions exist. This is not unconditional before-value compensation: rejection selects the maximum authored sequence among the surviving base and contributions. A newer ordinary write updates the base; an accepted contribution promotes to base only if newer. An older acceptance cannot displace newer accepted truth. Repeated equal-valued writes receive distinct sequences (ABA is authorship, not equality).

All public writers prepare facts, validate a captured revision, install native values and responsibility, and only then queue delivery. Native installation has no application callbacks. Restoration refuses any live owner (matching the slice's permitted policy); otherwise it prepares the complete saved undo unit and installs it as new native truth. No ownership records exist during this installation. First pending touch afterward reads that restored native truth. Undo history is a separate explicitly counted user-requested restoration obligation, not a second settlement engine.

Entity locations are atomic key/lifetime/flat-record facts. References close over a key plus monotonically allocated lifetime ID. They consult current native membership, cannot mutate another lifetime, and need no retained reference registry. Removing and rejecting the same lifetime restores it; replacing the key preserves the newer lifetime. Hidden lifetime facts remain only with pending or undo obligations. No ordered collection semantics or nested member fields are claimed.

Delivery uses queued microtasks, one queued observer batch per successful installation. `flush()` also drains synchronously. Multiple already-installed changes may be coalesced observationally because callbacks read current native state, not historical snapshots. Reentry occurs after complete installation and terminality; nested writes append later deliveries. Observer exceptions are collected by `takeErrors()` and do not roll back installed state. Callback exceptions preserve identity; failed cleanup exposes the still-pending handle as Error.recovery when the thrown Error is extensible. The cleanup failure is also recorded by takeErrors(). These are prototype-only semantics, not an SDK proposal.

Counts are named modeled work/allocation events, not total JS or V8 allocations: fact objects, prepared cell slots, entity record copies, ledger Map copies and entries copied, owner/reference/delivery objects. `visitedLocations` includes affected locations and contributions examined, not untouched native locations. Snapshot enumeration has its own count. `stats()` enumerates live obligations to report retained entries; this debug call is outside point-operation work. Transient JS arrays, ordinary object wrappers returned by read, closures and runtime-internal Map storage are not an exhaustive allocation census. CPU and GC heap measurements must account for these separately. Native collection enumeration occurs only in explicit snapshot output; ledger work scales with obligations at affected locations. The hidden-base ledger is reclaimed after the last contribution, regardless of whether a held reference exists.

Limitations: flat entity records and atomic branch cells; no hierarchical implicit branch creation, sorting/rekey, framework integration, async callbacks, redo, or deep immutable value semantics. Resource exhaustion during JavaScript Map.set cannot be usefully recovered by this experimental fault model. Supported injected failures occur before preparation/installation and preserve authority unchanged. Getter-driven preparation reentry is detected by revision validation, preserving the inner committed write while refusing the outer unit.

## Independent-review correction

`arm-b-first.mjs` preserves the initial implementation. Review found that branch payload aliases could change native truth outside installation and that absent entity removal should throw under the incumbent policy. The corrected version structured-clones object payloads on ingestion and all public value-returning reads, including entity reference reads and snapshots. Preparation captures revision before cloning/getter reflection and validates afterward; reentrant inner installation survives while the stale outer preparation refuses. Scalar absent removal remains an intentional no-op matching control. Entity absent removal now throws before installation.

The new `payloadCopies` and `payloadObjectCopies` counters cover clone calls and traversed cloned object nodes for the finite-record payload model. They include consumer reads/snapshot clones as well as preparation; primitive scalar values require no clone. This adds real copy obligations and must be included in fresh cost measurements. The earlier notes' disclaimer about deep immutable value semantics is superseded for supported structured-cloneable finite record payloads: callers receive detached copies. No full-store canonical mirror was introduced.

## Staged-preparation fault coverage and common units

`arm-b-pre-staged.mjs` preserves the copy-isolated source before this instrumentation. Fixture-only `failNextPreparation(error, {afterPrepared: 1})` now throws after the first affected location's staged facts/index copy/resolution and before any native write, ownership commit or terminality change. Mixed settlement can therefore demonstrate partial preparation followed by atomic refusal and retry. Omitted options retain entry-only failure. This is a deterministic model-stage injection, not exhaustive allocation-failure coverage or a proposed production API.

`installedUnits` counts successful public installation units (including settlement with no visible value change and empty settlement); `observerDeliveries` counts actual callback invocations, including callbacks that throw. Existing publications counts installed publication requests, not callbacks. Neither getter/revision refusal nor injected preparation failure increments installedUnits. Staging-only counters legitimately increase on failed preparations.
