## What the two designs must make concrete

**A. Sparse root owns current truth, native state is projection.** All semantic value/presence/lifetime/key/rank/selection decisions must be encoded before root commit, including declarative restoration, raw frames, omission/reacquisition and inspection policy. Native slot/store setters become projection-only installation endpoints with source revision validation; a restoration target cannot independently define committed truth then notify the root later. Preserve non-reused lifetime identity and revival of the same retained lifetime. Index/root replacement, native installation, pending terminality, publication and reclamation need one explicit failure/reentry protocol. Cost obligation: benchmark ordinary writes, initial seeding, collection fields/nested terminals and restoration, not only point settlement. A root plus a projection is not automatically two authorities if projection cannot decide independently, but the current implementation has not enforced that relation.

**B. Native state owns current truth, sparse records pending contributions only.** Remove the persistent duplicate committed-value root as an authority. Pending records must distinguish authored contribution, superseding committed writes, absent members, lifetime replacement and dependencies. Each native installation family above must stage both native next state and pending-record disposition/rebase before mutation, even when no ordinary authored hook runs. A raw frame cannot bypass this just because it publishes realized notifications later. Restoration and Link committed truth must atomically supersede or reconcile pending records under established refusal/provenance rules. Cost obligation: prove dependency-index work proportional to touched active obligations, zero-pending cost and no cumulative history retention. This is not simply sourcing current before-values at rollback: historic contribution dependencies and newer writes require retained evidence.

Neither design can be accepted from naming its authority. The discriminating obligations are (1) restoration undo before a later transaction, (2) restoration with live pending overlap, (3) same-lifetime revival vs same-key new lifetime, (4) branch absence with retained slot value, (5) inspection visible-state/provenance behavior, and (6) callback writes/throws between installation, terminality and publication. Keep unchanged assertions and useful overlap settlement. No winner selected here.
