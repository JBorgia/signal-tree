## Publication payload ownership

Use actual plan publications: populated state, eight started/held plans, eight
acknowledged plans, dismissal, then sixteen total completed/dismissed plans.
At each stage assert complete public and transport payload equality, state,
count and attempt identity in the browser without returning entire datasets to
the harness. Later accepted edits must not rewrite earlier publication data.
The deterministic backend retains its own history; heap includes that common
storage. Track weak references to public payload objects without strongly
retaining them in the harness.

End with an unresolved command and dependent intent, destroy the store/UI while
retaining only the test backend, then deliver the old reply and release that
backend. Check no late publication or UI resurrection. Record heap and weak
liveness before/after those boundaries. A surviving object is an attribution
lead, not automatically a leak: save a final heap snapshot for a case with
surviving sampled objects so retaining paths can be inspected.

## Interpretation

Assertions certify only the specified traces. Forced-GC used bytes, observed
weak liveness and actual retaining paths are different evidence. Growth can
include warmed code, framework/query caches, reserved IDs and service history.
Finite low growth does not prove unlimited boundedness. A temporary payload map
has no measured memory benefit until its populated lifetime is actually tested.
Keep unfavorable and inconclusive results; narrow the application recommendation
or repair a concrete ownership failure before recommending the affected use.
