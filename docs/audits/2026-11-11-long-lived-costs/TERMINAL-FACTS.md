# Retired publication facts: representation experiment

Registered after the `a35ed7534` residual census and before runtime edits.
This is internal representation work; rejected destination/input/validation
facts, uncertainty, fixed historical windows and late-reader behavior are frozen.

## Concrete problem and rejected shortcut

Thirty 1,000-row population/rollback cycles leave no counted physical lifetime
or value backing, yet five native source maps each contain 30,000 retired IDs.
An active recipient adds two 30,000-address maps. The current negative members
carry actual rolled-back destination ownership. The existing source retirement
classifier deliberately refuses deletion. Empty claim registries do not grant
permission to erase those facts: a later native consumer must retain the same
contradiction behavior. The earlier mapping-only deletion hypothesis cannot
resolve this case because the current negative member itself is non-neutral.

The exact-bundle identity witness checks three cycles of twenty rows. All twenty
retired subjects within each cycle share the same five requirement references:
ordinary member, physical member, physical placement, ordinary key mapping and
physical key mapping. Across cycles the references differ. That supports packing
identical storage without normalizing owner identity or proof meaning.

## Candidate design for independent challenge

1. Use the existing installed-forget authority, physical/ordinary absence check,
   source readiness and exact currentness guard. Leave true eligible deletion
   unchanged. For a permanently absent subject whose facts cannot be deleted,
   move the exact five facets into a private sorted interval index. Merge adjacent
   IDs only when all five requirement references are identical. Do not modify any
   issued requirement or view. Preserve regular-map plus packed lookup, whole
   native input capture and late-enrollment exclusions.
2. Preserve exact recipient addresses in packed storage, including `get`, `has`,
   `set`, `delete`, `deleteSubject`, `clear`, ordering, draft copying and emitted
   support edits. Only identical stored values may share a run. Queued units must
   continue to address their original keys and captured contributions. Ready
   callback/snapshot sharing is a separate possible implementation optimization;
   it requires exact reference identity and reentry/current-entry guards.
3. Initialize additional storage only when actual retired facts need it. Keep
   active point work on its existing path. Distinguish logical fact/subject counts
   from stored runs or aggregate entries in diagnostics; changing a counter's
   meaning is not a memory improvement.

No terminal-proof normalization is required by this candidate. The existing
test-only `compactTerminalProof` has a separate equivalence argument, but adopting
it would expand this change. Do not substitute equal current owner outcomes for
reference identity or normalize pending/abandoned/foreign proof ancestry.

## Falsifiers and cost decision

Freeze the exact bulk-add → rollback → drain → independent native consumer trace
before editing, with no recipient, active recipient, disposed recipient and late
enrollment. Compare callback values, contradiction, receipt reason/basis and
delivery, not only final data. Test captures made before settlement and afterward,
held rows/receipts, same-key replacement, rekey, inspection-hidden ordinary rows,
foreign/pending/abandoned/input/validation facts, and prepared-source currentness.
Keep the existing foreign-omission mutation control and fixed-window retirement
controls. The point-work witness must still assert its emitted numeric bound.

Repeat the identified source/recipient inventories and original aging workload.
Record exact artifact hashes, first failures and actual logical fact counts.
Then price population, full settlement drain, point work, heap, package bytes and
the ordinary no-Link path. Do not adopt a complex representation solely because
its best case allocates fewer objects.

The proposed bound is proportional to distinct exact tuples/runs, not constant
space. Adjacent homogeneous bulk operations can move from one entry per row to
one run per batch. A workload with a distinct tuple for every subject can still
grow per subject; retained contractual facts and unavoidable information must be
separated from avoidable wrapper/index overhead in the final decision.

## Review corrections and implementation authority

Independent review rejects the initially proposed permanent recipient aggregate.
Inbound acquisition can call `prepareSeed`, replacing relationship support and
emitting exact deletions for old negative addresses. The original reseed test
explicitly removes prior `1:m` support. Forgotten source lifetime therefore does
not mean permanent recipient contribution. Exact addressed packing is selected;
no permanent summary is authorized.

Source packing must include generic and point selected-support closures, not
only exposed evidence methods. Its first implementation is deliberately narrow:
all five facets present, negative ordinary/physical members, no fields/views or
ordinary placement, and no waiting `onSettlement` retirement plan. Preserve the
existing eventual own-window deletion. Optional/missing facets are not silently
encoded as unavailable requirements. Additional storage is lazy, and active
lookups must hit regular maps before any interval search.

The frozen pre-edit public trace passes four recipient configurations and 24
consumer cases. Exact behavior matters: independent declarations contradict after
the callback, while the installed target value can later deliver once through a
surviving fallback. Unknown declarations return started with surviving basis.
Contradiction is not permission to assert permanent silence. Held captures before
and after rollback, current reads, same-key replacement and rekey are preserved.
The baseline logs and emitted traces are separate from successor tests.

Root authorizes the source stage under these reviewed constraints, followed by
separately checked exact recipient packing. Final adoption still requires the
full comparative and contract checks above. Final architectural authority and
this record remain centralized.


## Source-stage result

Runtime `145e2a19cfe208c70f30ff64006fa6929fd092fb` implements the source stage.
Append/adjacent-merge admission avoids shifting an increasingly large interval
array. Out-of-order distinct tuples remain in the existing maps; there is no
arbitrary run limit that silently stops helping after a fixed number of cycles.
Repeated requests and invalid numeric addresses are guarded. The source shape
and waiting-own-window restrictions above remain intact.

[Independent source review](v16-source-packing-review.json) verifies the 24 exact
public traces against the pre-edit baseline, 44 focused test results, the
naive-retire control, types/build checks and the original 1,800-visit witness.
The reviewer performed source/hash/equality checks; these are not reviewer-run
framework or performance suites.

The [separate installed-artifact measurement](v16-source-packing-measurement.json)
passes eight residual samples, two planted controls and two census arms. At
30,000 retired lifetimes, both arms still represent all 30,000 logical subjects,
now in 30 stored runs with zero unpacked subject facets. Ten sampled requirement
summaries match the predecessor exactly. No source map remains above the census
threshold; the active recipient's two 30,000-entry maps remain.

Median current-ID whole-process heap above empty changes 13.0288 → 3.7555 MiB
without a recipient and 24.7536 → 15.4533 MiB with one. Across all four matched
cells the reduction is 9.267–9.363 MiB. These are separated descriptive cohorts,
not paired CPU measurements or universal bounds. The source stage preserves
per-batch facts; it does not erase historical rejection evidence.

## Recipient experiment scope

The next smaller prototype retains both exact keyed maps. It tries to reuse
identical immutable contribution snapshots and ready entries that have neither
a callback nor a subscription. A mutable-proof regression test disproves blind
caching by proof-object identity: the same object can later contain different
owner arrays or flags. Reuse therefore must validate every role's length and cell
identities (including duplicates), flags, rejected bits and readiness. Existing
slots retain their old snapshot after a later proof mutation. Unresolved entries
remain distinct and keep their callbacks/currentness guards.

This prototype can reduce repeated wrappers/arrays while retaining linear map
backings. Ordered run-map machinery is deferred until the measured remaining
cost justifies its implementation and maintenance burden. Canonical numeric
membership-address storage, if attempted, is a separate exact-map experiment
with deletion, reinsertion and reseed controls; no public flag is selected.


The first snapshot-sharing variant fails a new lifetime falsifier: after disposing
its only recipient, retaining and then emptying the same proof object still keeps
its old owner cell alive through the strong cache value. The deliberate-owner-pin
control also remains alive as expected. This failure rejects the strong-value
cache despite its passing functional cases. The repair must make cached snapshots
non-owning and avoid a new history-sized cache where a bounded reuse window can
obtain the benefit. Its package, source, generator and failing observation remain
separate evidence; no cache savings are accepted before this lifecycle check passes.

## Bounded weak-cache cost and lexical replacement

Commit `a4316e1229d4c54d3af8044c44dee2d56a8ec043` replaces the failed strong
cache with a bounded weak proof/entry pair. Its owner-release control passes,
and exact contribution, mutable-proof and reseed checks pass. The separate
30-child cost cohort nevertheless rejects uniform adoption: sharing helps the
homogeneous case, while alternating and unique misses consistently cost more.
Those misses allocate weak references and freeze snapshots even without reuse.
The source and first cost cohort remain preserved; functional correctness alone
does not justify this representation.

The successor limits sharing to the existing synchronous collection reduction
and seed loops. A local pair dies when that batch returns or throws; direct
replacement keeps its original allocation path. Every edit rechecks the handle,
including after user-controlled iteration. Nested batches use independent local
pairs, and freezing occurs only on first actual sharing. This avoids global
owner retention and extra cleanup scheduling. It adds no configuration flag and
does not change recipient addresses or permit dropping old contributions.

Its focused validation includes proof mutation within a single generator,
nested batches, iterator disposal and exact thrown values. Adoption requires
the registered 40-child comparison of shared, alternating, unique and direct
replacement work, followed by integrated history, lifecycle and point checks.

The lexical implementation is `895d5ae3b`; lint/type narrowing is corrected in
`5d04ff65d2eaab1986ed1b420cbc013edc01542b`. The latter captures five references
from an unexposed, unmodified local snapshot array. Independent review checks
that currentness and later requirement contents remain unchanged; the emitted
artifact differs and is bound separately. Removing the assertions alone failed
TypeScript, and that failed attempt remains recorded.

The first lexical cost cohort checked role counts more weakly than its protocol
claimed. It remains historical evidence. The
[corrected 40-child cohort](v16-lexical-batch-verified-cost.json) asserts actual
OwnerCell identity, per-address role multiplicity, flags, readiness and removal.
Both omitted-write and same-cardinality swapped-owner controls fail as intended.
All 40 normal children pass. This is an internal recipient-index comparison;
the old collection forwarding wrapper is outside its timer, so it is not a
whole-publication measurement.

For 20,000 identical entries, median retained allocation falls 5,768,784 →
988,192 bytes while population CPU is 23.995 → 23.879 ms. Direct unique writes
are 34.279 → 34.771 ms with nearly identical retained allocation. The cost is
not uniformly neutral: alternating population is 27.287 → 38.158 ms; neutral
replacement after unique proofs is 29.087 → 39.657 ms; deletion is 3.895 →
10.110 ms. Those latter costs occur in every matched pair. Unique population
is variable and receives no speedup claim. No samples or first failures are
removed. Integrated history and application measurements determine whether the
memory saving warrants these internal CPU costs in the supported workloads.
