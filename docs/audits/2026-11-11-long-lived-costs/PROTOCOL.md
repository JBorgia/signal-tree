# Long-lived cost and optionality investigation

Owner-authorized November 11, 2026, following application comparison source
`18e2eed330629900b5e519168785591c0ab751dc`. This work investigates and optimizes;
it does not publish a release or silently weaken either line's semantics.

## Questions and frozen premises

Separate ordinary retained-store work from the full v16 coordination contract.
Measure cumulative elapsed/CPU work from setup through successive operation
windows, not a crossover inferred from subtracting independently measured p95s.
Compare native Angular, pinned NgRx SignalStore, published v15.4.8 and the sealed
v16 packages using identified artifacts. Wider rows, sparse/full field demand,
aggregate queries, membership replacement and finite heavy edit aging are distinct
workloads. Include same-arm repeats, explicit oracles and planted faults.

From contributor contracts at the source above: "Framework packages may realize
SignalTree truth for their runtime. They must not create another state authority."
From support policy: v16 must "preserve pending authority, expose a usable recovery
handle, and require explicit confirmation before releasing durable consequences."
Stable v15 compatibility remains binding. Entity lifetime identity is already a
v15 guarantee; NgRx extensibility is not proof that these behaviors are built in.

## Coordination coverage

Run existing kernel and Angular contracts for current retained native reads,
late enrollment, independent/dependent/unknown publication, contradiction,
confirmation/rollback, refused compensation recovery, reentry, retirement,
restoration and point-work bounds. In addition run repeated installed-artifact
coordination episodes on retained stores, with exact intermediate output checks,
pending and settled heap checkpoints, and teardown. This exercises the guarantees;
it cannot prove arbitrary histories or make a simpler competitor semantically
equivalent. Keep cost comparisons of shared tasks separate from v16-only traces.

## Activation and optimization

Audit each relevant cost as always present, construction-selected, module-selected,
demand allocated, or active only with an optional feature. Measure actual selective
production bundles before proposing new runtime flags. A synthetic branch loop
does not establish the cost of a viable optional architecture. Configuration is
worth adopting only if real saved work outweighs routing, bundle, maintenance and
compatibility costs. Existing no-subscriber state must not discard evidence a
supported late reader needs.

Use observed profiles to implement compatibility-preserving v15 optimizations in
an isolated checkout. Preserve original artifacts and failed attempts. Check
meaningful behavior, compare independently repeated samples, and obtain independent
review before adopting runtime changes. Do not promote an ambiguous timing win.

## Evidence limits

Record commands, schedules before execution, source/build/package hashes, runtime
versions, shared-host load, raw child outputs and complete result distributions.
Execute timing cohorts serially across workers. GC checkpoints measure whole-process
heap, not library-only bytes; attribution samples are not exact CPU partitions.
Finite aging and collection observations do not establish universal boundedness.
New Node harnesses isolate runtime work and do not replace browser rendering tests.
Keep earlier failed controls and source claims separate from fresh execution.
