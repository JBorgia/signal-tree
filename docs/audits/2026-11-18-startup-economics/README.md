change is fresh, ordinary and aligned. It avoids redundant ordinary topology

## Measured costs and benefits

A fresh production Angular application compares the final canonical packages
with the frozen current baseline, five paired samples per workload plus separate
A/A controls. At 10,000 rows the factory paired median improves by 37.9 ms
(range 31.8–68.8 ms faster; A/A differences −2.8 to −0.7 ms). At 50,000 rows it
improves by 201.6 ms (199.4–253.0 ms faster; A/A −70.9 to −27.9 ms). The selected
factory medians remain 133.0 and 638.7 ms. This is a substantial bounded startup
improvement, not parity with v15 or NgRx and not a universal device claim.

Populated application heap falls by paired medians 293,036 and 982,204 bytes at
those sizes. Heap is whole-application live JavaScript after forced GC, including
Angular and the local service; it is not isolated library memory or peak RAM.
The application emits 147,481 gzip bytes of JavaScript, 180 more than its current
v16 baseline. Workload tiers do not represent measured industry/device populations.
See the [central study](https://github.com/JBorgia/signal-tree/tree/codex/startup-market-economics/docs/audits/2026-11-18-startup-market-economics)
for all peers, complete-command costs, native guarantees and economic assumptions.

The separate final native retained-store cohort passes its 10 controls, 12
functional, 32 CPU and 12 heap children. Active CPU remains mixed and adverse in
some cases: synchronous settlement across ten cycles increases in all three pairs
for 1,000-row rollback and 10,000-row confirm. All twelve observed trees collect
after owner return, while signed whole-process residuals remain positive. These
results do not establish an active-path speedup, equivalence or universal leak
absence. The central native report preserves raw and A/A observations.

The earlier isolated allocation cohort saves approximately 457 KB at 10,000 rows
and 837,176 bytes with 64 live scalar Links across 8,192 ordinary leaves. Actual

Tested trees collect. This is neither a universal leak claim nor equivalence.
Those observations retain their pre-resolver whole-artifact identity; only the
resolver payload changes in the final build, and unchanged-module continuity

Diagnostic profiles locate substantial population frame/publication work and

## What is optional

Creating a Link or using a transaction is optional. First observation and entity
field carriers allocate on demand. When publication infrastructure is loaded,
participant activation is automatic; correctness does not depend on a user
remembering another switch. Module loading depends on packaging: unbundled ESM
facade/root imports evaluate the reexported Link module and its factory
registration, while an unused Link module can be tree-shaken from supported
bundles. Shared entity-publication machinery is still present. “No Link means no
publication cost” would therefore be false.

Skipping notifications merely because no observer currently exists is rejected
by source reasoning about late enrollment and ownership, not a measured shortcut.
V15's empty-plan/lazy-container ideas remain a separate unmeasured v16 opportunity
requiring witness/cancellation adaptation. No extra configuration is justified
by this selection, and no claim of an irreducible or globally optimal runtime is made.
