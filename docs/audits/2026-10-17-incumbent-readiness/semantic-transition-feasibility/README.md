## Decision

ordinary facts. A transient shared result without a second authority is therefore
a plausible design inference—not an exercised common-record implementation. **This does not establish that one local return-value
change can integrate the feature.** Coverage and disposition span six installation paths and eleven writer families.
The demonstrated change must cross multiple value writers and consumers that
currently reconstruct chronology from physical notifications. This does not prove
that all six paths need redesign. The requested broad-writer-scope stopping
condition is reached before implementation.

Do not implement another setAll-only previous-value substitution. Do not replace
every physical previous value with ordinary truth. The decision now is whether to
fund the explicitly scoped internal migration below, or make a product decision
to defer declared early publication and retain conservative Link. Neither choice
has been silently made here; current hold and activation block remain.

## Inventory and minimum migration scope

The accompanying [writer inventory](WRITERS.md) traces exact anchors, delegates,
physical installation and independently staged facts. Six paths:

1. Direct existing-subject value installation (updateOne/held fields).
2. Entity mutation frames (replacement and structural/batch operations).
3. Point realization for existing lifetimes.
4. Complete-target realization (legitimately collection-wide).
5. Prepared structural replay plans (rekey/add/remove/restore).
6. Direct order/selection/maintenance paths, whose semantics cannot be reduced to
   ordinary row replacement. Selection itself uses scalar location machinery.

Eleven families include field/row updates, whole-row replacement, batch/predicate
updates, add/prepend, rekey, removals/clear, upsert, setAll/order, hidden-collection
reintroduction, realized replay and retirement. Inventory is source coverage, not
execution qualification of all families. Initialization remains unqualified.

An implementation would need to:

- Prepare physical and ordinary row views, explicit authored presence/field facts,
  lifetime/key/structural facts, order endpoints, participation and revision guard
  before installation. Keep storage-specific sparse paths; do not route point work
  through whole-target reconstruction.
- Return/retain that prepared result from the affected fast/frame value seams and
  have callers consume it rather than recreate semantic previous values afterward.
  Audit point/target/replay/order/selection/retirement for compatibility; leave them
  unchanged where their existing result already supplies the necessary facts.
- Carry consumer-specific evidence through the single existing notifier protocol.
  Inspection must derive chronology from prepared authored facts; native values
  and taps retain physical semantics and established timing/arguments. Existing
  Link projection consumes ordinary participation and field footprints.
- Preserve paired responsibility installation and all-unit-before-delivery ordering,
  throwing preparation behavior, first-error recovery and reentry revision checks.
- Retire transient results after consumers copy live obligations. No canonical
  row mirror, independent chronology authority or unbounded operation log.

This is a cross-cutting internal producer/consumer migration, not a thin adapter.
Adding fields to the frame result while leaving current callers intact is explicitly
insufficient. Its benefit is preventing divergent reconstruction; code size, runtime
cost and full compatibility are unmeasured.
