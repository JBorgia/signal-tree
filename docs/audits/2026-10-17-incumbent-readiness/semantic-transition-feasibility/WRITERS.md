## Capture, chronology and publication are presently distinct

`commitAndProjectEntityMutationFrame` and direct commit prepare/install terminal responsibility before committed observers. `committedEntityObserver`1253 freezes owner/context and optional structural placement facts; `lib/internals/mutation-capture-runtime.ts:102` independently delivers committed evidence, containing/reporting observer failures. Order evidence is a separate listener channel144.

Path publication later recomputes field changes from caller-supplied before/after (`lib/path-notifier.ts:336`) and distinguishes explicit authored footprint, full-row null footprint and unknown derivation. Its enqueue evidence snapshot307 precedes batching but still receives the caller's tuple. Transaction inspection explicitly owns local chronology separately from conservative rollback evidence (`enhancers/transactions/transactions.ts:1353`); inspection rejects a captured contribution lacking chronology at1951–1964. Therefore correct terminal responsibility alone does not establish correct inspectability/publication.

The frozen setAll counterexample demonstrates this exact split: private adoption changed semantic capture-before while caller staged physical prev remained equal to displayed next. The original setAll code anchors are3648–3667 (staged prev),3706 (frame install),3778–3793 (own publication tuple). This is established evidence against the rejected patch, not a claim that unmodified incumbent implements approved adoption already.

## Shared transition feasibility constraints (inference, not implementation selection)

A shared internal result can in principle carry each touched lifetime's physical before/after, ordinary-authority before/after, authored footprint, participation, key/existence facts, prepared terminal record identity and notification/chronology descriptor. Existing commit return seams do not currently express these together. Returning such data only from frames would miss the direct fast path, point realization, complete-target realization, direct ordering and hidden collection reintroduction.

A candidate scope must explicitly include producers AND consumers: callers must publish committed transition facts rather than their independently staged physical prev. Merely adding fields to a frame result cannot close setAll/updateMany/upsertMany if they continue to ignore it. Derive callbacks must still read displayed state; authority-before is not the callback input. Partial updates must not adopt untouched inspected siblings. Same-lifetime identity and membership/absence are not interchangeable with key names or payload IDs.

Physical change and authority change need separate decisions: equal adoption may require responsibility/chronology and Link eligibility without duplicate framework value notifications. Terminal preparation must precede installation; metadata cannot become live before failure-prone cloning/comparison/getters complete. Reentrant writes must either invalidate the prepared revision before install or remain newer authoritative work afterward; callback delivery cannot rewrite earlier prepared state over them.

Ordering requires a complete proposed topology/frontier where settlement reconstructs anchors, and all affected installations must precede delivery. Existing point/target/plan phase separation is useful but does not establish a single sparse semantic transition representation. A full-order operation may enumerate its members; a field update must not acquire full collection work. Reclamation must remain obligation-aware and reachable through ordinary churn.

These facts justify a finite seam-design assessment. They do not establish impossibility or authorize another runtime patch. No new public API is required merely by identifying an internal return seam, but structural adoption semantics for inspection-created/removed lifetimes must be separately governed before generalizing existing-row authority changes.
