S1 says M unchanged and W1 likewise; read literally that contradicts E3, which they require unchanged. Distinguish this from unresolved transaction compensation of an inspection-created lifetime. Slice1 should identify ordinarily-existing lifetimes as its repair domain and preserve existing egress behavior on the other case, with a characterization/stop gate rather than claiming that M is universally unchanged.

2. **Close slice1's realization dependency.** Slice1 requires inspect+rollback+ordinary publication, yet S3 realized handoffs are deferred until slice3. Ordinary-before retention is not discharged merely by writing physical values; equal realization/acquisition and point rollback must install the same authority transition or stale baselines can survive. Include the minimal existing-lifetime S3 install/discharge handoff in slice1 (with unchanged semantics), or explicitly prove the frozen point realization handoff already consumes the new result before accepting slice1. Do not defer that proof. Full topology S4/S5 can remain later. State whether the experiment starts from production plus approved scalar/projection/lifecycle components or from a rejected combined overlay; list frozen prerequisites, because a helper silently inherited from the rejected patch would obscure this dependency.

3. **Split mixed writers within slice1 honestly.** W7/W8 expose public methods whose update and structure/order branches share one invocation. Slice1 should specify that its new capabilities are update-only upsert and unchanged-topology setAll, while mixed add/remove/reorder cases run compatibility controls without claiming new adoption support. If a mixed operation cannot retain coherence with old structure and new value evidence, it must be included atomically with slice1 or held entirely experimental until slice2; do not ship/accept a partially coherent public operation. Scope this before implementation rather than discovering it after the positive subset passes.

4. **Retention owner/cleanup needs an explicit plan invariant.** The result is transient, but approved ordinary/inspection divergence necessarily survives the inspection operation until ordinary adoption or realization. Name the existing substrate-owned divergence retention obligation, its identity key and release conditions (ordinary adoption, realized acquisition, removal/retirement/destruction as applicable). This need not select syntax or add a mirror. Without it, “transient result” leaves unclear where ordinaryBefore comes from across operations, and W11 audit cannot verify no stale baseline after same-key new lifetime. Entity payload collectibility remains independently unresolved as the plan already says.
