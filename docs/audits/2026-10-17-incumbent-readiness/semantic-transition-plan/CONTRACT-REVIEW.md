The proposed separation, single notification protocol, source identity and audit/disposition treatment of S3–S6 are sound scope constraints. The plan avoids mandating a universal row event for ordering/selection/retirement. Five corrections should be made before treating the matrix as executable acceptance:

1. **Distinguish inspectable realized evidence from adding rollback chronology.** S3 says “H truthful realized chronology”; S5 says “H records realized footprint.” Native transaction enqueue inspection deliberately skips origin restoration and transaction-rollback (transactions.ts3150 onward), while settlement snapshot/terminality is independently maintained. These phrases must not require adding those skipped operations into pending authored chronology. State “preserve existing realized/rollback inspection filtering and terminal snapshot semantics; retain whatever realized evidence existing consumers require.” Otherwise the table silently changes inspection participation policy while claiming no semantic change.

2. **Qualify zero-installation on reentrant throwing preparation.** Slice1's “Throwing preparation/equality/getters install nothing” is too broad. A getter can author a legitimate nested write; the tested transaction-owned nested write is then compensated by abort, while an independent ordinary nested write can survive. State that the failed prepared outer operation installs no state/responsibility, while nested effects follow their actual ownership and existing abort/error contract. This avoids turning the preserved oracle mismatch into a new acceptance requirement.

3. **A1's original failure belongs to the rejected overlay.** Slice0 says “A1 reproduces exact original failure.” Unchanged incumbent lacks approved entity adoption and can instead inspect only m, then restore inspected99/88. Exact chronology-unavailable reproduction requires the frozen ba21c351 overlay plus its identity, not just copying the assertions into current Nx. Require separate incumbent behavior, exact rejected-overlay replay and future candidate expectations; do not manufacture the old error on a different baseline or count a different failure as reproduction.

4. **Keep inspection-created/removed lifetime rows explicitly conditional.** W4/W6 mention authored existence/removal and minimal-inspection rules. The stop section correctly reserves unresolved compensation semantics, but matrix success must not treat minimal egress adoption as deciding transaction lifetime ownership. Add a note on those rows: execute established controls unchanged; undefined structural-compensation combinations are owner decisions and cannot be marked covered by inferred rules. Existing-row adoption is the approved premise.

5. **Predeclare decision criteria, not only measurement methodology.** The measurement section freezes workloads/sample counts/distributions and keeps ceilings. It should also preregister how measured CPU/heap/churn/retention outcomes affect acceptance or trigger explicit owner tradeoff review. Existing measurement policy requires acceptance criteria before decision measurements; statistics alone leave room for after-the-fact acceptance. No new numeric threshold is selected by this review.

No additional architecture or public API appears necessary merely to authorize this bounded internal migration. These corrections clarify existing constraints; they do not authorize a notifier replacement, structural policy or performance tradeoff. The recurrence stop remains meaningful only after a slice claims its mapped shared coverage; ordinary first-red test development before a general correction is not itself a reason to abandon the slice.
