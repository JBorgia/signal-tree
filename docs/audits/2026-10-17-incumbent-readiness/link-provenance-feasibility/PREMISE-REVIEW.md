## What is observable today

1. **Write occurrence and identity.** PathNotifier.notify sees old/new value, owner, position/subject identity, metadata and field footprint (path-notifier.ts:262-320). Its enqueue observation precedes coalescing, so it is possible to distinguish chronology before delivery hides intermediate writes. These identify effects and location/lifetime; they do not identify inputs consumed by arbitrary user code.
2. **Notifier callback argument delivery.** `_runNotify` calls each handler with the supplied new/previous values and source identities (path-notifier.ts:440-458). The kernel therefore knows which source envelope it handed to that callback, even if the callback never calls a source getter. The existing hook explicitly clears declared observation scopes; it does not install a read-dependency/provenance context. `hop` really does consume the argument: link-reactive-settlement.spec.ts:48-54, 351. A read-only collector alone misses this supported path.
3. **Portable kernel computation graph.** location-runtime.ts:258-278 records dependency edges while `activeConsumer` exists; 561-600 refreshes/replaces a derived computation's graph and restores the prior consumer in finally. Writable getter reads go through 422-425. This is a computation invalidation graph, not currently a graph of inputs for arbitrary writes. `peek` bypasses that tracking (483); updater input is delivered through `update(current)` (464-466), another implicit input boundary.
4. **Write intent.** Portable/native bindings distinguish replacement and updater calls (location-runtime.ts:447-477; native-location-realization.ts:109-136). That distinction is useful, but does not prove a replacement value independent: `destination(source())` is replacement too. Conversely an updater may ignore its argument. Values alone do not settle this distinction.
5. **Settlement outcome and identity.** commit-consequence.ts owns scopes and receives explicit commit/discard. transactions.ts:4022-4058 confirms then closes in finally; 4090-4094 keeps refused rollback pending; 4155-4196 marks rejected only after compensation and discards even when observer delivery failed. These are usable lifecycle facts, not permission to treat every closure as confirmation.

## Missing facts and strict limits

**Native cached reads are not covered by the portable getter.** native-location-realization.ts:98-102 returns the adapter's native cell; only setters/update are replaced at 139-141. Native derived cells are returned directly at 212-215. Angular's adapter constructs `signal(read())`, publishes via native set, and returns `computed(compute)` (`packages/angular/src/lib/observation-adapter.ts:22-40`). A later native getter/cache hit need not call kernel storage read or compute. The ObservationAdapter interface supplies token observation/invalidation and creation/grouping, but no “current computation consumed these dependency identities” callback. Wrapping only the supplied compute function cannot witness a cache-hit consumer. A bounded result must state whether native cache consumption is excluded or explicitly unavailable; neutral tests cannot prove native coverage.

**Closure capture destroys recoverable provenance.** `const captured = source(); queueMicrotask(() => destination(captured))` arrives as an ordinary replacement with no intervening source read. The same destination value can come from a constant. Write-context.ts:14-30 and 58-68 expressly restores context before await continuation. PathNotifierHandler permits Promise<void>, but `_runNotify` does not await it. Existing boundaries cannot distinguish these executions at the deferred write by value equality, path disjointness, or lack of ambient scope. This is an observability limit, not evidence that a particular candidate leaked. A claim of all deferred closure copies requires an additional carrier/contract or explicit containment/unsupported classification. Blanket taint for every later write cannot also prove unrelated constants progress.

**Callback envelope provenance proves exposure, not exact use.** During a callback delivered speculative `value`, `destination(value)` and `destination(42)` are different dependencies but both receive the envelope. Conservatively treating the callback as dependent covers the copy, with a documented false-positive boundary. It does not prove semantic dataflow within arbitrary JavaScript. Distinguish “direct constant write outside callback” from “constant written by a callback that received speculative data.”

**Replacement needs current-version evidence.** Keeping a permanent union on destination makes later independent replacement remain held. Clearing every replacement loses `destination(source())`. Any bounded accounting must identify the current installed write and its known input provenance, preserve identity through queued delivery, and distinguish unknown from empty. Equality/no-op writes and ABA need separate examination: a skipped setter does not necessarily establish a new current version or discard old ownership (path-notifier.ts:502-508 skips equal delivery).

**Commit and discard differ.** Removing a token at either outcome is insufficient: confirmation can authorize surviving derived truth; rollback must not authorize a dependent value that still contains rejected input. Compensation may generate later notifier hops after scope closure. Nested settlement can create a new scope or overwrite a held callback; admission must remain valid at actual delivery. Callback/error unwinding must restore provenance frames independently of observer containment. Existing transaction cleanup solves scope lifetime, not provenance lifetime.

## Concrete falsifiers for a bounded experiment

- Pending x=7; direct y=42 outside a reactive callback: y endpoint must progress before x settles. Repeat y equal to 7 to disprove value-based taint.
- Notifier `(value) => y(value)` with no source getter: no y=7 before settlement. Extend x→y→z through queued delivery; confirmation releases valid truth, rollback never sends rejected 7.
- While y retains copied 7, replace y with independent 42; y=42 must progress. Reverse the order and ensure the later copy remains held. Include same-value replacement explicitly; report its chosen semantics rather than assuming a new write occurred.
- Native computed warmed from pending x, then read from cache into y: establish whether any kernel hook actually runs on that read. Compare cold/warm reads and portable/native paths.
- Capture x into a local and later copy via Promise/timer; pair with an identical constant write. If traces are indistinguishable, report unavailable provenance, never “independent.” Also test source rollback before delayed callback executes.
- One callback settles A, opens B, writes another destination, then throws; later independent callback must not inherit a stale frame. Refused rollback must keep dependencies pending. Compensation observer errors must not strand scope or release rejected truth.
- Endpoint “sending” observer mutates relevant state before endpoint entry; prove revalidation at the actual call, not only enqueue.

Disposition: notification-envelope and portable synchronous-boundary evidence can support a bounded experiment, but present hooks do not establish complete application dataflow. Address interference alone is already concretely refuted. Native cached consumption and arbitrary deferred closure copies remain explicit observability gaps; a broad feasibility claim is not established by source inspection or by a notifier-only harness.
