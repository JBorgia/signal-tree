# Concrete private input mapping for review

Proposal only. Rejected source2dacae7b remains unchanged. This maps semantic
requirements to current owners and installation sites; it is not an approved
runtime design, exported API or new test result. The unobserved-origin fallback
admission policy still needs owner selection. Unknown entity/read coverage remains
unqualified rather than being mislabeled as success.

## Metadata authority and identities

Native source owners keep publication requirements for their own facts. They do
not retain a second value store or select settlement. A requirement describes:
source identity, fact kind, immutable authored revision, ordinary/physical-view
participation, and compact owner/validation outcome references. Read certification
and recipient permission are separate. Hidden callback inputs still need complete
application declarations; a native argument certificate proves only its domain.

Ordinary branch membership needs two related indexes:

- Addressed slot: native parent identity plus supported literal key and occupancy
  generation; the current presence fact points to child identity only when that
  identity applies. This supports never-present versus pending omission and
  different lifetimes at the same spelling without creating infinite key records.
- Domain obligations: source-owned index of membership facts still relevant to
  current input certification or live inverse/recovery. Negative facts remain
  indexed while their obligations exist; unrelated value overwrites do not retire
  them. This index cannot be reconstructed by enumerating visible children.

The existing member-membership source retains physical descriptors, divergent
ordinary presence, expected child identity and revisions. Publication metadata is
prepared from those existing before/after facts, not used to decide membership.
Current private nativeMembers(child) is insufficient as the only domain access
path. The index is over actual changes/live obligations, not all queried strings.
A key known absent with no outstanding per-key obligation uses the domain's
ordinary baseline; a baseline cannot be minted while a pending negative fact is
silently omitted. A held old entity handle additionally uses collection
incarnation + lifetime, not current business-key lookup.

## Exact snapshot/cache association

Three situations must be handled separately:

1. **Value recomputed:** snapshot production resolves the existing P read and
   corresponding source fact identities together. It captures visible values,
   membership-domain obligations (including omitted x) and observable order. No
   dormant payload is imported simply because its slot is retained. The produced
   descriptor is immutable and tagged with the exact snapshot view/revision.
2. **Cached value, unchanged semantic/support revision:** use the same descriptor.
   No callback replay and no forced framework recomputation are needed.
3. **Cached value, support-only or ordinary-view metadata changed:** paired source
   installation has advanced a separate private certificate revision even if
   public value notification is suppressed. An existing installed transition must
   establish that this cache still represents the same observable P value/domain.
   At the next native-input acquisition, refresh only its evidence for that same
   current input view. Retained descriptors keep their old revisions; never mutate
   evidence held by an earlier callback/supported snapshot. If physical cache
   identity is stale or certification cannot establish correspondence, do not pair
   it with current O proof. Reuse a fresh input reader only where that native
   producer already supplies it. Branch updaters currently use unwrap/materialized
   snapshots; the separate unwrapBranchForWriteCapture bypasses nested memos for
   capture and must not silently replace their callback arguments. Preserve the
   exact existing cached-input descriptor or retain unavailable coverage when no
   faithful descriptor exists. Do not impose new native-computed timing or
   substitute an argument to obtain a clean certificate.

The private revision is installed alongside the source facts. It is independent
of application value notifications. Reading current metadata after a callback is
not an acceptable substitute for capturing the argument before that callback.
Source preparation can be reentered; validation must compare the exact native
source/view revisions after any callback-capable preparation, as existing
membership preparation does. A changed revision does not authorize rerunning the
user updater or inventing a new public refusal. Such a conflict must use the
existing pre-install validation contract or stop as a semantic conflict.

The first implementation could rebuild a full native argument's descriptor on a
support-cache miss from the source-owned domain description. Its cost is explicitly
O(visible input domain + relevant negative obligations), even if value materialization
was cached. That cost belongs in qualification. It must not happen on every point
setter or cleanup. Incremental support summaries are an alternative to measure,
not assumed free or required as an additional authority. A point argument uses
addressed field/ancestor/occupancy indexes and its own applicable negative fact.

No supported public metadata-carrying snapshot API is added. A saved ordinary JS
object/boolean consumed later remains an application hidden input; retaining it
does not entitle a future callback to current source evidence. Internally retained
input descriptors for active callbacks/inverses/delivery pin only the compact
metadata their actual obligations require. User-held receipts do not pin them.

## Inspection, selection and lifetime specifics

P and O need distinct tags even when equal. Native scalar derive already supplies
a displayed argument and separately reads ordinary before. A descriptor of that
argument must describe its displayed source; it cannot certify it from ordinary
before. Ordinary adoption then records its approved O transition; rejection restores
ordinary topology within the authored footprint while preserving unrelated
inspected fields. Unknown inspection input remains unknown until the authorized
adoption mechanism supplies the facts. No new adoption policy is introduced.

Selection is a key-based cell; activeEntity's domain includes selection plus
occupancy and returned lifetime. A held row's domain includes only its acquired
lifetime and relevant fields/existence, never a fresh by-key retarget. A removed
key's absence proof can retire when a newly authored mapping supersedes it, but
any live historical input/recovery retains the old version. Sorted ids/all also
consume native comparator arguments; external predicate/comparator state remains
subject to the complete declaration's hidden-input rule.

## Work/reclamation acceptance

Required counters separate source installation, descriptor acquisition, recipient
fanout, owner wake and retirement. Point mutation is proportional to affected
facts/ancestor depth and actual fanout; no registered-tree walk. A full snapshot
may cover a full membership domain; its negative obligations are counted too.
Same-value support changes and dormant transitions must not trigger blanket
collection value notifications to hide stale certificates.

Reclamation follows references from current source facts, active callback input,
incumbent recovery/history and queued/in-flight revisions. Replacing a negative
fact decrements only its superseded current reference; the last real obligation
releases its record and owner reverse links. A new lifetime never reuses it.
Repeated churn with fixed live obligations must bound the indexes. Domain baseline
compaction cannot erase pending negative support. Source destruction and Link
disposal each release their own roots; neither manufactures owner settlement.

This is a concrete placement/invalidation proposal for independent review, not
new code. It can be developed independently of the policy decision, but cannot
clear recurrence until the complete read domain, cache correspondence and fallback
admission are judged coherent together. The hook collision and stale mixed-undo
publication require the separate invariants already recorded; these descriptors
do not repair their causes automatically.
