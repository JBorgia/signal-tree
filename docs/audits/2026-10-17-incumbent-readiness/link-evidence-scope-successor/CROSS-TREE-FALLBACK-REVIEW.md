## Finite design dispositions to resolve before runtime repair

- Preserve a conservative default for genuinely unscoped/unproven-origin writes, while allowing separately certified native input/declaration cases to use their justified local fallback. Specify the evidence distinction and cost; do not classify it by value equality or a connection's grant.
- Supply direct-read dependency information only through an explicitly supported bounded execution mechanism. An unrestricted sticky “last getter read” is not justified: saved values, independent literals, reentry and async continuations make that a new architecture, not incidental port wiring.
- Explicitly qualify default cross-tree synchronization as an application boundary and require declarations/workflow separation. That is a public scope/compatibility decision needing owner authority, not an automatic test correction. Preserve the safety counterexample even if a future scope excludes it.

No option is selected here. Useful positive controls must distinguish a certified unrelated foreign-p write, this actual default pending copy, known foreign declared/native inputs, rejection, and source destruction/unavailable outcomes. No new blanket global hold or “unknown means safe” rule is authorized by this review. Unaffected membership mapping can proceed independently; production hold and integration acceptance remain blocked.
