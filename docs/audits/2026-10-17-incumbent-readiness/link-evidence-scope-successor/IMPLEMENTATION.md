## Source-owned requirements

`intrinsic-mutation.ts` has an optional native publication participant on each
existing scalar SourceRecord. The experimental module installs its factory before
tree construction. It runs independently of recipient registration, so a native
write before the first Link is not retroactively inferred from a later baseline.
The native participant prepares first; its opaque prepared requirement accompanies
the same mutation's recipient preparers. All plans share the existing terminal
record installation and installed-only completion mechanism. A failed preparer
cannot install the native record independently of the value/recipient plans.

`private.ts` owns weak identity maps `nativeValues` and `nativeMembers`. Each native
identity retains one current requirement, not a canonical payload, historical
values, or transaction compensation. Requirements name actual authored owner
cells, captured native supplied-input requirements, and the actual executing
validation horizon. Inspection writes do not replace ordinary requirements.
Unavailable historical origins stay unknown. Literal replacement replaces the
current value requirement; updater requirements compose the captured supplied
input and current execution obligations. Membership requirements have independent
child identity and survive recipient disposal.

Branch/root input scopes capture requirements from the native graph before user
callback execution. This snapshot survives overwriting a consumed field or
disposing its Link during the callback. It is distinct from each recipient's
coverage snapshot. `updateAndReport(updater)` now enters the same input scope
through recursive installation and exits in `finally`; its literal overload does
not claim a root input that was not supplied.

## Execution validation and recipient coverage

`lifecycle.prepareNativeRequirement` snapshots actual executing frames and installs
common owner/unknown/contradiction obligations through primitive terminal edits.
No passive connection baseline or relationship permission enters this operation.
`NativeRequirement` retains frame references only through the active horizon.
Outermost finish freezes compact owner/unknown/invalid proof, then clears input,
frame and temporary known arrays. This does not alter rollback ownership.

Recipient `prepareRevision` separately retains `coverageUnknown` plus its native
requirement reference. Recipient unavailable input coverage no longer mutates the
shared frame's unknown set. Actual native unknown and actual unknown/invalid
nested validation remain shared requirements. Actual known owners still test
immutable declaration assertions. The receiver reduces native requirements plus
its own coverage and retained projection support; a valid declaration can yield
a held aggregate.

Permission is not native provenance. Source input capture does not borrow the
cleanest recipient, another receipt, or a successful send grant. Default receiver
operations still lack declaration permission. Ordinary fallback uses the existing
tree-local consequence gate plus real known pending dependencies. Global pending
owner snapshots were removed from newly prepared blockers; unrelated activity
alone is not a fabricated foreign dependency.

## Routing and enrollment

Exact member routing admits a scalar only when the child identity is that source;
nonempty scalar descendant routes remain excluded. Binding construction seeds
source ancestor/internal membership from `nativeMembers`, including dormant slots.
Field-value support is excluded while its membership is masked; the absence fact
contributes its own requirements. Re-addition can expose retained component facts.
The enrollment walk uses the source graph already visited for initial binding,
not a scan of registered unrelated trees.

`hasPublicationPreparation` retains its recipient-enrollment meaning. A source
native participant alone does not make this query report a live receiver after
all receivers dispose. Actual native setter admission continues to record source
requirements independently.

## Replacement, completion and cleanup

Native weak-key records are independent of connections. Disposal removes recipient
hooks, indexes, operations and queued recipient references, without deleting
native facts or another active validation horizon. Native source collection can
release its weakly owned record. Literal overwrite drops prior current evidence;
transitive input requirements collapse to compact proof after the horizon rather
than retaining an ever-growing input graph. Current compact owner cells may remain
where their outcome still matters to the current fact; terminal cells do not own
the source tree or its callbacks. Receipts remain detached result views under the
existing terminality logic. No GC/collectibility acceptance is inferred here.

The existing membership hook is currently registered by the experimental module
independently of Link enrollment. Whether that singleton registration composes
with the preserved controlled preparation probes is an explicit first-run check,
not an assumed pass.

## Cost and coverage limits

This experiment adds native requirement preparation to scalar sources even before
Link enrollment. It therefore has real source metadata/allocation/work cost;
source-local does not mean free. A point scalar input follows its own retained
ancestor path. A branch updater enumerates the argument's native graph; the
updater already requests that whole argument, but duplicate traversal and
allocation cost still need measurement. No CPU, heap, bundle, retention or full
suite qualification is claimed.

Entities, dynamic source materialization and selected history origins remain their
recorded coverage boundaries. No public API/export or new settlement engine is
introduced by these private hooks. Production hold remains unchanged outside the
isolated experiment. B remains closed.
