## 1. What the added pairs actually establish

**Classification: scoped plausibility, not an executed repair.** A complete before/after pair for every changed adjacency, plus presence/key and changed head/tail, contains enough information to reconstruct a contiguous structural endpoint backwards or forwards. Including unchanged-authority neighbors whose pointers changed is necessary: `EntityPlacementStage.remove` edits both neighbors (`physical/entity-placement-stage.ts:23–30`), and insertion edits the predecessor/successor around the new row (lines 32–57). Sampling the pre-install base before installation avoids making its before facts follow mutable physical storage.

The record therefore can express the missing add-w prefix in the preserved add/overwrite-prepend falsifier. It can also express one-frame disconnected removals without imposing caller order as restoration order. The proposal correctly preserves full P/O separation and does not require a global linked token history. Topology-neutral units must not become self-edges; O-only existence adoption must produce O evidence even when P has no structural interval.

The source extension is real work, not merely adding optional fields: `mutation-capture-runtime.ts:120–122` currently dispatches structural boundary subscribers only when a physical structuralFrontier exists. Restoration additionally filters on that frontier and structuralRecords (`restoration.ts:4785–4793`). Both must support ordinary-only changes; generating pairs that these paths silently omit would repeat the failure.

**Additional source-mapping correction:** the old `structuralRecords` cannot simply be renamed P evidence. `entity-signal.ts:1254–1256` passes `ordinaryPlan.changes` into `committedEntityObserver`; lines 1982–1990 extract its structural records while pairing them with the physical structuralFrontier. Ordinary admission can synthesize an ordinary add at lines 1005–1014, whereas inspection retains the incoming physical change at940–944. The current carrier is therefore not uniformly physical. The proposed independent P/O stage-pair sampling avoids that ambiguity if implemented literally; a field-only relabeling would not. This is verified source structure, **not an executed additional failure**.

Cheapest behavioral falsifiers, **not rerun**: the byte-identical add/overwrite-prepend case in `order-composition-readiness.spec.ts:37–88` (saved candidate failure/production pass), the caller-ordered multi-removal and disconnected-run cases at lines 237–321, and an ordinary-only adoption followed by another owned structural operation and useful inverse. Their needed outputs are complete endpoints and usable repeat cycles, not absence of a throw alone.

## 2. Neighbor support is not an inverse ownership domain

**Classification: the draft correctly rejects an invalid interpretation; the valid selected-inverse mapping remains unproved.** A final stage patch is evidence of installed topology. It is not a list of independently reversible neighbor writes. Inserting B changes A.next; granting that writer A's placement authority would violate the frozen plan's ownership constraint. The proposal explicitly distinguishes support, authored order domain and endpoint membership, which is essential rather than cosmetic.

A concrete source discriminator is `indexed-source-owner-subset.spec.ts:58–87`: ordinary ABC, inspected removal of B, then authored setAll(C,A). O endpoints are ABC→CBA, but the admitted order domain excludes B. `entity-signal.ts:1050–1067` and `EntityPlacementStage.orderDomain:75–89` permute admitted slots while retaining omitted ordinary subjects. B's two adjacency links change even though B is not newly owned. Treating every pair as authored order, or filtering B out of the complete endpoint, fails this contract.

History inversion adds a second constraint. Source adjacency reconstructs *what happened then*; existing lifetime-sensitive placement decides *what can be restored now*. `structural-store.ts:428–480` resolves current live successors/predecessors rather than blindly assigning historical pointers. `restoration-missing-anchors.spec.ts:10–72` requires atomic refusal when the selected removed rows have neither live anchors, same-target restorations nor an authorized order delta. A pair record must not manufacture an order delta to bypass that refusal. Conversely, `two-setall-turn.spec.ts` retains transient dependencies that a surviving obligation actually needs.

Required concrete mapping: identify which composed endpoint is used only to complete an existing broad order delta; which selected structural effects enter the current placement resolver; and how support pairs are excluded from ownership/inspection effects. Show the subset-domain case and missing-anchor refusal through that mapping. **No static counterexample defeats the draft as written because it forbids the invalid promotion. No native proof currently demonstrates that a consumer implements the distinction.**

## 3. Noncontiguous selection is still a handoff to an unspecified resolver

**Classification: missing concrete proof, not a license to refuse more cases.** Splitting compatible runs is valid; saying “if an existing safe inverse applies, keep it useful” does not specify how selected runs are combined when foreign membership/key changes separate them. Token mismatch proves a gap, not its policy or final target.

The existing `native-foreign-disposition-matrix.spec.ts` supplies a useful discriminator that is harder than foreign fields: own rekey a→b; foreign removal of that lifetime; own fresh add at b. Rollback must leave both old/fresh references absent and remove the own fresh replacement, without resurrecting the foreign-removed old lifetime. Another case requires occupied-destination refusal, then successful retry after the foreign replacement is removed. These separate compatible noncontiguous selection, true conflict and later useful recovery. The full-order foreign-ABA witness is a different rule and cannot substitute for them.

A completed frame can also contain multiple effects while later authority selects/supersedes only part of their responsibility. Unit correlation must deduplicate physical evidence without converting effect selection into all-or-none unit selection. The routine's input names both references and selected effects, but its output projection from an indivisible topology patch onto selected inverse responsibilities is not yet specified.

Cheapest next proof is a paper/source mapping of those existing structural cases through input selected effects, support-only pairs, unselected gap evidence and the exact current target resolver. **Not executed or supplied by this review.** Do not bridge gaps merely because tokens join, rewrite foreign work, or add a blanket “gap refusal.”

## 4. Full record correlation is insufficient if order admission stays delayed

**Classification: conditional static counterexample to retaining the old admission timing; missing explicit installation rule in the proposal.** F01 installs frame values/placement/ordinary state and terminal responsibility before `observeCommitted` (`entity-mutation-frame.ts:381–392`). That callback invokes committed-capture subscribers (`mutation-capture-runtime.ts:118–125`). The caller publishes collection order later; for setAll, see `entity-signal.ts:4521–4555`. Order interference is admitted only by that later collection-order subscriber (`transactions.ts:2777–2807`).

Consequently, changing only the captured record while retaining that timing admits a bad observation order: installed own order A; a committed-capture observer reenters with foreign order B; outer A's delayed order projection arrives; later own order C. The order-witness subscriber can observe B,A,C rather than installation A,B,C. It would treat B as before the first own order instead of between owned orders. The existing witness distinguishes these cases, and the proposal promises to preserve that distinction. This is a static control-flow counterexample to that implementation choice, **not a newly executed public reproduction or proof the proposed stronger completion rule is impossible**.

Required clarification: “minimum responsibility” must include admission of the unit's order contribution and foreign-order witness before *any* committed observer can reenter, including fault reporting that calls user error handlers. Subsequent entity/order projections may arrive in either order only as idempotent consumption of already admitted facts. Deduplication must cover witness admission, not just endpoint composition; no double ordinal/admission on the later projection.

Also narrow “the broad order endpoint already exists in frame preparation”: prepend's `orderEndpoints` is prepared by `EntityMutationFrame:224–230`; setAll's physical endpoint arrays are held by the caller and published later (`entity-signal.ts:4538–4555`). The data is available before delivery, but not universally through the same frame field. This is a source-mapping correction, not an argument for another journal.

Cheapest future falsifier: use the existing own/foreign/own order-interference case with the foreign write triggered between committed-entity capture and the later order projection, then require atomic refusal plus inspect/confirm usefulness. Repeat with the foreign event before the first own unit, which must retain its useful inverse. **Not run.**

## 5. Leaf evidence join: correct target, still an admission-phase proof

**Classification: scoped plausibility with explicit remaining proof.** This proposal now identifies both failed identities: tagged membership with undefined value slots is not a ping, and ancestor influence does not match the leaf's exact position. It correctly preserves literal segment identity, per-tree identity, separate entity lifetimes, connection-relative baselines and no retroactive event enrollment.

Joining an actual affected-leaf membership admission to that relationship's actual projection addresses this failure class without granting authority from payload equality. The proposed ordering requirement is necessary. Moving evidence minting after those callbacks would still allow dependencies to be inferred from the wrong moment. At the same time, minting a fact is not permission to send while declaration validation or pending dependencies remain. The exact pre-reentry terminal source point, completion on both delivery paths, and per-event/per-connection ticket lifecycle need to be mapped. Preserve the membership chronological barrier at631–639 and creation after admission but before delivery.

A tree-local affected-source index is plausible; no static source proof establishes its registration, preparation-failure, disposal and in-flight cleanup. Useful missing-member/re-add, literal-key, validation-reentry, ABA and queued/synchronous controls must execute on the eventual exact native source. They were **not run here**.

## 6. Retention and final disposition

The no-backpointer source token and reuse of existing retention owners are stronger than adding a second journal. The cited transactionOrderAdmissions clear at `transactions.ts:4991` exists; there is no demonstrated teardown defect from its alleged absence. Nevertheless, shared pair references retained by history, pending handles, callbacks or Link tickets require release accounting distinct from merely clearing one map. The O(k) target counts changed neighboring links and retained intermediate dependencies; broad reorder and affected-consumer fanout remain separate dimensions. Nothing here accepts the current bundle failures or proves collectibility.

Keep paired extension as a concrete candidate. Before calling it sufficient, explicitly install order-witness admission before reentry, map selected runs/effect subsets into existing inverse policy, and show the neighbor-support/domain distinction survives both undo and redo. The leaf join remains separate and must carry pre-reentry evidence through both delivery paths. These are finite mechanism proofs, not authorization to patch native runtime, change authority, relax refusal policy, increase budgets or reopen B.
