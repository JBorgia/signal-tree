## Required distinction

A declaration covers the inputs of newly authored facts in its connection's native source. It is not a certificate for the whole final object. Existing sibling value, ancestor/member existence, lifetime, occupancy and order remain supporting facts. They can make a valid new receipt held/conservative; they do not themselves contradict that field's declaration. An actually consumed updater argument or inherited validation input remains a known lower bound and can contradict an independent declaration.

A full replacement can replace only the value/membership/order facts its native operation actually authors. Existing API semantics, not method name, decide the footprint: an explicit row replacement differs from derive/partial update; subset order preserves omitted eligible slots; inspection is not ordinary authority; native new input and incidental preparation neighbors are different. Never broaden capture ownership from publication support.

## Representation and sparse index obligations

Keep one relationship eligible reducer/baseline. Extend it with stable per-field/source fact slots and native structural slots; do not create a native value store from those slots. Each installed edit references one immutable own proof; outgoing projection revision composes only still-contributing support. Native field/lifetime identity and ordinary topology remain source-owned. Own proof must stay distinct from composite proof, or a supporting ancestor either becomes permanently copied into a field or disappears on field overwrite.

Required indexes are bounded to actual subscriptions/dependencies: native scalar source→fact subscribers (including ancestor aggregates); exact registry/structured-address trie for membership and ancestor subscriptions; collection owner→connections; lifetime→field/existence/mapping facts; authored order-domain subscriptions; owner/horizon→live fact/revision dependencies; connection→all release handles and pending units. Construction may enumerate the source and retained dormant locations as acquireObservation already does (`observation-substrate.ts:145–185`); disclose and count that work. Full replacement/output materialization/order may visit their real domain, not masquerade as point work.

Untouched baseline fields should inherit relationship-baseline-safe support only under the existing baseline gate. A connection created while relevant evidence is unavailable receives unknown for that support, not blanket independence. A later field declaration cannot bless untouched structure. Inspection-before-creation adoption remains relationship-relative; inspection after creation never advances its O component. Masked ordinary components remain part of the eligible reducer, with added retention counted and released on replacement/disposal.

## Receipt and completion map

Each relevant authored aggregate projection revision supersedes the previous unstarted relevant revision/receipt, even if some old fact support remains required. Supersession retires receipt views, not still-contributing source proof. Pending units/work must be registered before observable callbacks; native completion is independent of notification presence and already-held sends. Horizon validation gates all covered connections. Once complete, receipt state reflects composite held/conservative/eligible status, not merely the new field's independent own proof. Started/superseded/disposed/no-write remain terminal detached snapshots. In-flight transport acknowledges only its own immutable packet and reconciles a later eligible correction.

Effective equal support means no new receipt revision; an equal value with genuinely changed final support can be meaningful without a value event. Ordered reduction must retain a prior useful unsent payload when a later tentative equal setter collapses; it cannot restore an older fact over newer reentrant installation. A no-setter scope remains no-write.
