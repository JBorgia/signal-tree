## Mechanism established for implementation review

Keep destination ownership, proven input support, possible-owner windows,
validation obligations and recipient uncertainty logically distinct in the
existing private evidence. Combine their gates; no category erases another.

1. A write owned by p still acquires its applicable fixed possible-input window.
   Confirming p discharges p only, not possible q.
2. A truthful independent literal inside p has no speculative input merely because
   p owns it. Preserve p's delivery gate without making p an input contradiction.
3. When a native argument consumes a revision owned by p, that p becomes actual
   input support of the consumer. Do not erase it as destination ownership.
4. Only a newly acquired window may normalize duplicates against already-required
   identities. Inherited uncertainty retains its reason and surviving-basis receipt,
   even when the same owner also appears in destination, input or validation roles.
5. Terminal events wake exact current obligations for fresh ordinary evaluation.
   They do not authorize stale captured payloads or revive terminal receipts.
