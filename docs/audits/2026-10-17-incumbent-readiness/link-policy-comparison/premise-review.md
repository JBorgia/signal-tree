## A concrete supported incoming boundary

`link.ts`'s `acquire(value, seq)` receives an endpoint value after stale/disposed checks, sets `knownY`, directly replaces `eligible`, and synchronously applies `external(() => write(value))`. Its comment states: “External truth is authoritative for this relationship.” The complete supplied value, rather than a subsequent live-tree reread, is the authority input. Endpoint subscription and successful retrieval both feed this existing boundary.

A concrete automatic-progress control is an externally authoritative sensor reading admitted to y while an unrelated transaction keeps x pending on the same tree. Use an incoming Link on y plus a distinct outgoing Link on y. Feed sensor 42 and assert the outgoing endpoint receives 42 before x settles; repeat sensor value 7 with pending x=7 to disprove value-equality heuristics. This can progress without a new per-event caller assertion: the existing endpoint relationship already declares acquisition. It proves bounded authoritative ingress progress, not all apparently unrelated ordinary writes.

Testing only the receiving Link's endpoint is vacuous: `knownY` equals the inbound value, suppressing echo regardless of admission policy. Also avoid external writes to another tree as the principal witness: the incumbent already has tree-local isolation. The second outgoing Link on the same tree exposes the actual hold to change in the research bridge.

Important qualification: Link trusts an endpoint as an authority; it does not inspect how its callback manufactured the value. A local worker computing from speculative input is authored work under external.ts's existing contract, even when asynchronous or remote. Routing such a value through a purported external endpoint cannot be advertised as automatic provenance discovery. Research should identify the existing trust boundary and include this misuse/unsupported case explicitly.

## Envelope, closure, and cache are different inputs

- A runtime-owned authoritative incoming payload can seed an authoritative installed revision. Only that envelope earns the fact. It does not clear all ambient dependencies, cleanse arbitrary local variables, or authorize an entire branch containing other pending fields.
- A notifier-delivered payload exposes its source revision to the callback. `_runNotify` in path-notifier.ts calls handlers with new/previous values and metadata, currently under `withoutWriteObservationScopes`. Source-envelope attribution can cover an argument-only copy that never calls a getter. It proves exposure, not exact use. If code can consume both new and previous values, the frame must account for both, not merely tag the newest revision.
- User callbacks may also read captured variables and native cached values. Receiving a clean envelope is insufficient to classify every callback write as clean: `onSensor(clean => y(capturedPending))` is the direct counterexample. A trusted incoming installation performed by Link itself is stronger than running an arbitrary application callback with a fresh empty frame.
- Portable getters call `trackDependency` in location-runtime.ts, but this currently tracks computation invalidation, not arbitrary callback provenance. `peek()` and updater arguments are separate consumption paths. Derived caches need retained revision/dependency facts, not only a hook around recomputation.
- Native location realization returns adapter cells directly and replaces only setters/updaters; native derived cells can serve cache hits without kernel compute/read. Angular adapter constructs `signal(read())` and `computed(compute)`. Missing native consumption instrumentation must select unknown/safe fallback in the bounded experiment, not empty dependencies. A portable pass is not native qualification.
- Unscoped post-await writes stay unknown. The preserved paired probe demonstrates identical normalized existing write/delivery metadata for captured 7 and literal 7. Relaxing universal async inference does not authorize labeling these existing indistinguishable writes clean.

## Disposition

There is a defensible existing authoritative acquisition seam for bounded automatic independent progress. There is not yet an established clean arbitrary execution seam. A specification that calls all top-level/no-read callbacks independent repeats the failed premise. A specification centered on actual admitted envelopes, observed synchronous inputs and unknown fallback can be tested against real Link, while explicitly reporting that arbitrary direct constants outside those evidence boundaries are not yet qualified. If owner intent requires those constants too, this narrower capability must remain partial rather than silently satisfying the broader requirement.
