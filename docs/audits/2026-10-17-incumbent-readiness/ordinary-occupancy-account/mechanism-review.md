# Independent occupancy mechanism review

Read-only against MECHANISM.md, rejected6bd4ee8a records, and the frozen rejected implementation's incumbent effect/target code. No runtime edits or executable model. This assesses expressibility, not acceptance.

## Finding

Bind/Unbind is a plausible common **occupancy** compiler and directly removes the writer-conditioned displacement omission behind the successful rekey-vacancy failure. It is not yet a complete operation account. The document correctly keeps value, placement and transaction authority separate; that separation must be concrete at lowering and realization, not merely prose around Bind.

No proof of an impossible representation or unavoidable second settlement engine was found for the two preserved failures. There is, however, a precise limitation of the existing inverse interpreter that the mechanism must explicitly replace or precede.

## Exact incumbent lowering boundary

The frozen `target-transition.ts` structural interpreter (`applyStructuralEffect`, around679–726) treats add as requiring a physically absent subject and rekey as requiring a physically active subject at effect.before. Its add path throws `Subject ... is already active` before constructing the target. Therefore an ordinary remove inverse cannot simply remain an add while feeding current physical source to that interpreter when the old ordinary lifetime is physically active elsewhere. That is the preserved active-old safe refusal.

Two coherent internal representations are possible within the stated mechanism:

- Keep original admitted ordinary inverse facts for authority, but compile a distinct physical realization edit from target occupancy joined with current lifetime lookup before this interpreter sees it.
- Build an explicit validated physical target directly from the joined occupancy account, retaining original ordinary edits separately for ordinary discharge/publication.

Neither may mutate the transaction's original ordinary add/remove record into a physical rekey and then pretend it is the same authored fact. That would lose the ordinary inverse and change dependency/inspection meaning. The existing private prepared result can carry both views, and native storage already has exact-lifetime transfer/restore operations, but the current complete-target interpreter does not perform this join automatically. This is an implementation boundary to acknowledge, not evidence that a full replacement authority is required.

## Required rules/limitations

1. **Bind is not a complete rekey or placement instruction.** It can determine which bindings are replaced, but cannot distinguish append, prepend, full reorder, necessary-existence adoption, or key-only rekey. Explicit placement and field intent must come from the existing operation before compilation. Do not recover them from the resulting occupancy map or P order.
2. **Active-old value handling needs a discriminating case.** If old ordinary A is physically at B with an inspected payload change, inverse occupancy may transfer that lifetime to A. A physical rekey normally preserves its current displayed payload; it must not silently adopt that payload into O, nor necessarily replace every physical field with a historical ordinary row. Carry exact value edits separately. Compare active-old with unchanged payload and active-old with an unrelated inspected field; an ordinary add-record's retained recovery value is not automatically authority to overwrite unrelated current P fields.
3. **Placement is not solved by current-P identity reconciliation.** The active-old transfer must still implement the approved successor/predecessor policy and preserve later independent placement or established atomic refusal. A map of keys/lifetimes cannot decide position. Missing/replaced/moved anchors and anchors removed by the same settlement need the already-approved rules applied to the complete target. No new chronological replay policy follows from Bind/Unbind.
4. **Before-set versus chronological edits.** Recording each affected prior fact once is suitable for operation-before state; it cannot replace the ordered edits needed for repeated key use and conditional dependency/supersession. The compiler needs staged lookup for both directions, including displacements earlier in that same frame. Installation must validate both index directions together with physical/source revisions.
5. **No-override requires a maintained invariant, not an expensive proof on each read.** An inspection rekey must prepare all affected subject/key exceptions before P changes. Otherwise falling back to P can resurrect an ordinary absent subject or miss a displaced occupant. Test roundtrips and multi-step swaps with zero unrelated collection enumeration.
6. **Net equality sentence needs qualification.** Preserving operation revision for responsibility observation is appropriate, but the sentence “net equality does not erase ... responsibility revisions” must not grant a new nonempty rollback contribution where the incumbent intentionally nets canceled operations. Retain the incumbent's terminal/no-op behavior and publication-responsibility revision distinction. Before-set, authored intent, and surviving compensation are different products.
7. **Supersession stays with incumbent authority.** Updating O on a newer authored write is not sufficient to prove the older inverse remains valid. The existing newest-open-first refusal/admission must consume the actual binding/value/order claims. Retained recovery snapshots must never participate in ordinary reads after supersession. The proposal states this correctly but has not demonstrated the complete lifecycle.
8. **Reclamation includes ongoing divergence.** Ordinary-present/physical-absent identity is a live obligation even with zero pending owners. Conversely absent/absent inspection roundtrips may release false overrides after both indexes normalize. Held reference identity can remain non-reused without retaining a whole row/tree. No counting or GC result is supplied by this design.

## Disposition

The proposed account can express the original rekey-vacancy omission and active-old transfer distinction in principle, provided it preserves separate ordinary authority and physical realization edits. It cannot be accepted as a simple lowering into today's unchanged add/remove/rekey interpreter: the active-old witness proves that interpreter lacks the necessary physical-identity reconciliation.

Before a successor, specify that exact private join, value/placement behavior and staged-index invariants against the unchanged witnesses. This review identifies no need to reopen C1–C3 owner policy or adopt B. It does not approve runtime implementation, a universal structural model, or later-slice expansion. The unresolved work is a bounded representational demonstration, not another writer-specific displacement guard.
