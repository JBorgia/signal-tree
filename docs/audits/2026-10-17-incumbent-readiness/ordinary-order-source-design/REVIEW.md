## Source-owner mechanism

The design makes existing collection-local EntityOrdinaryTopology authoritative for ordinary presence/key/placement and retains EntityValueStore payload ownership. That is one source authority with separate storage responsibilities, not a Link/history store or settlement authority. It requires a complete separately named P/O patch, reciprocal neighbors/head-tail preservation before P changes, immutable final source facts before callbacks, revision/occupancy validation before a callback-free installation, and existing authority deciding permitted inverse/refusal.

It explains all four failures at their source: ordinary B A/C neighbors survive inspectedCBX; final prepend placement is captured before any flush; nested callback operations follow the completed outer unit; redo consumes those same facts. No downstream physical snapshot correction or writer-specific neighbor exception is proposed.

Measured N cleanup with zero retirement justifies a requirement to normalize only union(Pchanged,Ochanged) or an exact dirty set, not an assertion that such an optimization already works natively. Existing frozen models still scan all exceptions/snapshot records. Retirement/hidden parent authority and established P99/O7, successor placement and order-conflict policy remain separate constraints. The design states that fallible native install paths must be resolved before adoption; it does not assume universal OOM safety.
