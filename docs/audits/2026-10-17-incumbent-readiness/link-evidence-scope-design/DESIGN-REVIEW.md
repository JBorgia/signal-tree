## Why the split addresses the demonstrated recurrence

Frozen `private.ts:66–78` already keeps branch-input snapshots by recipient. Yet `prepareScalar:155–164` folds native attribution errors, actual input proof, and that recipient's coverage into one unknown Boolean. `lifecycle.ts:95–102` broadcasts the Boolean to every active frame. `finish:145–157` freezes the resulting shared unknown into the declaring recipient's proof. Passive c2 enrollment therefore changes c1's validation status despite identical native input and declaration.

Design lines34–62 separate the identities that this code conflates. Native lower bounds require a source fact/revision; actual nested declarations and validation execution accumulate in their existing frames; recipient-only unavailable evidence stays with that recipient. Lines101–106 explicitly prevent local coverage from altering the shared horizon result while preserving a genuinely unknown/invalid enclosing declaration. This is stronger than filtering nonmatching channels at one call site and is consistent with the contract.

Installation now prepares common execution/frame deltas once per native operation rather than allowing separate fanout plans to overwrite shared state. Completion is expressly not validation or eligibility. Reduction combines the recipient's actual contributing support instead of treating a completed y write as authority over x. Those are the necessary distinctions for the existing root progress failure and earlier last-revision collision.

## Native requirements versus relationship annotations

The draft's prohibition on promoting a relationship grant or assertion to native proof is necessary and supported. In frozen source, `Fact.revision` is a private serial allocated per recipient, `factChannels` associates it with a channel, and `ownProofs` can contain that channel's declaration/coverage result. Neither authentic OwnerCell identity nor a matching current value proves which native input required that owner. The word native cannot make this representation common authority.

Before an implementation uses a common requirement, its handoff must establish the native source/lifetime/fact revision, the actual consumed or authored footprint, and why the requirement applies to this unit. The draft already demands that certificate and keeps a mere recipient annotation scoped when it is all that exists. This is a remaining source mapping, not an owner-policy ambiguity and not evidence that a new global proof store is necessary.

A useful precision for implementation review: distinguish authentic owner identity from proven dependency. The former prevents forged handles; the latter establishes that the particular input/unit depends on that owner. Keep both checks. Do not solve the current contamination by throwing away a recipient's genuine foreign support merely because it cannot be promoted to common native evidence. Design lines50–56,118 and142–145 preserve that constraint.

The bounded full-source c1 case can continue to use its own available input annotations. The draft does not promise complete source evidence for an ancestor argument wider than a descendant recipient. Its explicit unqualified-route condition at the end prevents silently importing another connection's cleanest proof or making unseen native input an application-hidden-input exception.

## Nested scopes, replacement and cleanup

The draft retains A0's actual nested-scope accumulation explicitly. Outer independent → inner dependent(p) write → outer literal rewrite still accumulates p and contradicts the immutable outer empty assertion after callback. Passive enrollment is not such an inner declaration. An implementation must preserve getter/then-getter/reporter writes as real execution, not classify all effects occurring during an enrollment/disposal helper as harmless merely by function name. The enrollment matrix's callbacks are passive; this limit matters when interpreting its result.

Replacement operates on exactly authored facts outside the prior closed horizon. Same-scope support cannot erase inherited unknown/invalid validation; a new scope may replace value support while preserving native lifetime/presence/key/order requirements. Equal-support no-op remains no-write, while an explicit equal-value write with changed responsibility creates a support-only unit. These rules remain aligned with A0 and avoid using equality as an independence grant.

Cleanup is rooted in live source/capture, active validation and recipient contribution/queued/in-flight work rather than terminal receipts. Disposing c2 cannot rewrite c1's horizon or delete common native requirements still referenced by c1. A terminal receipt cannot keep those graphs alive. The draft specifies those ownership boundaries adequately; it does not establish bounded memory, exact release-index implementation, or source-destruction auto-drain. Those remain native verification obligations, not omissions that justify a second authority.

## Fallback and the sixth original red

Design lines112–125 correctly distinguish declared permission from ordinary surviving fallback. The latter uses a fresh coherent ordinary projection under the actual tree-local gate plus known foreign constraints. A successful send is not a native proof for a later updater. No completion flag or closed horizon alone grants permission.

The approved proposal's line17 concerns a surviving copy with explicit foreign support; it does not make unrelated open owners dependencies of every unknown-coverage input. A0:157 permits unavailable historical evidence to drain under the supported ordinary gate. Therefore the design's separate adjudicated wider-input case—no declared grant, with actual local/foreign obligations governing fallback—is consistent with those exact premises. Keeping the original no-send assertion and first red archived, rather than rewriting them as a pass, preserves the evidence.

One implementation boundary must stay explicit: dropping the global pending-owner surrogate does not drop an already known foreign dependency, an unavailable authentic owner requirement, or an unresolved relevant horizon. Those obligations need their own reverse indexes and wake/disposal semantics. The draft states this; passing a tree-local fallback alone will not prove it. The two preserved same-tree controls pass but do not establish foreign-source safety or post-rejection recovery.
