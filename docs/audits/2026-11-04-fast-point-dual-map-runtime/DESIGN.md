## Mechanism

Keep source-issued point packet authentication, aligned topology, native-only composition, lazy collection version and exact pending-membership snapshots unchanged. Change only native entity field storage and its necessary reader/freshness bookkeeping. Restore separate `Map<subject,Map<field,NativeFieldEndpoint>>` and physical View maps from f165; native Map insertion order preserves independent side order. Keep exact endpoint identities, deliberately mutable equal-value physical Views and immutable per-edit physical images distinct. Ordinary merge/deep equality and public exports are unchanged.

Point preparation stages a single endpoint/View pair. Unescaped, non-busy Maps can be changed only at terminal installation. Exposed Maps clone during preparation; busy Maps clone for callback-reentrant inner preparation. Source always exposes native completion before passing it to a recipient, and native-only source completion stays opaque. Point completion seals/clones during exposure. Generic physical-only ordinary support retains the predecessor's dynamic fallback. No terminal cloning, iteration, payload callbacks or new field-order arrays/pair wrappers/RowFacts objects.

A saved retirement plan marks BOTH captured Maps escaped; ordinary subsequent point preparation copies them and Map identities invalidate the saved plan. Independent review found a distinct late-capture ordering: point prepared first, retirement plan captured second, point installed third. Preparation-only copy-on-write cannot detect this through Map identity. Use one participant WeakMap from captured row Map to an identity token, established only on the first retirement capture and never merely changed by another read. Plans snapshot both identities and token references. Point preparation precomputes a fresh token; terminal installation updates only existing token entries for Maps it mutates. Thus no persistent token exists for never-captured populated rows, no numeric wraparound and no terminal allocation/clone. This bounded carrier closes a concrete correctness hole; it is not a general numeric-revision/storage redesign.

The inspected source admission has no demonstrated path for a previously unexposed native generic completion to escape after another source point is prepared: recipients always receive expose first, native-only completion is opaque, evidence is dynamic and View capture deliberately live. Direct native.prepare/expose bypassing Source is outside that admission. No blanket escape marking of all generic seed rows is introduced from this unsupported hypothetical.
