## Implementation and interpretation

[Design and verbatim frozen premises](DESIGN.md) constrain the experiment. Only one production module changes from eef7: separate ordinary endpoint and physical View Maps replace fused RowFacts/pair wrappers/order arrays. Source-issued point authentication, aligned topology, native-only completion, lazy collection versions, exact pending membership, ordinary merge/equality and public APIs remain unchanged. Native Map insertion order retains independent side order. Saved evidence and reentrant preparation copy Maps before installation; physical View identity remains deliberately live while per-edit evidence is detached.

[Premise review](independent-premise-review.md) found a concrete late-retirement ordering: prepare a point, capture a retirement plan, then install the point. Preparation-only COW misses it. Plans therefore mark both captured Maps and lazily establish WeakMap identity tokens; point preparation precomputes a replacement token, and terminal installation updates only existing token entries. No permanent token is created for never-captured rows, no numeric wraparound, and no terminal clone/iteration/payload callback. A token may remain while its captured Map remains reachable after its plan is dropped; no storage saving is inferred from weakness alone. [Code review](independent-code-review.md) and late-capture tests cover this carrier alongside unread readers, callback reentry, equal-value Views, physical-only dynamic ordinary support and ordering.

This tested combination shows the faster point processing can coexist with predecessor field storage without the fused prototype's populated-heap regression recurring in this screen. It does not isolate each pipeline change's CPU contribution or attribute the saved bytes. Remaining investigation concerns pending and deferred work; this run does not identify their cause or authorize a new owner-journal/wholesale storage redesign.
