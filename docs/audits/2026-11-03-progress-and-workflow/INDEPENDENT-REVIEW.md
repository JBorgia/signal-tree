## Does agentic configuration/workflow hurt progress?

**Some current workflow practices do; the inspected project rules do not require most of that overhead.** AGENTS explicitly rejects fixed model/headcount rules and calls for the cheapest meaningful falsifier. The architecture protocol says additional rounds require a new concrete question, wording repairs do not automatically require full review, and parked conditions are not a backlog. PLAN says not to append an unbounded chain of optional research tasks. The small Codex/Claude reviewer definitions are bounded and permit “no blocker found.” Project `.codex/config.toml` registers a local MCP server; it is not evidence of a compulsory multi-agent choreography or a defective model selection. Global model/permission economics were not audited.

Concrete overhead sources and remedies:

- **Historical status embedded in the live queue.** RELEASE-CURRENT still says small memory measurements “are next” immediately before reporting their completed stop. IMPLEMENTATION's early remaining-work list includes artifacts/protocol/browser work documented as completed later. TODO explicitly calls older headings historical, but is still a large historical container (Main reports276KB; that size was not independently measured here). Remedy: a short live status table with superseded sections clearly archived, not deletion of first failures. This improves current truth without weakening evidence.
- **Many full candidate snapshots and repeated identity handoffs.** They protect provenance, but repeatedly rediscovering which candidate owns which result consumes attention and makes milestone closure difficult. Remedy: one selected integration identity, incremental manifests/diffs and a compact evidence/dependency index. Preserve raw first outcomes once; avoid duplicating complete historical narratives into every handoff.
- **Cold tooling setup inside every bounded measurement command.** R1 used new Nx workspace-data directories each time; graph/plugin/config discovery was repeatedly visible. Historical archived tsconfig paths also appear in discovery warnings. Requiring Nx is reasonable; requiring a cold graph every invocation is a protocol choice, not fresh-library-worker isolation. Separate these layers rather than bypassing tests or relaxing runtime budgets. No precise share of overhead is established.
- **Coordination and waiting.** C0 was administratively cancelled after another heavy job was reported. In this session the available task inventory did not expose a directly addressable Noether thread, leading to relayed/file-based review clearance. Remedy: give workers stable tool-addressable IDs and one exclusive heavy-job ownership/clearance mechanism; exchange milestone events rather than repeated polling. This is a tool/orchestration problem, not a library defect.
- **Review scope can expand past the decision.** The late-loading question and absolute-count premise illustrate where qualified unknowns can turn into indefinite obligations. Remedy: every review should end with a bounded disposition, a concrete reopening condition and the next implementation/acceptance action. Ordinary wording or receipt repair needs a delta review, not a new full architectural cycle.

Do not remove independent scrutiny wholesale. It caught real registration-artifact false positives, stale proof witnesses, controller acceptance holes, misleading test oracles and the unasserted cold-boundary observation. The productive change is to retain independent review at material semantic/artifact/measurement boundaries while reducing repeat framing, unclear handoffs and investigations with no completion criterion.

## Feasibility and limits

A bounded multi-actor reference workflow is already demonstrated, and a semantics-preserving integrated implementation is plausible given the extensive surviving evidence. There is **no justified schedule, effort estimate or assurance that the current complete semantics fit the current absolute budgets**. Product differentiation and final adoption burden remain separate uncertainties. None of this requires assuming impossibility or abandoning approved semantics; it requires a finite acceptance decision rather than interpreting every new passing probe as proximity to release.

This audit used current documents plus selected raw logs/source and previously independently checked packets. It did not rerun suites, inspect every acceptance family, assess every old rejected candidate, benchmark agent latency/spend or audit a production backend. Recommendations are proposed dispositions, not authorization to change APIs, budgets, frozen semantics, publication state or R1. No repository files were edited.
