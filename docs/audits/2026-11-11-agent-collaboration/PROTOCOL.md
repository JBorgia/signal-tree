## Governing question and premises

The governing multi-actor plan at v16 `5d04ff65` states:

> Make application changes accountable and safely settleable across humans, embedded agents, browser agents, machine agents and external services.

> Success means a developer can implement the complete dispatch workflow with truthful review, conflict, recovery and delivery behavior through supported APIs. Passing internal experiments alone does not complete this objective.

Its architectural boundary also states:

> Approval consumption validates evidence at the authoritative boundary; inspect-then-confirm is not automatically revision-bound acceptance.

Source: [governing plan](../../architecture/multi-actor/PLAN.md). These are existing
selected requirements, not a new mandate to put permissions, durable commands,
model reasoning or a second state authority inside the kernel. The
[18-family acceptance ledger](../2026-10-29-multi-actor-product/ACCEPTANCE.md)
remains the scenario inventory. Historical reference passes on older packages do
not qualify this runtime or its successor.

Judge separately: native state and settlement contracts; supported public
application composition; common outcomes implemented with rival stacks; external
services and future requirements not established by these tests. An LLM is not
the correctness oracle. Deterministic delayed agent proposals exercise the state
and coordination boundaries without attributing model delay or reasoning quality
to a state library.

## Public workflow audit

Requalify the existing optional coordinator, supported native bridge, Angular UI,
protocol adapter and HTTP test authority against exact current artifacts. Inspect
their existing failures and limits before extending them. Application-side
immutable review, declared input versions and remote command identity must not be
credited as kernel-built-in features. Keep local operation, agent run, transaction,
delivery attempt and backend command identities distinct.

The initial discriminators include useful independent progress; stale input and
net-zero ABA during agent delay; edits between review and approval consumption;
same-key entity replacement; user rejection and compensation refusal; explicit
retry/confirmation; lost acknowledgement and duplicate retry; callback error and
reentry; late publication consumers; cancellation, disposal and recreated sessions;
and UI-only input with honestly unknown executor attribution. Test permission and
grant tampering at the test authority, without claiming production authentication
or durable database recovery from an in-memory fixture.

Planted defects must fail their intended assertion: stale approval accepted,
premature publication/confirmation, dropped useful independent work, duplicate
remote execution, wrong-lifetime retargeting and retained disposed resources.
Do not treat silence, missing capability or a swallowed error as success.

## Broader metric plan

Freeze executable workloads, sample counts and artifact bindings after premise
review and calibration, before comparative execution. Preserve the pinned original
library versions and strong native/NgRx/TanStack alternatives when measuring the
effect of SignalTree changes. Runtime and application-strategy changes are separate
arms. Admit a performance arm only after equivalent observable outcomes pass.

| Question | Metrics and boundaries |
| --- | --- |
| Can the user keep working while agents run? | Scripted input-to-observed-result latency distributions, worst sample, browser task/script/layout time, and measured frame-callback gaps under a fixed useful agent workload. These are local controlled observations, not real-user INP or a physical-device rating. |
| How much useful work completes? | Checked edits/proposals/settlements per interval, accepted/refused/conflicted outcomes, independent progress and retries. Count dropped or duplicate work explicitly. |
| What does startup buy? | Construction/population, first demanded reader/context, first review and first publication; separate deferred demand from the initial interval. |
| How expensive is agent context? | Selected and full context materialization/serialization elapsed time, CPU where available, exact bytes and correctness checks. Do not infer model tokens, accuracy or provider cost from byte counts. |
| What happens as work overlaps? | Fixed concurrent pending-operation counts, time to quiescence, pending/settled heap and per-operation growth; agent delay is controlled separately from local execution. |
| What remains after repeated sessions? | Whole-process/browser heap at registered GC checkpoints, deterministic registry counts, sampled object collection, retained-store aging and teardown with explicit pin/release controls. |
| Where is the cost? | Separate attribution runs for transient allocation/GC, exact work counts and phase CPU. Instrumented profiles are not substituted for uninstrumented comparative timing. |
| What must an application implement? | Required guards, version/review/transport mechanisms, supported imports and observed failure handling. Source counts describe fixture implementation burden, not developer productivity or intrinsic library quality. |

Browser metric availability is established against the pinned actual browser.
Event Timing has thresholded/quantized reporting, so missing entries are not zero
latency and a percentile over reported slow entries is not the percentile of all
interactions. The former W3C Long Tasks draft was discontinued on October 20,
2026; any `longtask` observations are explicitly browser-implementation telemetry,
not a current W3C-standard compliance claim. Prefer supported event/animation-frame
and CDP observations with named boundaries and sensitivity controls.

## Verification and closure

One exclusive heavy execution slot covers installs, builds, tests, mutation runs
and measurements. Keep original controls and exact versions before corrections.
Use same-build repeats, repeated fresh processes and rotated order; distributions
and paired differences remain descriptive unless an inferential method is actually
registered and executed. Never pool unequal workloads or suppress an unfavorable
first result.

Independently challenge consequential premises before implementation and final
interpretation after raw results exist. Final qualification covers changed source,
types, relevant frameworks, installed artifacts, production demo and required
release checks. Numerical size failures remain explicit; no threshold is raised
to manufacture a pass. The final report must state which agent/user goals are
demonstrated, require optional application integration, remain external obligations,
or are still unsupported, and weigh useful benefits against measured costs.

Primary external references consulted for measurement/protocol scope:
[Event Timing draft](https://www.w3.org/TR/2026/WD-event-timing-20261013/),
[discontinued Long Tasks draft](https://www.w3.org/TR/2026/DISC-longtasks-1-20261020/),
and [AG-UI state synchronization](https://docs.ag-ui.com/concepts/state).
Protocol transport/synchronization facilities do not by themselves establish
authorization, conflict resolution or durable execution.

## Follow-up hypothesis from the fresh startup profiles

After the complete 136-child C1 cohort and four separate production profiles,
source/history inspection identified v15's delivered-path observation gate as a
possible narrow port. The fresh production maps omit Link's native factory, so
this lead concerns ordinary delivered notifications, not an excuse to drop
publication/currentness facts when there is no current recipient.

Before any prototype, independently inspect the two lines' port ownership,
history, enqueue/delivery boundaries and listener enrollment/reentry behavior.
The candidate may skip only work whose result cannot be received under the
existing contract. Preserve C1 source, packages and all completed results as the
matched baseline. A changed source must get its own identity, useful listener
and non-listener falsifiers, exact built qualification and startup/heap comparison.
If adopted, refresh affected application comparisons on that final artifact;
the already completed C1 results cannot be relabelled as successor measurements.

Disposition: four installed C1 baseline witnesses pass and the deliberately
blind isolated fresh-add delivery mutant fails all four cases' expected assertions. Enqueue
consumers, post-install getter enrollment/nested work and completion enrollment
make that tested shortcut unsound. The mutant is evidence, not a candidate, and
never replaces C1. This does not rule out a more careful future demand design;
none is adopted or assigned a synthetic saving. The final application cohort
therefore remains the unchanged complete C1 cohort.
