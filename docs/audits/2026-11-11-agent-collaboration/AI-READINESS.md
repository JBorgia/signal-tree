# Agent and human collaboration: capability disposition

Evaluated November 16–17, 2026 against v16 `5d04ff65` and successor runtime
`2c439198b13a93ede29e7bece69a07a534f30797`. The governing question is whether a
developer can build truthful review, conflict, recovery and delivery behavior
through supported APIs. An agent producing a plausible answer is not that proof.

**v16 is a useful state and coordination foundation for this goal. It is not a
complete agent platform or a substitute for authoritative backend decisions.**
The installed public workflow works on both identified artifacts. This phase
finds and repairs an application recovery gap, reduces one native capture cost,
and measures the remaining ordinary-state premium. It does not establish that
v16 is the cheapest implementation of the full multi-actor product.

## What the executed evidence establishes

Each artifact passes 62 Node tests, 15 original production DOM cases, and twelve
production Angular browser-to-HTTP cases. These are distinct fixture families,
not a count of unique product capabilities. Strict installed types, full AOT,
package inventories, emitted production code and frozen fixture sources are
verified. Both HTTP negative controls fail their intended assertions on both
artifacts. The first HTTP run, seven passes and five failures, remains evidence.

| Responsibility | Demonstrated behavior | Boundary |
| --- | --- | --- |
| Native state | Stable entity lifetime; pending ownership; supported confirmation, rollback and safe refusal; independent publication; late readers, reentry and teardown | Kernel and facade qualification, plus selected installed public discriminators; no replacement state authority |
| Optional operation reference | Immutable proposals, explicit review, separate operation/native/command identities, asynchronous response correlation and recovery state | Repository application reference, not a newly shipped SDK or built-in agent executor |
| Browser/HTTP integration | Actual fetch, pending review, separate trusted host approval, exact command receipt, native settlement, retry and cleanup | One reviewed remote operation at a time in this browser reference; Node tests cover two simultaneous pending native owners with separately correlated, sequentially delivered remote commands |
| Authority fixture | Permission checks, revision/instance preconditions, immutable approval, stable command identity and deduplication | In-memory server with fixture credentials; no production authentication, durable database or restart proof |
| Agent producer | Delay, cancellation, stale input, net-zero ABA and unknown executor attribution | Deterministic producer; no inference quality, provider latency, token billing or real human-presence proof |

The twelve HTTP cases inspect intermediate pending IDs and actual native terminal
events, command bytes, rendered state, attempts and effects. Passing final values
alone would not be enough. Retained reports contain final case records; the
intermediate checks are awaited assertions in the exact frozen test source, not
separate timestamped snapshots of every transition.

## What failed and how recovery changed

The initial transport injection destroyed a socket after applying a command.
Chromium retried transparently, so the application sometimes received an
acknowledgment instead of remaining uncertain. The corrected fixture returns
HTTP 503 after the effect and withholds the application receipt. It then requires
an explicit same-command retry, two requests and exactly one effect. This proves
the specified gateway-uncertainty behavior, not every TCP failure mode. A second
failure was a DOM assertion racing rendering; the assertion now waits for the
expected two pending owners before checking their identities.

The substantive recovery gap was same-key entity replacement. The backend
correctly rejected the old instance and the kernel correctly refused unsafe
rollback, but the reference left the obsolete owner pending without a useful
explicit resolution. Its new **Keep authoritative replacement** action requires
a terminal instance rejection, a different authoritative row instance, a route-only
obsolete proposal, matching replacement truth, exactly that pending owner and no
newer blocker. It closes only the obsolete local ownership through supported
confirmation and checks the actual terminal event. The replacement and independent
human note survive. The remote outcome remains failed and its receipt remains
rejected; recovery sends no command again.

This is a narrow application policy. Confirmation can release deferred native
consequences; the reference has no transaction-scoped persistence or dependent
outgoing route effect. A broader transaction needs its own reconciliation policy.
A blanket catch-and-confirm would not be a valid general repair. Cleanup remains
separate: lost grant-revocation acknowledgments retain a retryable cleanup job
and prevent disposal even after native ownership settles.

## Disposition against the existing eighteen-family ledger

The [acceptance ledger](../2026-10-29-multi-actor-product/ACCEPTANCE.md) mixes native
contracts and proposed product integrations. Its historical introductory statement
that no cases had run described that earlier research, not this qualification.
It remains an inventory; this audit does not silently mark every future product
requirement complete.

| Families | Current evidence and remaining boundary |
| --- | --- |
| M01, M02–M06, M10–M12 | Native source/framework suites and built witnesses pass; installed workflows add independent progress, held publication, late consumption, refusal/retry and reentry examples. The broader native contract remains governed by its tests, not inferred from a common benchmark. |
| M07 | Declared/unknown executor attribution is explicit. UI actuation does not establish authenticated human or agent identity. |
| M08, M09 | Immutable review, stale/ABA input, approval consumption and instance rejection are exercised; held old rows cannot retarget replacements. Explicit replacement recovery is now demonstrated. |
| M13 | Tampering, transport-only grant attempts and post-approval permission revocation are rejected by the fixture. Production identity, authorization policy and hostile same-origin execution require separate integration/security work. |
| M14 | Withheld application acknowledgments, stable-command retry, exact single effect and cleanup retry are demonstrated. Durable receipts, database transactions and restart recovery are unproven. |
| M15 | Cancellation, explicit disposal, pending-operation disposal protection and stale completion guards are exercised. Actual navigation, cross-tab ownership and durable resumed sessions are not demonstrated by the HTTP browser reference. |
| M16 | All four framework projects pass affected qualification. The new full browser/HTTP reference is Angular; it is not four equivalent browser applications. |
| M17 | Explicit correlation across asynchronous work is exercised in the optional coordinator and public bridge. A synchronous native transaction does not automatically extend over an await. |
| M18 | Correctness uses native authority rather than private Studio. This phase does not establish a production audit-retention, redaction or truncation service. |

## Keep the costs and optionality honest

Transactions, restoration and retained diagnostics are already construction-selected
features. Row and field handles are demand-created. The operation coordinator,
agent protocol adapter and backend are application integration choices. These
choices do not need another configuration layer merely to rename them.

Native v16 topology/currentness work is integrated with state mutation. It is not
shown to be reproducible by an external enhancer at lower cost. Link participation
also has a module-wide component: removing Link through bundling differs from
having its module present with no current recipient. Historical activation
measurements price that distinction; this phase does not rerun or relabel them as
fresh heap attribution. A per-tree publication capability remains a design
opportunity, with late enrollment and cross-tree consumption as required semantics.
No subscriber-count shortcut or new public option is adopted without that design
and a complete cost comparison.

The selected internal collector removes redundant expansion automatically. Correct
cleanup and cheaper internal representation should not become options users must
discover. The first full context read still creates useful reader/snapshot state,
and repeated contexts still cost time. Prefer bounded, relevant context in an
agent workflow; that reduces measured local work and bytes without weakening
state guarantees. The current tests do not establish what subset makes a real
model accurate or how many tokens a provider will charge.

## Product and business judgment

The strongest application fit is an entity-heavy editor where human work must
continue while proposals, approvals and remote outcomes remain unresolved.
Useful independent progress, safe refusal and explicit recovery have practical
value there. Simple forms and ordinary CRUD should not pay for an agent platform
they do not need; native Angular, NgRx and v15 remain credible choices, with the
measured startup and representation tradeoffs in the [comparison](README.md).

The six-way benchmark proves common observable work, not full semantic parity
with every v16 guarantee. Native/NgRx/TanStack fixture code supplies explicit
application protocols; their success is real and is not evidence of missing native
capability. Conversely, this study has not built the complete optional companion
against every rival or run an unfamiliar-developer usability study. It therefore
does not prove lower total development cost, fewer production incidents, or a
commercial moat for v16.

The appropriate position is SignalTree with stronger coordination, keeping the
operation/backend layer explicit and optional. A separate agent product or brand
is not justified by these measurements alone. The remaining external obligations
are concrete integration work—durable authority, navigation/resumption,
cross-tab convergence, production security and real-model evaluation—not reasons
to misrepresent the demonstrated native contract as broken or universally sufficient.
