## Corrected scope

The5000-prefix observation requires the ordinary path to be part of the first
candidate's cost boundary. A design cannot claim reachability of `<2000` by
replacing only `experimental-publication/entity.ts` and lifecycle proof storage
while retaining the measured producer/admission sequence. Nor can it merely
replace iteration syntax with operations the original counter does not observe.
CPU, wall and heap must independently validate the complete task.

The integrated candidate needs to account for value installation, topology effects,
ordinary/physical support and native publication, including their preparation,
validation and installation boundaries. Its organization is not prescribed. It
must show which producer facts are positively certified, how mutable caller aliases
are excluded, and what happens on non-point, inspection, restored or callback-capable
paths.
No fast path can be justified by recipient absence alone.

## What compact global windows could mean

A possible component is a shared immutable snapshot of exact global pending-cell
membership, refreshed when membership changes and acquired at finalization.
Destination/actual-input exclusions remain specific to the installation; inherited
possible-owner evidence is retained independently. Open,terminal and source
abandonment paths must invalidate current membership caches. Issued snapshots
must not be rewritten, and a destroyed owner's captured cell must not be
reinterpreted as successfully settled.

An integer epoch can name such a snapshot; an integer alone cannot reconstruct
lost membership. A global journal also needs an explicit reclamation rule so its
current root does not retain every historical write forever. This component is
plausible, not implemented or accepted. The prior counter charged zero visits
inside window/proof phases in its empty-owner workload; cache sharing alone does
not address the5000prefix or establish CPU savings.

## What fused fields must preserve

A field lookup could jointly address an ordinary NativeFieldEndpoint and physical
View, but it must retain both authorities. Ordinary endpoints may be exact frozen
selected/restored objects. Existing physical View cells deliberately update their
requirement at terminal installation when physical value/presence compares equal;
changed physical values create different cells. Snapshot certificates depend on
that distinction (`experimental-publication/private.ts:106–140`).

Per-edit physical images have a separate stability obligation. Holding a live View
cell is not automatically equivalent to capturing the requirement at that edit's
boundary. A fused implementation must explain saved-reader behavior across later
writes and equal-value support refresh, not merely put two pointers in one object.
Physical-only rows require optional sides; union-key traversal cannot introduce
physical-only support into ordinary truth. Membership,placement and key mapping
also remain separately observable; field fusion does not erase those facts.

A wrapper-per-field can add objects while removing map entries. It is therefore
not a demonstrated heap optimization. Copy-on-write/persistent lookup is another
candidate component, with explicit version,escape and reclamation invariants still
needed. No particular allocation count is stipulated from the incumbent.

## Decisive oracle order

Before promotion of any implemented mechanism, execute the existing unchanged
witnesses in the source-bound admission command, then its missing supported-path
coverage. Important anchors include:

- `native-window-preparation-audit.spec.ts`: foreign pending owner, callback opens
  owner before finalization, callback settles owner before finalization.
- `fixed-window-independent.spec.ts` and `publication-uncertainty-provenance.spec.ts`:
  exact prior membership, later-owner exclusion, abandonment, inherited versus
  newly acquired uncertainty.
- Public late-history fixture: consumer attaches after ordinary write, independent
  sibling write, foreign confirmation and rollback separately, useful later write,
  disposal refusal.
- `packet-physical-pair-semantics.spec.ts`, `packet-index-adversarial.spec.ts`,
  `singleton-row-reuse.spec.ts`: pairing,repeat/reused edits,physical-only support,
  saved readers,absence/present-undefined,preparation/finalizer refusal.
- `native-admission-handoff.spec.ts`, `scalar-horizon-lifecycle-controls.spec.ts`:
  equal/inverse/net-zero destination responsibility,unfinished validation/activation,
  disposal and failure behavior.
- `publication-retirement-acceptance.spec.ts`, `fixed-window-retirement.spec.ts`:
  old lifetime cannot retire fresh key reuse,negative evidence,held readers,
  completion failure/reentry and source teardown.

Passing incumbent oracles only establishes the baseline. An implemented mechanism
must independently pass; a correctness failure rejects that implementation before
cost work. Tests do not establish all semantics by enumeration alone. Known-bad
controls must independently show that the relevant omissions are detected.

## Future cost preregistration boundary

This is a proposed promotion rule for the first implemented experiment, not a
release waiver, new production SLO or executed cost registration:

1. Original200-update/two-size `<2000` gate passes unchanged, with planted positive
   and width-regression controls. No interval shrink or uncounted-loop substitution.
2. On matching uninstrumented artifacts,ordinary point CPU and populated live heap
   must each classify lower than frozenfe18 beyond the registered same-arm/range
   variability rule. Wall,pending heap,construction and allocation remain separate;
   a gain cannot compensate for another required dimension's failure/unresolved result.
3. Predefine the exact workloads,number/order of fresh children,artifact/dependency
   hashes,quiescence,abort policies and counterfactual controls before execution.
   Do not run another full campaign until semantic and absolute-work screens pass.
4. Released-v15 is context on matched ordinary outcomes,not a capability-parity
   baseline for native overlap. No result separates unavoidable semantic cost from
   implementation cost without a further controlled discriminator.

The attached40-option review ranks hypotheses. It does not specify all transitions
above. Neither an implementation nor an architecture winner is selected by the
present admission result. The next concrete design must account for the producer
prefix and exact history/reader lifetimes; it cannot rely on the native-only scope
that this screen falsified as sufficient.
