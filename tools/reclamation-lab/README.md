# Post-capture entity reclamation: v15 port

This port follows the validated projection change at
`878a6686f63ab4918dfc00df556e985cbded692d`. It does not change the public API,
transaction refusal policy, package version, or release authorization.

The concrete retention defect is not a startup cost that amortizes away.
On published v15.4.8 (`37ef1788f6bac61678fc312f391b180bd7a6bbd7`), three
10-row population/removal cycles on the same retained empty tree leave
10/20/30 entity lifetimes and value backings when `transactions()` is present,
even if it is never called. The bare control leaves zero; designated restoration
with a two-entry history retains a bounded ten. The deterministic installed
artifact witness binds every package payload and exact protocol:
`/private/tmp/st-v15-never-claimed-churn-2.json`, generated by
`/private/tmp/st-v15-never-claimed-churn.mjs`. These inventory observations are
not a per-feature heap attribution or universal boundedness proof. The first
exploratory receipt copied a v16 artifact label in its protocol; the corrected
receipt above names and hashes the actual v15 inputs.

Entity retirement happens before notification capture can register history
claims. Reclaiming inline would break legal undo/rollback; the existing
`never-claimed-retirement.spec.ts` proves that gap. Previously, transaction claim
release deliberately did nothing physical, and only history eviction drove the
production sink. A transaction-only workload has no history-eviction event;
ordinary retirements may never have a claim to release at all.

The optional enhancers now install one deferred queue through the existing
physical-owner registry. Actual retirement and last-owner release offer exact
entity-lifetime IDs. The queue waits for notifier capture and open callback
capture, then the shared sink rechecks current claims and physical eligibility.
It does not scan collections, block behind unrelated materialized pending
transactions, or poll while idle. Destruction removes its callback and pending
work. Bare trees retain their immediate zero-owner reclamation path, and the
scheduler remains absent from ordinary production bundles.

The v16 implementation additionally protects ordinary placement when inspection
has hidden a physical row, and reoffers the lifetime when an ordinary companion
removes that placement. V15 has no equivalent ordinary-topology representation;
this port does not import that machinery or v16 settlement semantics.

## Verification and limits

Using Node 24.15.0/pnpm 10.17.0 with `NX_DAEMON=false`,
`NX_ISOLATE_PLUGINS=false`, and `CI=true`:

- `pnpm nx test kernel --skip-nx-cache`: 433 files, 7,856 ordinary passes,
  seven existing expected failures, thirteen skips and one todo.
- `pnpm nx test angular --skip-nx-cache` (run through serial Nx run-many):
  214 passes and three existing skips.
- `pnpm run typecheck`, `node tools/check-spec-types.mjs`, and
  `pnpm nx build kernel --skip-nx-cache` pass. The spec-type ratchet still has
  222 existing errors across 36 files; no new/worsened errors is the claim.
- `pnpm nx build demo --configuration=production --skip-nx-cache` passes its
  unchanged strict production configuration.
- The command below passes seven of eight selected gates. Its bundle gate
  remains numerically failing; no ceiling or runtime text was changed to hide it.

```sh
node tools/verify-gates.mjs --only=lint:budget,api-baseline,tree-shaking,declaration-docs,doc-links,readme-apis,source-controls,bundle-budget
```

`budget-bytes.mjs` evaluates the canonical gate's exact fixture strings and
build settings while reporting integer gzip bytes. Against released v15,
projection-only, and this port respectively, entities measure
25,222/25,269/25,300 production bytes and 28,147/28,194/28,232 development bytes.
The existing ceilings are 25,292.8 and 28,160 bytes. This repair adds 31 production
and 38 development bytes to the projection candidate; its final excess is 7.2
and 72 bytes. Bare fixtures remain 11,011/13,159 bytes, with zero scheduler bytes
in either ordinary fixture. The exact receipt is
`/private/tmp/st-v15-reclamation-budget-bytes-1.json`. The central task accepts
this small code cost under the owner's instruction to weigh budgets against
cost and feasibility. That economic acceptance is separate from the failing
numerical gate; it is not a claim that every release gate passed.

The first full suite failed three historical value-null fixtures because they
tried to delete a lifetime the new queue had already forgotten. Those fixtures
now execute the same manual value-only deletion before the deferred boundary;
their pending/history ownership controls and subsequent public-behavior
assertions remain. First failures and corrected runs are preserved in
`/private/tmp/st-v15-reclamation-full-tests-1.log`,
`/private/tmp/st-v15-reclamation-ownership-null-1.log`, and
`/private/tmp/st-v15-reclamation-full-kernel-2.log`.

An exploratory fixture deliberately disabled internal PathNotifier batching and
threw `undefined` during synchronous rollback delivery. V15 classifies that
internal failure as a refusal and keeps its claim until explicit confirmation;
the port preserves that ownership. History 48b8af0fd deliberately marks only
errors after a completed apply callback, as described in
[operation outcome provenance](../../docs/audits/2026-10-01-v15-outcome-provenance.md).
There is no production caller disabling global batching, and this fixture does
not establish a default public workflow regression. It is not a reason to
silently import v16 settlement semantics. The first observation remains in
`/private/tmp/st-v15-reclamation-focused-1.log`.

Independent source review is bound in
`/private/tmp/st-v15-reclamation-independent-source-review.json` with exact file
snapshots. It found no concrete blocker; full validation and measured cost remain
separate evidence.
