# Entity registration regression checks

The original eight transport cases and six source-matched lifecycle cases are shared byte-for-byte between ordinary source specs and installed/bundled probes. Receipt states in original eight are observations, not exact oracles. receipt-cases.ts separately asserts actual changed writes are not no-write, dependent pending hold and earlier terminal receipt stability.

Source wrappers under packages/kernel/src/lib/entity-registration-*.spec.ts use relative imports within the kernel project. Shared fixtures are under packages/kernel/tests/entity-registration. Run through Nx. The TypeScript receipt harness is covered by source/spec imports; .d.mts declarations type the unchanged JS harness boundary (not a claim that JS implementation is statically typechecked).

Artifact replay: build canonical packages through Nx, prepare package artifacts, npm pack/install all five fresh tarballs plus pinned peers into a new isolated consumer. Copy cases.mjs, lifecycle.mjs, receipt-cases.ts from packages/kernel/tests/entity-registration and the four consumer entry files plus facade-imports.mjs into that directory. Under pinned Node24 run consumer.mjs (8), lifecycle-consumer.mjs (6), receipt-consumer.mjs (6), no-link.mjs and facade-imports.mjs. Then from the repository run `node tools/experiments/entity-registration/build-consumers.mjs /absolute/isolated/consumer`; run all four resulting *.production.mjs programs. Retain commands/logs, source/tarball/installed hashes and metafiles. No aliases to source, sideEffects overrides or private activation.

Do not execute staged consumers without installing fresh tarballs.

The permanent `entity-registration-artifacts` gate reuses these exact fixtures against isolated installed packages and minified production bundles. Run `node tools/verify-gates.mjs --only=entity-registration-artifacts,entity-registration-artifacts:self` to build and verify; add `--self-test` to prove the companion detects classifier blindness. The gate's own `--self-test` removes the built registration call only in a disposable package copy, requires behavioral failures in both modes, and reruns clean recovery. Setup fetches peers pinned by `tools/fixtures/entity-registration-consumer/package-lock.json`; it does not require an npm cache warmed by pnpm. Dependency/setup failures never count as mutation evidence. Evidence directories and first failures are retained under the system temp directory. Direct invocation consumes prebuilt artifacts and does not establish source freshness. The no-Link production graph must exclude Link and the entity factory. These focused gates do not confer release sign-off.

The namespace harness retains optional enhancers and is not a minimal size workload. Genuinely late FIRST registration is unqualified; pre-Link pending controls assume module evaluation already happened. Current cost/large/budget failures are not waived by these cases.

The companion registry proof is opt-in: it accepts only an identified classifier-blindness witness after the clean baseline, both mutant modes and controls, clean recovery, and unchanged-input checks. Setup failures, timeouts, integrity failures, or a missing/invalid witness are errors, not proof; its parent is not proven unless the companion witness validates. The tool rejects TMPDIR inside a workspace before creating a consumer.

Recorded qualification uses Node 24.15.0 (officially bundled npm 11.12.1). Full registry mutation/setup-failure/recovery checks ran on npm 11.12.1. The publish job's floating `npm@^11.5.1` range resolved to 11.21.1 on 2026-11-03; one exact-11.21.1 sealed normal gate smoke passed locked-peer setup and the installed/bundled cases. Mutation proofs were not rerun on 11.21.1, and future versions in the publish range are not covered by these receipts.
